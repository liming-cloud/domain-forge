# 独立服务模板使用说明

## 当前边界

模板候选 `0.3.0-iam.2` 提供单 PostgreSQL、Web、启动迁移及必要诊断，尚未人工验收或对外发布。组件和模板的本地验证范围不等于生产可用承诺。身份接入显式选择
`domain-forge-access-control` 和 `domain-forge-iam-client`，导入 `BackendAccessConfiguration` 与 `IamClientConfiguration`
，配置IAM服务名、项目、原生Nacos发现及客户端SSL bundle；裸模板不自动连接IAM。多数据源、完整链路及可分发 Harness
留在后续单元；部署前须完成项目自己的身份、管理端点保护和容量设计。

## 生成与依赖

使用固定模板目录和 Python `3.14.5`：

```sh
python3 generate.py --group-id com.example --artifact-id sample-service \
  --package com.example.sample --output /已有父目录/sample-service
```

输出父目录须存在，输出目录须不存在且名称等于 artifactId；不接受符号链接、路径跳转或覆盖原工程。输出带来源摘要、官方
Wrapper、POM、启动配置和本文的固定版本副本；不依赖平台源码或 parent。没有业务时不造四层空类、演示表或接口。

使用 Temurin `21.0.12.1+1-LTS`、Maven Wrapper `3.3.4`／Maven `3.9.16`。POM 导入
`org.domainforge:domain-forge-bom:0.3.0-iam.2`，显式依赖 Web `0.3.0-iam.2` 与 persistence `0.3.0-iam.2`；版本由 BOM 管理，框架
API 的直接使用同样显式声明。新 BOM 不覆盖旧 GAV，不自动启用组件。模板 bootstrap 使用
`@Import(DomainForgePersistenceConfiguration.class)` 选择单库能力。 新持久化版本仅用原生事务超时键；检测到旧
`domainforge.persistence.transaction-timeout-seconds` 时拒绝启动并提示迁移，两键同时配置也拒绝。旧版制品保持，既有项目不强制升级。

构建前在自己的 Maven settings 配置可信制品仓库和凭据；本候选目前只验证隔离 file 仓库，未提供公司或公共发布地址。默认无
parent；需要自有 parent 时由项目维护，不改为继承平台内部 parent。兼容证据仅覆盖固定的公司 parent 夹具，不保证任意 parent
的插件覆盖都兼容。

## 运行与故障

在生成工程中执行 `./mvnw verify`，然后运行 `java -jar target/sample-service-0.1.0.jar`。先由本机秘密管理或部署配置注入
`DB_URL`、`DB_USER`、`DB_PASSWORD`；URL 为 PostgreSQL JDBC 地址，应用账号需要连接及本服务 schema
的启动迁移权限。模板不内置凭据，不回退内存数据库。运行时 PostgreSQL 基线为 `18.4`。

默认业务端口为回环 `8080`，管理端口为独立回环 `8081`，分别用 `SERVER_PORT`、`MANAGEMENT_PORT` 调整。管理入口只开放
`/actuator/health` 和 `/actuator/metrics`。`/actuator/health/liveness` 表示进程可继续运行；`/actuator/health/readiness`
含真实数据库检查，断库返回 503。不能把独立回环端口视作生产鉴权方案。

| 初始参数                  | 默认值与责任                                                                                                                           |
|---------------------------|----------------------------------------------------------------------------------------------------------------------------------------|
| Hikari 最大连接／获取等待 | 10／3000 毫秒；连接验证 1000 毫秒，驱动连接 3 秒、读取 5 秒                                                                            |
| MyBatis 语句等待          | 5 秒；由真实 Statement 生效，不保证所有外部调用受此约束                                                                                |
| 应用事务默认等待          | 10 秒；原生 `spring.transaction.default-timeout` 支持 1—300 秒（例如 `30s`），未配置仍10秒                                             |
| 分页插件上限              | PostgreSQL 方言，`domainforge.persistence.max-page-size` 默认 200，允许 1—1000；服务自己的入口仍须限定请求页和条数，插件不审计任意 SQL |
| 日志出口                  | ECS 结构化日志；异步队列 256，满时不阻塞业务，关闭刷新最多 1000 毫秒；可能丢失，不冒充安全审计                                         |

JVM、HTTP、连接池及日志指标通过管理端点读取。HTTP 指标在实际请求后产生。`domainforge.logging.degraded` 表示缺失／停用出口或当前队列已满，
`domainforge.logging.queued` 表示队列长度；零值不能证明过去没有丢失。降级不改变已完成业务事务，也不进入数据库
readiness；恢复须核对新日志。指标只使用固定应用／版本和框架有限分类，不添加用户或请求 ID 维度。

缺少数据库输入、错误凭据、非法池参数或迁移失败时应停止启动。运行期断库时 liveness 可保持 UP，但 readiness 失败；恢复后应验证新
SQL。公开健康不显示连接串、栈或凭据，内部日志用于定位；项目新增日志同样不得记录秘密。

## 数据与迁移

当前组件明确绑定 Spring 原生默认名称 `dataSource`、`transactionManager`、`sqlSessionFactory`、`flyway`
（自定义名称可声明同名别名），四者必须使用同一实际数据源；缺少绑定或错绑会拒绝就绪，不按类型、Primary 或 Bean
顺序猜测。无关资源可以共存，但不会自动获得路由、迁移或事务配置；当前不等于已支持多数据源路由。组件不扫描业务包，不提供
BaseEntity、万能 Repository 或 BaseService。服务拥有 PO、Mapper、SQL、映射与 schema，Mapper 扫描只在自己的 bootstrap 指向基础设施包。

有真实业务后才添加 `src/main/resources/db/migration/V<版本>__<描述>.sql`。裸模板无迁移是空 schema
的真实状态；验证用表不进入生成结果。Flyway 启动迁移，已发布 SQL 不原地改写；升级添加新版本。校验和冲突、无权限和执行失败保留原始证据，核查后修正输入，不自动
repair、baseline 或 clean。应用回退不等于数据库自动降级。

## DDD 与查询边界

一个服务默认一个 Maven 模块、一个 context 根包；多个真实 context 出现后再按批准设计拆分。代码按需要建立以下职责，不创建占位目录或空壳转发层：

| 位置                                             | 所有权                                                        |
|--------------------------------------------------|---------------------------------------------------------------|
| bootstrap                                        | 明确扫描根、配置、装配、生命周期；其他层不反向依赖            |
| interfaces/http                                  | 协议校验与错误映射，不直接调用 Mapper 或承担业务授权          |
| application/command                              | 事务、用例与实际编排，通过领域行为和仓储合同工作              |
| application/query                                | 技术无关查询接口、Filter／View，不泄漏 PO、IPage 或 SQL SDK   |
| domain/model、domain/repository                  | 真实领域规则及必要业务仓储合同，无 Spring、ORM 或平台组件类型 |
| infrastructure/persistence、infrastructure/query | PO／Mapper／SQL、映射及查询实现，只访问自己的私有表           |
| infrastructure/acl                               | 有外部语义翻译需求时才建立防腐适配，不预造通用接口            |

纯查询允许 `HTTP → application.query 接口 → infrastructure.query SQL → View`；没有编排便不造
Handler，需要资源授权时由实际应用用例负责。固定排序选项、参数绑定、有界返回和无写入要用真实 SQL 验证，不能只靠注解。

事务通过实际应用代理入口调用，默认所有异常回滚；覆盖回滚策略需明确批准并补反例。自调用、异步线程、远程调用不自动获得原子性。领域事件及集成事件须按事务后的外部效果设计；本模板未提供消息总线、Outbox
或分布式事务，不应推断已有跨服务一致性保证。

## 验证与升级

仓库内产品检查对生成工程执行既有 schema 4 源码／架构规则，并以隔离夹具验证事务、SQL、迁移和失败恢复；夹具不进入发布模板。本阶段没有将整套
Harness 分发到消费项目，生成后的 `./mvnw verify` 不能代替完整业务语义评审和人工验收。项目需要先明确任务、设计、可证伪标准和评审责任，再研发业务。

组件升级修改 BOM 后重验；模板升级按文件差异评审，不重新生成覆盖业务。保留自己的 `template-origin.json`
以定位初始来源，后续代码归项目维护，不能用旧生成摘要声称修改后的工程仍与模板相同。

迁移前会核对绑定的 dataSource 和 Flyway 的资源身份，拒绝通过 `spring.flyway.url`
另开连接；就绪前继续核对事务管理器、会话工厂与迁移器的同资源绑定。该检查保证本模板的受控启动路径，不替代使用方自行添加的生命周期代码评审。

领域类型通过 BOM 管理的 `shared` 使用 `org.domainforge.shared` 包中的 `AggregateRoot`、`Entity`、`ValueObject`
标识；它们只标识角色，不提供基类字段或 ORM 行为。shared 中的传输对象不能进入
domain。裸模板不生成虚构聚合，按真实领域规则创建后依照[模型规范](../../../docs/standards/01-需求与领域建模.md#战术设计)
选择标识。
