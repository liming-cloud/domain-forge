# 服务模板使用说明

模板在本仓库 `platform/services/<name>` 生成一个业务服务，并在 `deploy/` 写入它的部署文件：继承内部 parent，加入 `services` 聚合，自动执行架构规则、格式、依赖声明与测试门禁。生成后代码归该服务维护，模板升级不覆盖已有服务。

## 生成

在仓库根目录执行（Python 3.10 及以上）：

```bash
python3 platform/templates/ddd-service/generate.py --name order-service --package com.company.order
python3 platform/templates/ddd-service/generate.py --name order-service --package com.company.order --with-example
```

| 参数 | 含义 |
|---|---|
| `--name` | 服务名，即模块目录与 artifactId；小写字母、数字与 `-`，不能与已有模块同名 |
| `--package` | 服务根包，也是唯一的上下文根包 |
| `--permission-namespace` | IAM 权限命名空间，默认为去掉 `-service` 的服务名 |
| `--with-example` | 附带便笺示例，演示三条路径与 IAM 数据范围（见下文） |

目标目录或部署文件已存在、参数无效时拒绝，不修改仓库；失败时删除本次创建的文件。

## 生成内容

| 位置 | 内容 |
|---|---|
| `bootstrap/` | 启动类（只扫描本服务根包、启用 `infrastructure/acl` 中的 Feign 客户端）、Mapper 扫描、日志出口降级状态 |
| `application/port/access/DataScopes` | 当前主体在本服务精确权限上的数据范围端口 |
| `application/port/operation/Identifiers` | 雪花 ID 端口，实现在 `infrastructure/persistence/operation` |
| `infrastructure/acl/iam/` | IAM 当前授权的 Feign 客户端、`CurrentSubjectSource` 与 `DataScopes` 实现、失败翻译 |
| `application.yml` | 数据库、会话 Redis、IAM 地址与 Nacos 配置，凭据只来自环境变量 |
| `deploy/services/<name>.compose.yml` | 部署覆盖文件：本服务专用数据库账号与 schema 的初始化任务、服务本身；镜像取生成时 `deploy/compose.yml` 的 postgres |
| `deploy/nacos/config/gateway.yaml`（追加） | 仅 `--with-example`：示例接口的网关路由，见[API 网关](../../../docs/architecture/06-API网关.md#路由配置) |
| `deploy/nacos/config/<name>.yaml` | Nacos 配置种子（含来源标记）；服务的 `config-center` profile 在部署时读取，见[配置中心](../../../docs/architecture/05-配置中心.md) |

IAM 接入方式：会话 Redis 与 IAM 共用，登录态由 Sa-Token 原生校验；受保护入口经访问组件向 IAM `GET /internal/access/current` 读取当前主体（每个请求最多一次，不跨请求缓存），数据范围经 `GET /internal/access/scopes` 读取；两次调用都携带 Same-Token（`SameTokens.current()`），服务自身入口也校验 Same-Token，直连被拒（见[API 网关](../../../docs/architecture/06-API网关.md#same-token)）。IAM 返回 401／403 时保持语义，其他失败一律按依赖不可用（503）处理，不降级为匿名或允许。地址 `<ENV>_IAM_URL` 为空时经 Nacos 发现名为 `iam` 的服务；连接超时 1 秒、读取超时 2 秒，不自动重试。

## 示例（`--with-example`）

便笺聚合属于创建者，可选归属一个组织。示例覆盖架构要求的三条路径：

| 路径 | 入口 | 说明 |
|---|---|---|
| 命令 | `POST /api/notes`、`PUT /api/notes/{id}` | 入口声明权限码；用例读取写范围后在一个本地事务中核对并保存；版本不符返回 `NOTE_CONFLICT`，范围外对象按 `NOTE_NOT_FOUND` 处理 |
| 纯查询 | `GET /api/me/notes` | 只需登录：Controller → 查询合同 → SQL 投影，不经过编排 |
| 编排查询 | `GET /api/notes` | 先向 IAM 取得读范围，再映射为参数绑定的 SQL 条件；空范围直接返回空结果 |

示例的权限目录在 `src/main/resources/iam/permissions.json`。使用前由系统管理员把它安装到 IAM（`PUT /api/permission-namespaces/<namespace>`，请求体为其中的 `permissions`），再建立角色授予并分配给账号。

`NoteServiceIT` 在真实 PostgreSQL 与会话 Redis 上启动服务，用本地 HTTP 替身按 IAM 公开合同应答，验证 Feign 适配、权限注解、数据范围过滤、业务拒绝与 IAM 故障。不需要示例时直接删除 `note` 相关包、迁移、Mapper 与测试。

## 运行

| 环境变量（前缀为服务名大写、`-` 换成 `_`） | 含义 |
|---|---|
| `<ENV>_DB_URL`、`_DB_USER`、`_DB_PASSWORD` | 本服务自己的 PostgreSQL 库；启动时执行 Flyway，`clean` 禁用 |
| `<ENV>_REDIS_HOST`、`_REDIS_PORT`、`_REDIS_PASSWORD` | 与 IAM 共用的会话 Redis |
| `<ENV>_IAM_URL` | 直连 IAM；为空时经 Nacos 发现 |
| `<ENV>_DISCOVERY_ENABLED`、`_NACOS_SERVER_ADDR` 等 | 服务注册与发现 |
| `<ENV>_PORT`、`_MANAGEMENT_PORT` | 业务端口（默认 8090）与回环管理端口（默认 9092） |

管理端口只开放 `health` 与 `metrics`；readiness 包含数据库与 Redis 检查。多实例部署须为每个实例设置不同的雪花 worker-id／datacenter-id（`MYBATIS_PLUS_GLOBAL_CONFIG_WORKER_ID`、`MYBATIS_PLUS_GLOBAL_CONFIG_DATACENTER_ID`）。

## 验证

- 生成后：`platform/mvnw -f platform/pom.xml verify -pl services/<name> -am`。
- 部署与 IAM 接入闭环：`scripts/verify_closure.sh`，步骤与核对项见[部署参考](../../../deploy/README.md#接入业务服务)。
- 模板自身：`python3 -m unittest discover -s platform/templates/ddd-service -p 'test_*.py'` 检查生成器；`scripts/verify_template.sh` 在仓库的干净副本中生成带示例的服务并执行完整门禁。两者都在 CI 的 template 作业中运行。
- 修改模板资产后，同步更新 `template.json` 的登记；资产中的 `@@NAME@@` 占位符见 `generate.py` 的 `values_for`。
