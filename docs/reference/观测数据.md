# 观测数据参考

平台产出的应用侧观测数据与对接方式；采集、存储、看板、告警由业务项目提供（[O-07](../rules/08-配置与运行.md#o-07-管理端点不公开观测环境由业务项目提供)）。规则见[故障与可观测性](../rules/09-故障与可观测性.md)。

## 指标

各服务管理端口上的 `/actuator/prometheus`（Prometheus 文本格式，带 `application` 标签），只在内部网络可达；业务项目的 Prometheus 在同一网络中抓取（目标为 `<服务名>:<管理端口>`，IAM 9091、网关 9093、模板服务 9092）。指标不附带链路 exemplars，日志与链路按 traceId 关联

## 日志

部署环境（`config-center` profile）每条日志是一行 ECS JSON，写到标准输出，由业务项目的采集端从容器日志读取；本地开发为文本。固定字段：`@timestamp`、`log.level`、`log.logger`、`service.name`（服务名）、`message`，有当前链路时带顶层 `traceId`、`spanId`；异常在 `error.*` 中。每个请求一条访问日志：网关 `gateway_access trace_id=… method=… path=… status=… route=… millis=…`，其他服务 `http_access method=… path=… status=… millis=…`（不含查询参数）。按 traceId 关联一次请求在各服务中的日志。各服务的 `logback-spring.xml` 注册状态监听器，Logback 的内部状态不以文本写到标准输出（配置错误仍使启动失败）。RocketMQ 客户端自带日志实现、不经 SLF4J，部署镜像把它的内部日志写到容器内 `/tmp/rocketmq`（不采集），消息收发结果以消息组件的日志与指标为准

## 链路

OTLP 导出，见[链路追踪](components/tracing.md)

## 健康

管理端口上的 `/actuator/health/liveness`、`/readiness`，部署参考的容器健康检查使用 readiness

## 验证

`scripts/verify_closure.sh` 以临时 Prometheus 与 Jaeger 验证指标与链路可被采集和查询，并逐行按 JSON 解析各服务日志、按 traceId 关联；临时观测端不进入部署参考（[#44](https://github.com/liming-cloud/domain-forge/issues/44)）。
