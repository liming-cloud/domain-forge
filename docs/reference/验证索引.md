# 验证索引

各能力由哪些测试与脚本证明。组件页只写合同，场景与证据集中在这里；新增能力或验证时在对应小节补一行。规则见[测试与验证](../rules/10-测试与验证.md)。

## 配置中心

组件页：[配置中心](components/config.md)

| 场景 | 方式 | 判定 |
|---|---|---|
| 启动读取 | `ConfigCenterIT`：真实 IAM＋PostgreSQL＋Redis＋开启鉴权的 Nacos | 登录防护按 Nacos 中的阈值生效（而非 YAML 默认值） |
| 动态生效 | 运行中发布更严格的阈值 | 之后的登录按新阈值返回 429 |
| 无法应用的值 | 发布越界值或非数字 | 继续按原阈值工作，`rejected` 计数加一；修正后新值生效 |
| 运行中断开与恢复 | 暂停并恢复 Nacos 容器（随机端口映射在重启后会变化） | 断开期间登录照常；恢复后发布的新值生效 |
| 启动时不可达、dataId 不存在 | 启动应用 | 启动失败并给出原因 |
| 日志级别 | 发布 `logging.level` | 对应日志器级别实际改变 |
| 部署 | `verify_deploy.sh` 扩展 | 种子首次发布、重新部署不覆盖控制台修改、备份恢复后配置保留 |

## API 网关

组件页：[API 网关](components/gateway.md)

| 场景 | 方式 | 判定 |
|---|---|---|
| 转发与身份头 | `GatewayIT`：真实网关＋Redis＋开启鉴权的 Nacos＋后端替身 | 按最长前缀转到对应服务；令牌、客户端地址原样到达后端，后端收到同一链路的 `traceparent`，响应只有一个 `X-Trace-Id`；伪造的 Same-Token 被替换为当前值 |
| 登录前置 | 无令牌、无效令牌、只在参数中给令牌；匿名清单 | 前三者 401；匿名接口放行，同一路径的其他方法仍需登录 |
| 禁止与歧义路径 | `/internal/…`、`/actuator/…`、`%2e%2e`、`..;`、`%2F` | 404、404、400 |
| 下游故障 | 无实例、响应超时 | 503、504，统一外壳 |
| 限流 | 同一地址超过桶容量 | 429 与 `Retry-After`，其他地址不受影响 |
| 接口限流 | 发布带 `limits` 的路由；同一账号换客户端地址、两个网关实例交替请求 | 突发用尽后 429（`Retry-After` 1 秒），另一个实例共享计数；其他账号与未声明的接口不受影响；补充后恢复 |
| 路由动态更新 | 运行中发布新路由、非法路由 | 新路由实际转到新服务；非法发布保持原路由并计 `rejected` |
| Same-Token 刷新 | 刚刷新后检查、把当前值的年龄调到一个间隔后检查 | 未满间隔不刷新；满间隔后新值用于转发，上一个值保留 |
| Redis 中断 | 暂停 Redis 容器 | 受保护与匿名请求都 503，限流计数 `unavailable`；恢复后正常转发 |
| 后端校验 | access-control `SameTokenFilterTest`；模板 `NoteServiceIT` | 缺失、伪造 401；当前与上一个值通过；校验方不生成值；部署环境不能关闭 |

## 部署与闭环

### 部署场景（`scripts/verify_deploy.sh`，CI 每次执行）

在独立 Compose 项目中按接口行为核对，不以容器启动或备份文件存在代替。新版本由脚本在当前镜像上叠加验证专用迁移来模拟，不修改源码。耗时随数据量增长，生产数据量下需在部署环境实测。

| 场景 | 核对 |
|---|---|
| 首次部署、管理员初始化、普通重启 | 全部 healthy，仅 nginx 有主机端口；`/internal/`、管理端点经入口为 404，歧义路径不转发；重启后账号仍可登录 |
| 网关 | 响应带 traceId（不沿用客户端的追踪头）且见于网关访问日志；网段内直连 IAM（含伪造 Same-Token 访问 `/internal/`）401；同一地址的突发请求被限流，经配置中心调高阈值后实际生效 |
| 备份、备份后继续变更、删除数据库卷、恢复 | 备份前的账号和密码可用，备份后注册的账号与改密不存在，恢复前的会话被拒绝，审计可查询 |
| 升级到带新增迁移的版本 | 自动生成升级前备份，迁移已执行，账号可登录 |
| 应用回退 | 旧版本在新结构上正常运行，新增的表保留 |
| 迁移失败的升级 | 脚本非零退出；失败迁移没有历史记录、没有残留表；回到上一版本后正常 |
| 数据回退 | 用升级前备份恢复到旧版本后，新版本的迁移与表都不存在，账号可登录 |
| 配置中心 | 种子首次发布且 IAM 读取；运行中发布的阈值经入口登录实际生效；重新部署不覆盖；删除 PostgreSQL 与 Nacos 卷后种子重新发布，恢复后配置回到备份时的值 |
| 定时任务 | IAM 清理任务在部署中登记一次并实际执行成功；重新部署不重复登记、应用保留；删除数据库卷并恢复后任务仍在并继续执行 |
| HTTPS | 用测试 CA 签发证书启用覆盖文件：经 HTTPS 登录；HTTP 301 跳转且健康检查不跳转；接受 TLS 1.2、拒绝 TLS 1.1；默认不发送 HSTS，开启后发送；换证书后实际提供新证书且 Nginx 未重启；私钥与证书不匹配时拒绝重载并继续使用当前证书 |

### 闭环（`scripts/verify_closure.sh`，CI 每次执行）

在仓库干净副本中生成带示例的 `note-service`，以及用 `--call-example note-service --consume-example note-service` 调用它、消费其事件的 `board-service`，与 IAM 一起按[接入业务服务](../../deploy/README.md#接入业务服务)启动，经 Nginx 与网关核对：

- 跨服务调用：board-service 以同一用户身份读取 note-service 的便笺并受其范围限制；note-service 的无权限判定原样到达；note-service 停机时 503，恢复后正常。
- 消息：note-service 创建便笺后 board-service 的便笺统计随事件增加；RocketMQ 停机期间提交的事件留在 Outbox，恢复后继续发送并被消费；备份恢复后统计与便笺一致。
- 链路与日志：临时 Jaeger（`scripts/compose.tracing-verify.yml`）中能查到一条贯穿 gateway、note-service、IAM 与 board-service（消息消费）的链路；各服务容器日志逐行是 ECS JSON，同一请求的 traceId 在其中都能找到。
- 网关与身份：生成的路由写入网关种子并生效；绕过网关直连业务服务 401；无令牌 401；只需登录的查询共用会话即可通过；未授权的命令 403；安装权限目录、建角色授予（本人范围）并分配后命令成功，范围查询只返回本人数据，未分配角色的账号 403；撤销角色后同一会话立即 403。
- 数据隔离：业务服务数据库账号读 IAM 的表被拒，业务表属于服务账号。
- 文件：经 Nginx 与网关上传 2MB 附件并下载核对摘要，无权限账号下载 403，普通接口仍限 64k；附件上传按账号限流。
- 归档库与恢复：便笺归档写入独立的归档库（属于服务账号、主库中无该表）；备份（含文件卷与归档库）后继续写入、上传与重新归档，恢复后只剩备份前的数据、附件与归档快照（两个库一致）且服务仍可写入。
- 服务的 IAM 地址留空，以上结果同时证明其经 Nacos 发现了 IAM。
