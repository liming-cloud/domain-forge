# 扩展路径

每类能力提供真实可用的默认实现与经过验证的扩展路径：业务经公开配置或合同接入扩展，并回归默认实现。取舍见 [ADR 0022](../decisions/0022-扩展路径的取舍.md)。产品要求见实现支持与扩展范围（平台仓库 `docs/platform/产品定义.md`），跟踪见 [#111](https://github.com/liming-cloud/domain-forge/issues/111)。

## 清单

| 能力 | 默认实现 | 扩展路径（公开配置或合同） | 现有验证 |
|---|---|---|---|
| 文件存储 | 本地目录 | 配置切换为 S3 兼容存储，同一 `FileStore` 合同；其他后端：提供 `ObjectStorage` Bean，默认后端让位 | `FileStorageIT`（本地与 S3 通过同一合同；替身后端接入与回归默认） |
| 缓存 | 只用 Redis | 配置开启 L1 本地缓存（Caffeine＋Redis 失效通知） | `NativeCachingIT`、`LocalCachingIT` |
| 关系持久化 | 服务自己的库 | 配置附加数据源（`@AdditionalMapper`，各自事务） | `AdditionalDataSourceIT`、`scripts/verify_closure.sh`（归档库） |
| 业务错误 | 平台 Problem Details | 继承 `BusinessRuleViolation`（类别＋错误码），入口不登记映射 | `ProblemContractTest`、模板 `OrderRejected`、`OrderRuleViolation` |
| 异步消息 | RocketMQ＋Outbox | 实现 `EventHandler` 消费事件、经 `EventPublisher` 发布 | `MessagingIT` |
| 定时任务 | PowerJob | 实现 `ScheduledTask` 登记任务，周期在控制台调整 | `SchedulingIT` |
| 网关路由与限流 | 种子路由 | 在 Nacos 的网关配置中增加路由与接口限流规则，动态生效 | `GatewayIT` |
| 短信 | 阿里云 SendSms | 提供 `SmsSender` Bean 接入其他服务商，默认实现让位（见 [ADR 0022](../decisions/0022-扩展路径的取舍.md)） | `NotificationIT`（阿里云协议替身；替身服务商接入与回归默认） |

每一项都已核对：“经扩展路径接入”与“回归默认实现”两侧都有在 CI 中执行的验证（上表“现有验证”列）。新增扩展路径时同步补这一行和对应测试。

## 新组件的 Bean 可覆盖测试

组件的公开 Bean 可被业务替换（[O-03](../rules/08-配置与运行.md#o-03-spring-装配方式)），由各组件的 `OverridableBeansTest` 验证。公共部分在 `domain-forge-build-rules` 的 test-jar 中（`OverridableBeansContract`：只解析配置类、不创建 Bean，检查“业务 Bean 替换默认”和“不提供时回归默认”两个场景），新组件只写本组件特有的部分：

1. 组件 `pom.xml` 按 test 范围声明依赖：`org.domainforge:domain-forge-build-rules`，`<version>${domain-forge-build-rules.version}</version>`、`<type>test-jar</type>`、`<scope>test</scope>`。
2. 在 `autoconfigure` 包写 `OverridableBeansTest extends OverridableBeansContract`，实现 `types()`（要检查的公开 Bean 类型）、`configurations()`（组件的配置类，条件需要的辅助配置类放在前面）、`user()`；条件需要配置项时覆盖 `properties()`。
3. 嵌套配置类 `User` 为每种类型提供一个业务 Bean（方法体抛 `UnsupportedOperationException`，Bean 不会被创建）；按名称覆盖的 Bean 与默认 Bean 同名。

组件特有的场景（如开关关闭后没有 Bean）在同一个测试类中另写 `@Test`，可用父类的 `start`、`assertProvidedBy`。改测试约定时只改 `OverridableBeansContract`。
