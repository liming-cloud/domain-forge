## Maven 结构

`platform/pom.xml` 是内部 parent 和聚合入口：管理 JDK、依赖版本（Boot、Cloud、Alibaba BOM）和构建插件。各级聚合（`framework`、`services`）只列直接子模块，模块目录名等于 artifactId。只有可运行服务启用 Boot `repackage`。

`domain-forge-build-rules` 例外：它不继承 platform parent（parent 要依赖它，继承会形成循环），自行导入 Boot BOM，版本与 parent 保持一致。

`domain-forge-bom` 只管理平台组件版本，不引入依赖。服务按需显式声明组件，代码直接用到的依赖都要显式声明。

## 质量门禁

`mvn verify` 是本地可完整执行的构建门禁，与 CI 的 `verify` 作业相同；CI 另有模板、部署、闭环与文档作业（见 [CI](#ci)）。

| 检查 | 工具 | 阶段 | 配置位置 | 失败表现 |
|---|---|---|---|---|
| 架构规则：职责包归属、依赖方向、技术边界、internal 访问、跨上下文、SQL 注解与原始 SQL 拼接 | ArchUnit（`ModuleArchitectureTest`） | test | `domain-forge-build-rules/src/main/java` | 测试失败，逐条列出违规类与目标 |
| 单元测试 | JUnit 5 / surefire（`*Test`） | test | 各模块 | 测试失败 |
| 集成测试 | failsafe（`*IT`），依赖由 docker-maven-plugin 启动 | integration-test | parent `pluginManagement` | 测试失败 |
| 格式：缩进、导入分组、空白、括号、行尾与文件末尾 | Spotless 3.10.4（`spotless:check`，Eclipse 格式化器） | verify | `domain-forge-build-rules/src/main/resources/format/eclipse-formatter.xml` | 列出不符合的文件；执行 `spotless:apply` 修正 |
| 格式：行宽、多余导入 | Checkstyle 14.3.0（`format.xml`），格式化器保证不了的部分 | verify | `domain-forge-build-rules/src/main/resources/checkstyle/format.xml` | 列出文件与行号 |
| 类型说明、复杂度、Java 中的 SQL 文本 | Checkstyle 14.3.0 | verify | `domain-forge-build-rules/src/main/resources/checkstyle/` | 列出文件与行号 |
| 直接使用的依赖须显式声明 | `dependency:analyze-only` | verify | parent | 列出未声明的依赖 |

架构规则通过 parent 中的 `architecture-rules` profile 自动作用于所有含 `src/main/java` 的模块：profile 给模块加上规则 JAR 的测试依赖，并让 surefire 扫描其中的 `ModuleArchitectureTest`。新模块不需要任何额外配置。

规则的正反例在 `domain-forge-build-rules/src/test/java`。修改规则时必须同时补充正例和反例。

格式以 Spotless 的输出为准（[源码质量 C-03](../rules/04-源码质量.md#c-03-统一代码格式)）：`spotless:check` 绑定在 verify 阶段，`spotless:apply` 整理格式。在仓库根目录执行时须带 `-f platform/pom.xml`；`domain-forge-build-rules` 不继承 parent，在其 POM 中单独声明同样的配置。

`domain-forge-build-rules` 自身也执行 `main.xml`、`format.xml` 与 `spotless:check`（在其 POM 中单独配置）；测试目录的 fixture 故意违反架构规则，只检查格式。

## 集成测试

集成测试需要 Docker。docker-maven-plugin 在 `pre-integration-test` 阶段启动模块需要的容器（PostgreSQL、Redis、Nacos、RocketMQ、PowerJob、SeaweedFS；镜像固定摘要，PostgreSQL、Redis 与 `deploy/compose.yml` 相同），映射到回环端口，并通过环境变量传给测试。常用变量：

| 变量 | 含义 |
|---|---|
| `POSTGRES_PORT`、`POSTGRES_PASSWORD` | 数据库 `domainforge`，用户 `domainforge` |
| `REDIS_PORT`、`REDIS_PASSWORD`、`REDIS_CONTAINER` | Redis 端口、密码，以及供 `docker exec` 使用的容器名 |
| `NACOS_*`、`ROCKETMQ_*`、`POWERJOB_*`、`S3_*` | 对应容器的地址、端口与凭据 |
| `IAM_DB_*`、`IAM_REDIS_*`、`IAM_FINGERPRINT_KEY` | IAM 应用配置所需的同一组依赖 |

需要容器的模块在自己的 POM 中声明 docker-maven-plugin，并用 `<filter>` 选择 `postgres`、`redis`、`nacos`、`rocketmq`、`powerjob`、`seaweedfs` 中需要的。容器在 `post-integration-test` 阶段删除。

本机没有 Docker 时使用 `-DskipITs -Ddocker.skip=true`，集成测试由 CI 执行。单模块、单测试类与单服务冒烟（`scripts/smoke_service.sh`）的快速命令见[快速反馈](#快速反馈)。

## CI

`.github/workflows/ci.yml` 在 PR 和推送 `main` 时运行六个作业：

- `verify`：`platform/mvnw -f platform/pom.xml verify`，失败时上传测试与 Checkstyle 报告。
- `template`：生成器单元测试，以及 `scripts/verify_template.sh`——在仓库的干净副本中用模板生成带示例的服务并执行完整门禁（见[服务模板使用说明](../../platform/templates/ddd-service/01-使用说明.md#验证)）。
- `deploy`、`deploy-ops`：`scripts/verify_deploy.sh base|ops`，两个并行作业，各在独立 Compose 项目中验证部署参考——`base` 为首次部署、网关、定时任务、重启、备份恢复；`ops` 为配置中心、升级与回退、HTTPS（不带参数则本地顺序执行全部）。
- `closure`：`scripts/verify_closure.sh`，在干净副本中生成服务，与 IAM 一起部署并走完授权、跨服务、消息、链路、指标、日志、文件与恢复等场景。
- `docs`：`python3 scripts/check_doc_links.py`，检查 Markdown 相对链接与锚点。

依赖更新与漏洞提示由 Dependabot（`.github/dependabot.yml`）每周以 PR 形式提出，不阻断构建。

## 快速反馈

`mvn verify` 约 25 分钟，闭环验证（`scripts/verify_closure.sh`）约 12 分钟。开发中先用下面的命令缩小范围，提交前再跑 `mvn verify`。`<模块>` 写相对 `platform/` 的路径，如 `framework/domain-forge-cache`、`services/iam`。

```bash
M="platform/mvnw -f platform/pom.xml"
$M verify -DskipITs -Ddocker.skip=true                           # 快速门禁：全部单元测试、架构规则、Checkstyle，不起容器
$M -q -pl <模块> -am compile                                     # 编译（含上游模块）
$M -pl <模块> -am verify -DskipITs -Ddocker.skip=true             # 单模块门禁：单元测试与静态检查，不起容器
$M -pl <模块> -am verify -Dtest=<测试类> -Dsurefire.failIfNoSpecifiedTests=false \
    -Dsurefire.failIfNoTests=false -DskipITs -Ddocker.skip=true             # 单个单元测试类
$M -pl <模块> verify -Dtest=none -Dsurefire.failIfNoSpecifiedTests=false \
    -Dsurefire.failIfNoTests=false -Dit.test=<集成测试类>                    # 单个集成测试类（会起该模块需要的容器）
$M -q -pl services/<服务> -am package -DskipTests -Ddocker.skip=true  # 只构建服务的可执行 jar
scripts/smoke_service.sh <服务>                                   # 单服务冒烟，约 1 分钟
```

- 快速门禁实测约 1.5 分钟（2026-11-11，8 核，已有编译产物，同机 load average 约 100 时为 81 秒；28 个模块、263 个单元测试）。它不跑集成测试，不能代替提交前的 `mvn verify`。
- IAM 应用层用例用内存 Fake 做单元测试（`services/iam` 测试源码的 `application/InMemoryIam`），集成测试只验证真实数据库、锁和并发；参数相同的 IAM 集成测试经 `SharedIamApplication` 共享一次上下文启动。
- 单服务冒烟按[部署参考](../../deploy/README.md)（`config-center` profile）启动一个服务及其依赖，核对健康检查与标准输出逐行为 JSON。确认启动、配置、依赖打包或日志格式时用它，不要为此跑完整闭环；接口行为、跨服务、消息、备份恢复仍以 `scripts/verify_closure.sh`、`scripts/verify_deploy.sh` 为准。
- 不带 `-am` 时，上游模块取自本地 Maven 仓库中上次安装的版本：改了组件后要么带 `-am`，要么先 `install` 该组件。
- 切换分支或拉取后，`target/` 中残留的旧资源（如已删除类的 `spring.factories` 登记）会让不带 `clean` 的门禁失败：此时在命令中加上 `clean`。
- `-DskipTests` 同时跳过单元测试与集成测试，`-DskipITs` 只跳过集成测试。
- `-Dtest` 配合 `-am` 时必须带上 `-Dsurefire.failIfNoSpecifiedTests=false -Dsurefire.failIfNoTests=false`，否则没有该测试类的上游模块会失败。
- `-q` 会吞掉 `dependency:tree` 等插件的输出，查看这类输出时不要加。
- 文件名含中文：用 `git ls-files -z` 配合 `read -d ''` 处理，不按行分割。
