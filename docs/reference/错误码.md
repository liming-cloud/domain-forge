# 错误码

平台保留的 HTTP 状态与 `code` 的唯一清单。失败响应为 `application/problem+json`，`code` 是扩展字段；成功直接返回资源，没有外壳。Problem Details 格式与失败分类的规则见 [H-01、H-02、H-10](../rules/06-接口与错误.md)；业务自己的拒绝代码由业务定义，不能占用下表中的任何代码。

## 保留代码

| 场景 | HTTP 状态 | `code` | 来源 |
|---|---|---|---|
| 已判定的业务拒绝 | 400／404／409／422 等，由 `Kind` 决定 | 业务自定义的稳定代码 | [Web 组件](components/web-support.md)（`BusinessRuleViolation`） |
| 请求体或参数解析失败；multipart 格式错误；幂等键不合法 | 400 | `INVALID_REQUEST` | Web 组件、[文件存储](components/file-storage.md)、[请求幂等](components/idempotency.md) |
| 网关拒绝可能被后端规范化成其他路径的请求 | 400 | `INVALID_REQUEST` | [API 网关](components/gateway.md#路径检查) |
| 未认证（含 Same-Token 缺失或不符） | 401 | `UNAUTHENTICATED` | Web 组件、网关 |
| 无权限 | 403 | `FORBIDDEN` | Web 组件 |
| 请求体超过上限（上传超过 multipart 上限由文件存储映射；幂等请求体超过 1MB） | 413 | `PAYLOAD_TOO_LARGE` | Web 组件、文件存储、请求幂等 |
| 幂等请求：首次仍在处理 | 409 | `IDEMPOTENCY_IN_PROGRESS` | 请求幂等 |
| 幂等请求：同一键用于不同请求 | 422 | `IDEMPOTENCY_KEY_REUSED` | 请求幂等 |
| 网关限流（带 `Retry-After`；与 IAM 登录防护的 `LOGIN_RATE_LIMITED` 区分） | 429 | `RATE_LIMITED` | 网关 |
| 依赖不可用：存储、短信服务商、Redis、无可用实例、连接失败 | 503 | `SERVICE_UNAVAILABLE` | Web 组件、网关、文件存储、[短信与验证码](components/notification.md)、请求幂等 |
| 下游响应超时（网关连接 2 秒、响应 15 秒） | 504 | `GATEWAY_TIMEOUT` | 网关 |
| 未知异常、映射失败（固定安全提示） | 500 | `INTERNAL_ERROR` | Web 组件、网关 |
| 路由不存在、方法不允许、`/internal/`、管理端点 | 404 / 405 | 保持框架默认，不改写、不包装 | Web 组件、网关 |

## 组件带来的业务拒绝代码

以下代码由组件的规则违反类型自带类别（空文件等 422，过大 413，频控 429），入口不需要再处理；业务同样不能占用。

| 情况 | `code` | 来源 |
|---|---|---|
| 空文件、超过策略上限、类型不允许、文件名无效 | `FILE_EMPTY`、`FILE_TOO_LARGE`、`FILE_TYPE_NOT_ALLOWED`、`FILE_NAME_INVALID` | 文件存储 |
| 号码格式无效或服务商判定无效（`isv.MOBILE_NUMBER_ILLEGAL`、`isv.MOBILE_COUNT_OVER_LIMIT`） | `SMS_INVALID_PHONE` | 短信与验证码 |
| 服务商频控（`isv.BUSINESS_LIMIT_CONTROL`、`isv.DAY_LIMIT_CONTROL`） | `SMS_RATE_LIMITED` | 短信与验证码 |
| 验证码重发间隔内、当天已达上限 | `VERIFICATION_TOO_FREQUENT`、`VERIFICATION_DAILY_LIMIT` | 短信与验证码 |

验证码的校验结果（`VERIFIED`、`MISMATCH`、`EXPIRED`、`LOCKED`）不是异常，业务按自己的合同映射为业务拒绝。

## IAM 的业务拒绝代码

IAM 应用层的 `IamException` 与领域层的 `IamRuleViolation` 都继承 `BusinessRuleViolation`，经唯一分派点转换。输入无效统一为 400 `INVALID_REQUEST`，未认证、无权限分别为 `UNAUTHENTICATED`、`FORBIDDEN`；领域规则的代码（如 `ROLE_CODE_INVALID`、`ORG_MOVE_CYCLE`）见 IAM 领域模型。应用层另有：

| 情况 | HTTP 状态 | `code` |
|---|---|---|
| 登录凭据无效；改密时当前密码不符 | 401 | `LOGIN_FAILED`、`PASSWORD_MISMATCH` |
| 请求的账号、角色、菜单、组织不存在 | 404 | `ACCOUNT_NOT_FOUND`、`ROLE_NOT_FOUND`、`MENU_NOT_FOUND`、`ORG_NOT_FOUND` |
| 版本已变化、并发修改（唯一约束冲突） | 409 | `VERSION_CONFLICT` |
| 同级组织重名；组织仍被引用 | 409 | `ORG_NAME_TAKEN`、`ORG_IN_USE` |
| 角色代码已存在；角色仍分配给账号 | 409 | `ROLE_CODE_TAKEN`、`ROLE_IN_USE` |
| 菜单代码已存在；菜单仍有下级 | 409 | `MENU_CODE_TAKEN`、`MENU_IN_USE` |
| 登录名已不可邀请；原邀请不可重发、已被使用 | 409 | `LOGIN_NAME_TAKEN`、`INVITATION_NOT_RESENDABLE`、`INVITATION_USED` |
| 权限目录超过 1000 项；被引用的权限不能移除或改变范围 | 409 | `CATALOG_TOO_LARGE`、`PERMISSION_IN_USE` |
| 必须保留至少一名启用的系统管理员；项目已经初始化 | 409 | `LAST_ADMINISTRATOR`、`ALREADY_INITIALIZED` |
| 父组织、范围中的组织、成员归属的组织不存在 | 422 | `ORG_PARENT_UNKNOWN`、`GRANT_UNIT_UNKNOWN`、`MEMBERSHIP_UNIT_UNKNOWN` |
| 分配的角色不存在或已停用；父菜单、菜单关联的权限不存在 | 422 | `ROLE_UNAVAILABLE`、`MENU_PARENT_UNKNOWN`、`MENU_PERMISSION_UNKNOWN` |
| 登录尝试过多；密码计算繁忙（都带 `Retry-After`） | 429 | `LOGIN_RATE_LIMITED`、`PASSWORD_BUSY` |
| 提交阶段失败、结果未知 | 503 | `IAM_RESULT_UNKNOWN` |

## 服务间调用的失败分类

不是 HTTP 代码，是 `ServiceCallException` 的分类，见[跨服务调用](components/service-call.md#组件合同)。
