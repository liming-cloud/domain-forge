# 身份权限参考

IAM 是业务应用，复用访问控制与缓存组件；保留四层并按真实职责适度分包。SQL 在 XML／合法 MyBatis-Plus 链式调用；领域仅用 shared 纯 Java 标识。边界、术语、场景与聚合模型见[身份权限模型](../explanation/身份权限模型.md)，技术基线的取舍见 [ADR 0010](../decisions/0010-IAM的技术基线.md)。

## 标识、登录名与密码

账号、邀请、审计及外键采用 MyBatis-Plus 雪花 Long／BIGINT，HTTP 为十进制字符串；登录名推荐 ASCII 小写 `a-z0-9._-`、3—64 字符，按合同显式规范化，数据库唯一约束兜底，公开响应不泄露不存在／禁用／密码错误的差别。密码本单元采用 15—128 Unicode 码点，允许空白及 Unicode，不 trim、不截断、不隐式规范化，最多 512 UTF-8 字节；创建与修改使用同一规则并拒绝随制品提供的固定常见密码列表，列表版本及摘要可查，不调用第三方提交明文密码。本单元没有 MFA／找回密码；失去全部管理凭据的运维恢复另行设计，不能提供后门。

## 权限码与初始管理员

IAM 不拥有员工、客户、订单等业务服务数据。权限码形如 `namespace:resource:action`，IAM 自身命名空间 `iam` 由数据库基线维护：普通管理权限 `iam:invitation:create`、`iam:account:read`、`iam:account:state`、`iam:audit:read`、`iam:org:read`、`iam:role:read`、`iam:menu:read`、`iam:catalog:read`，以及只能授予系统角色的 `iam:org:manage`、`iam:member:manage`、`iam:role:manage`、`iam:account:role`、`iam:catalog:manage`、`iam:menu:manage`。未知权限不可授予。普通注册账号初始无角色，仅可登录、退出、改密及读取自己的最小资料与可见菜单；无默认组织、角色或租户。

初始管理员只分配受保护的 SYSTEM_ADMIN 角色，不使用超级用户绕过分支或通配符。变更用例在同一事务内重新核对当前操作者的有效依据。初始化命令不开放HTTP，凭据经交互输入或受保护文件读取，不放命令参数／日志；审计把来源标为受控部署命令，不把操作者自填名字伪装成已认证自然人。

## 数据范围合同

数据范围支持 SELF、DEPARTMENT、DEPARTMENT_AND_DESCENDANTS、CUSTOM_DEPARTMENTS、ALL；NOT_APPLICABLE 仅适用于目录声明的非数据操作，不是 ALL。部门型范围以当前全部有效成员部门为起点；CUSTOM 只包含列出的有效部门，不隐含子树。按某个精确权限合并有效角色中该权限的范围，再与业务资源／状态条件相交；无匹配授权为空，解析失败不能放行。角色 A 的订单 SELF 与角色 B 的发票 ALL 不能组合成订单 ALL。ALL 仍限于本系统和该权限资源类型。

公共 current() 返回可信主体、角色和精确权限，scope(permissionCode) 按精确权限取范围；范围合同不含 SQL、字段名或自由表达式。current 单次边界为 20 个角色、1000 个精确权限码和 256KiB；范围批量最多 32 项、每项 1000 个组织 ID、总响应 2MiB。超限明确失败，禁止截断后继续允许。

每次授权由主库单条 SQL／CTE 在同一语句快照中计算许可、账号、角色、权限、成员和组织有效性，不拼多个 READ_COMMITTED 语句制造混合授权图。范围响应与其主体、精确权限及校验时点绑定，不拼接旧入口角色。业务 Query 将可信范围映射为参数绑定 XML 谓词，列表、数量、分页、导出、单条与写入同样受限；写入还验证本地对象与状态。首版不建通用 SQL 拦截器、策略 DSL 或 DENY 引擎。

## 锁顺序

不中途倒序补锁。账号不加行锁：账号自身的修改（登录登记许可、改密、启停、角色、成员）统一按读到的 `version` 条件更新（CAS），零行即 409。

| 顺序 | 锁 | 何时取 |
|---|---|---|
| 1 | 管理员保全（唯一 `administration_guard`） | 可能移除系统管理员的操作（禁用、改角色）与初始化 |
| 2 | 组织协调 | 组织结构、成员与范围引用的写入 |
| 3 | 目录与菜单协调锁 | 授予、菜单引用权限时取目录共享锁；目录安装取目录排他锁；菜单写入先取菜单协调锁 |
| 4 | 幂等键 | 带幂等键的写入 |
| 5 | 按 ID 排序的角色／组织行 | 角色、组织行的写入 |

第 4 行沿用原设计文本；IAM 代码目前没有使用幂等键，第 3、4 行的相对顺序原文未写明，新增相关写入前先核对代码。


## 接口与实现要点

| 资源 | IAM 后端接口 | 权限 |
|---|---|---|
| 组织 | `GET /api/organization-units`；`POST`；`PUT /{id}/name`、`/{id}/parent`、`/{id}/state`；`DELETE /{id}?expectedVersion=` | 读 `iam:org:read`；写 `iam:org:manage`＋系统管理员 |
| 成员归属 | `PUT /api/accounts/{id}/memberships` | `iam:member:manage`＋系统管理员 |
| 角色与授予 | `GET /api/roles`、`/api/roles/{id}`；`POST`；`PUT /{id}/name`、`/{id}/state`、`/{id}/grants`；`DELETE /{id}` | 读 `iam:role:read`；写 `iam:role:manage`＋系统管理员 |
| 账号角色 | `PUT /api/accounts/{id}/roles`；详情 `GET /api/accounts/{id}` | `iam:account:role`＋系统管理员；读 `iam:account:read` |
| 权限目录 | `GET /api/permissions`；`PUT /api/permission-namespaces/{namespace}` | 读 `iam:catalog:read`；安装 `iam:catalog:manage`＋系统管理员 |
| 菜单 | `GET /api/me/menus`（登录即可）；`GET /api/menus`；`POST`；`PUT /{id}`、`/{id}/parent`、`/{id}/state`；`DELETE /{id}` | 读 `iam:menu:read`；写 `iam:menu:manage`＋系统管理员 |
| 当前授权 | `GET /internal/access/current`；`GET /internal/access/scopes?permission=…`（1—32 个） | 登录 |

- 写接口都要求 `expectedVersion`，版本不符或对象不存在返回 409；同级重名、代码重复和并发唯一约束冲突同样为 409。
- 系统专属权限（目录 `system_only`）只能授予 SYSTEM_ADMIN；SYSTEM_ADMIN 的授予由基线固定，不能修改、停用或删除。
- 外部服务通过安装自己的命名空间登记权限；被角色授予或菜单引用的权限不能移除，也不能改变是否需要数据范围。目录总量上限 1000。
- 授予的范围必须与目录声明一致：需要范围的权限只能用 SELF、DEPARTMENT、DEPARTMENT_AND_DESCENDANTS、CUSTOM_DEPARTMENTS、ALL；其他权限只能用 NOT_APPLICABLE。CUSTOM_DEPARTMENTS 列 1—1000 个组织，不隐含子树。
- `current` 与 `scopes` 都在一条 SQL 中同时核对会话许可、账号、启用角色、授予、成员归属与组织有效性；停用角色、组织或修改归属在下一次检查即生效。`scopes` 返回 `CurrentScope(all, self, unitIds)`，无授予为空范围，组织 ID 为十进制字符串。
- 登录不锁账号：与改密／禁用并发时许可可能带旧凭据版本写入，但许可校验要求账号启用且凭据版本一致（启停也递增凭据版本），这样的许可无法使用。所有管理写入与审计同事务。
- 事件、Outbox 或审计不能承担新检查立即生效；只有真实订阅者出现时再设计领域／集成事件和可靠外发。协议、SDK、BOM 及消费者输入成套演进，有旧客户端时显式版本化，不对严格解码端点无声加字段。

## SQL 与会话状态的生效合同

会话有效必须同时满足：原生 Sa-Token 会话有效、SQL 会话许可未撤销且未过期、账号启用、凭据版本一致。权限从 IAM 主库读取当前事实，跨请求不缓存允许结果；已完成授权检查的在途请求不追溯取消。

实现顺序：

- 登录：在事务外校验密码并原生签发 token；再用短事务锁定账号，重新核对启用状态与凭据版本，登记 SQL 许可；提交成功后才返回 token。失败时尽力撤销原生会话，失败的 token 不泄漏。
- 改密、禁用：提交新的凭据版本，旧许可随即不再满足身份校验。
- 退出：先提交当前许可的撤销，再尽力清理原生会话；清理失败计入指标，不恢复许可，也不声称 Redis 已回滚。
- 结果未知时不自动重试，不报告确定成功。

使用 Sa-Token 1.46.0 官方 Redisson DAO（由 access-control 装配），与 cache 组件共用同一个 `RedissonClient`，不自写 DAO。从 Redis 快照恢复后不复活会话，用户重新登录。

必须覆盖的验证：双实例下登录与改密／禁用交错、原生签发或撤销部分失败、响应丢失与重连、SQL 提交失败。

迟到写入由 SQL 许可兜底，见 [ADR 0023](../decisions/0023-会话迟到写入由SQL许可兜底.md)。

## 默认登录防护及审计

账号规范化登录名 10 分钟最多 5 次失败／未完成校验，来源地址每分钟 30 次尝试；保持原子预占、成功只释放本次预占、同名不存在账号的同等响应与密码计算。Redis 不可用或容量失败拒绝；安全键 noeviction，不进入普通缓存或 L1。Argon2id 保持 m=19456KiB、t=2、p=1、16 字节盐、32 字节结果，默认并发 2／队列 8／等待 1 秒。计数键仍用 HMAC，不记录秘密。

关键管理变更与必要审计同库同事务，审计失败回滚业务；没有通用 operationId／回执／UNKNOWN 查询、人工补录或提交后独立补偿。SQL 提交不确定仍返回安全错误并读取业务事实核对，不自动重试。审计只保存操作者（账号 ID 或 `deployment-command`、`invitation-holder` 等受控来源标识）、目标业务 ID、动作和数据库时间，不存原始密码／token／摘要；保留 90 天，由定时任务 `iam-retention`（PowerJob 调度，见[定时任务](components/scheduling.md)）分批清理。邀请一次消费、管理者保全、行锁和版本冲突继续验证。

## 登录防护配置

配置使用应用 YAML，保留已有保守参数边界及算法强度；服务覆盖组件默认配置。没有 SQL 防护策略代际、切换 CLI 或强制恢复控制系统。配置变更通过普通停机／重启部署生效；正常 Redis 重连保留计数，丢失数据不承诺保留旧计数，不自行新增热切换协议。

## 服务接入与故障边界

会话由公共组件复用原生 Sa-Token；账号密码与当前权限事实归 IAM。失败不得转换为匿名或被 OR 备选吞掉。

### 微服务调用与发现

没有独立的 iam-client 模块：调用服务自身 infrastructure 定义类型化 Feign＋Nacos，后端 HTTP，原生连接池与有限阶段超时；凭证仅传到该 IAM 接口；Same-Token、链路上下文、超时、不跟随重定向、不重试与失败分类由[跨服务调用组件](components/service-call.md)统一提供。无项目匹配、SAN、SSL Bundle 或自写域名解析。

### 原生执行与组件装配

IAM 本地实现 `StpInterface`，其他服务实现本地 Feign 适配；组件边界见[访问控制组件](components/access-control.md)。保留显式访问策略、遗漏拒绝与安全错误。

### 当前HTTP合同

GET /internal/access/current 只读当前 Bearer 本人，不接收任意账号 ID，返回账号 ID、角色、精确权限，无 projectId；仅检查登录与账号有效，不回调权限 SPI。纯登录检查无需 IAM HTTP；权限读取失败拒绝，同请求可绑定 token 复用一次，结束释放。成功直接返回资源，失败为 Problem Details；业务 ID 为十进制字符串。

## 目录、依赖和使用方式

目录、依赖图与 shared 单模块单包见[总体结构](../explanation/总体架构.md#仓库分区)。IAM application 通过组件公开接口使用会话能力；infrastructure 使用原生 Redis 脚本能力实现 LoginProtection，不复制客户端配置。业务事务默认 @Transactional REQUIRED／全异常回滚，密码计算的短事务片段用原生 TransactionOperations。暂不引入分布式事务协调器，未来真实跨服务写入再按系统规范选择。

## 使用路径

从干净源码通过 platform/mvnw 构建，用 deploy Compose 启动依赖与 IAM；配置 YAML 提供环境凭据，显式初始化管理者，再邀请注册、登录、读取本人／受保护查询、改密／撤权与退出。HTTP 默认无后端证书；HTTPS 由 Nginx 覆盖文件 `compose.https.yml` 启用，见[部署参考](../../deploy/README.md#https)。部署与初始化命令见[部署参考](../../deploy/README.md)。
