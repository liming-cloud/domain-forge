## 统计口径

- PR 与任务的关系：PR 的 `closingIssuesReferences`，或标题末尾的 `(#任务号)`。
- 评审轮次 = 1 + “要求修改”评审次数；评审意见数 = PR 对话评论数 + 带正文的评审数。本仓库由同一账号开 PR、自动合并，评审多发生在 PR 外，因此这两项偏低。
- AI 一次通过率 = 没有 `rework` 标签且评审轮次为 1 的 PR 占比。历史 PR 没有统一打 `rework`、`escaped-defect` 标签，这两项在首份报告中偏低，随着标签纪律建立才有参考价值。
- 交付周期取 PR 创建到合并；任务开工时间 GitHub 上没有记录，不另算。
- 模块数 = PR 改动文件所属的 Maven 模块去重个数；只改文档、脚本、CI 的 PR 为 0。
