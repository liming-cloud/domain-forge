# 工程北极星

目标：**AI 写的改动一次就对；出错由机器当场发现；人只做决定。**

2026-11-09 综合本仓库与 rag-pilot 的长处定下（[#137](https://github.com/liming-cloud/domain-forge/issues/137)），两个仓库正文一致；口径变化见 [ADR-0029](../decisions/0029-工程北极星与度量口径.md)。规范的可执行条目只写在规则卡里，本页列出每条规范对应的卡。价值北极星、变更局部性与耦合基线见[质量模型与北极星](质量模型与北极星.md)。

## 指标

由 [`scripts/dev_metrics.py`](../../scripts/dev_metrics.py) 统计，报告见[度量报告](度量报告/首版.md)。

| 指标 | 口径 | 目标 |
|---|---|---|
| 规则可执行率 | 检查行含“自动”标签的规则卡 ÷ 全部规则卡（[规则卡索引](../rules/00-索引.md)） | 「工程优化」里程碑结束时 ≥ 40%，首版收尾时 ≥ 50% |
| 快速反馈 | 本地快速门禁（`verify -DskipITs -Ddocker.skip=true`）时长；CI 完整门禁时长（`mvn verify` 作业与整次运行墙钟） | 见 [T-13](../rules/10-测试与验证.md#t-13-反馈时间有上限) |
| 一次通过率 | 没打 `rework` 标签的已合并 PR ÷ 全部已合并 PR | 越高越好 |
| 逃逸缺陷 | 带 `escaped-defect` 标签的 issue 数 | 不上升 |
| 编译告警 | 为 0，由编译参数 `-Xlint:all` 与 `failOnWarning` 保证（[C-18](../rules/04-源码质量.md#c-18-编译零告警)） | 0 |

`rework`：PR 合并后发现做错、需要再开 PR 修正时，给原 PR 打上。`escaped-defect`：通过门禁和评审后才发现的缺陷 issue。
