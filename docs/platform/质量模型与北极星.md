# 质量模型与北极星

平台维护者用来判断方向的指标与基线。质量模型见 [ADR-0001](../decisions/0001-质量模型.md)，原则与规则卡见[规则卡索引](../rules/00-索引.md)。

## 北极星

| 类别 | 指标 | 口径 |
|---|---|---|
| 价值北极星 | AI 一次通过率；中位交付周期 | 在全新副本中，AI 编码工具只凭仓库文档交付真实业务用例。一次通过率指不经返工就通过门禁和人工评审的比例；交付周期从 issue 开工算到 PR 合并 |
| 质量北极星 | 原则可执行率 | 规则卡中，检查含“自动”标签的卡占全部卡的比例 |
| | 变更局部性 | 单个业务 PR 涉及的 Maven 模块数和上下文数，越少越好 |
| 护栏 | 逃逸缺陷数不上升 | 带 `escaped-defect` 标签的缺陷 issue 数 |
| 领先指标 | 反馈时间 | 目标见 [T-13](../rules/10-测试与验证.md#t-13-反馈时间有上限) |
| | 组件耦合 | 组件间环数和违反稳定依赖的依赖数（硬规则，保持为 0，见 [S-24](../rules/02-系统设计.md#s-24-组件之间无环依赖指向更稳定的一方)）；Lakos 的 NCCD 和各组件的 D 值（只作报表，看趋势） |
| | 变更前置时间、返工率 | 参考 DORA 的五项交付指标，返工率用修复类 PR 的占比近似 |

决定见 [ADR-0002](../decisions/0002-双北极星与反馈时间目标.md)。指标由 [`scripts/dev_metrics.py`](../../scripts/dev_metrics.py) 按里程碑统计，报告见[度量报告](度量报告/首版.md)。

## 耦合度量基线（2026-11-05）

用 ArchUnit 1.5.1 的 `ArchitectureMetrics` 对 `shared`、12 个组件、IAM 和网关的生产代码测量。

| 粒度 | 组件数 | 环 | 违反稳定依赖 | Lakos NCCD |
|---|---|---|---|---|
| Maven 模块 | 15 | 0 | — | 0.69 |
| 组件内（api/internal/autoconfigure 与服务职责包） | 44 | 0 | 0 | 0.62 |

D 值不作门槛的原因见 [ADR-0003](../decisions/0003-组件耦合的度量与硬规则.md)。

同时测得的层违例：IAM 中 `interfaces → domain` 有 6 个文件，`infrastructure → interfaces` 为 0，领域层通用异常有 54 处。
