# 0027 错误、日志与空值约定

- 状态：已接受（2026-11-12）
- 关联 issue：#138

## 背景

IAM 另有一套异常体系（`IamException`＋`IamFailure`），与平台的 `BusinessRuleViolation.Kind` 重复，冲突类错误都是 `IAM_CONFLICT`，“目标不存在”返回 409；应用层抛 `IllegalArgumentException` 等通用异常时落成 500；包装异常时丢了原因；日志 API 同时有 slf4j 与 `java.util.logging`；全仓没有空值约定，编译不开告警。

## 决定

人在 #138 中逐项确认（2026-11-12，全部按推荐）：

- **IAM 并入平台失败模型**：`IamException` 继承 `BusinessRuleViolation`，按场景给稳定错误码（清单见[错误码](../reference/错误码.md#iam-的业务拒绝代码)），由 `Problems.dispatch` 统一转换；依赖不可用改为 `IamUnavailableException`（继承 `DependencyUnavailableException`，带原因）。请求的目标不存在返回 404，请求引用的其他资源（父组织、范围组织、角色、菜单、权限）不存在返回 422，版本已变化与并发唯一约束冲突返回 409 `VERSION_CONFLICT`。这是不兼容的接口变更，首版尚未发布，不保留旧代码。
- **领域层与应用层都不抛通用异常**：构建规则 `[通用异常]` 从领域层扩展到应用层；用户输入无效一律为 400 `INVALID_REQUEST`。
- **包装异常保留原因**：会话存储、登录防护、密码计算、身份事实源不可用时，原始异常作为 cause 交给内部诊断（`Problems` 只记录类型与位置，不读消息）。
- **日志只用 slf4j**：构建规则 `[日志 API]` 禁止 `java.util.logging` 与 `org.apache.commons.logging`。
- **JSpecify 空值约定**：每个生产包的 `package-info.java` 标 `@NullMarked`，可能为空的返回值、参数与字段标 `@Nullable`；构建规则 `[空值约定]` 检查每个包都已标注。领域层与应用层可以使用 `org.jspecify.annotations`。模板生成器为生成的每个包写 `package-info.java`。版本由 Spring Boot 管理（Spring 7 已依赖它）。
- **编译零告警**：`-Xlint:all` 与 `failOnWarning`；只排除 `processing`（注解处理器不认领 Spring、JUnit 等注解时必然告警，源码中无法消除）。异常类声明 `serialVersionUID`，未引用的 try 资源用未命名变量 `_`。

不采用：

- 引入 NullAway 等空值静态检查：要再加编译插件与依赖，另议；本次只建立约定与包级覆盖。
- 排除 `serial` 告警：能在源码中消除，不属于“无法消除”。

## 后果

- 客户端按错误码区分失败原因；依赖 IAM 旧 `IAM_CONFLICT` 或“不存在为 409”的调用方要改。
- 新包缺 `package-info.java` 时 `mvn verify` 失败；新增的告警直接使构建失败。
- 文件存储的 S3 客户端改用 SDK 默认 HTTP 客户端（`s3` 自带的 apache5-client），删除已弃用的 `apache-client` 依赖与 `domainforge.files.s3.socket-timeout` 配置（单次调用超时 `attempt-timeout` 已限制读取时长）。
- `@Nullable` 目前靠评审保证完整，没有编译期检查。
