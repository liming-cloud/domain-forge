# 0008 组件扩展机制

- 状态：已接受（2026-11-05）
- 关联 issue：[#93](https://github.com/liming-cloud/domain-forge/issues/93)、[#111](https://github.com/liming-cloud/domain-forge/issues/111)

## 背景

业务项目需要替换短信服务商、文件存储后端等提供方，并覆盖组件的默认装配，但组件没有统一的扩展惯例。

## 决定

遵循 Spring Boot 自动配置惯例：可替换的提供方以 Spring Bean SPI 定义，默认实现在用户自定义 Bean 时让位；autoconfigure 中的公开 Bean 都可覆盖；配置用 `@ConfigurationProperties` 绑定并生成配置元数据。

## 后果

- 规则写入 [S-25](../rules/02-系统设计.md#s-25-可替换的提供方以-spring-bean-spi-定义)、[O-03](../rules/08-配置与运行.md#o-03-spring-装配方式)，由 [#111](https://github.com/liming-cloud/domain-forge/issues/111) 实施。
- 由 #111 修订：[短信与验证码](../reference/components/notification.md)中写死的 `provider: aliyun`；[扩展路径](../reference/扩展路径.md)清单。
