# 0028 模板作为标准样例：包结构、仓储冲突约定、领域事件

- 状态：已接受（2026-11-13）
- 关联 issue：#139

## 背景

每个业务服务都从模板 `platform/templates/ddd-service` 开始，模板的写法会被大量复制，但它和 IAM 的约定不一致：`application/usecase/order/ReadOrderFiles` 从 `application.command.order` 导入命令与查询共用的类型；模板的仓储 `update` 返回 `boolean`、由应用层抛冲突，同时又加悲观锁，而 IAM 的仓储在基础设施层抛应用层异常 `IamException`、不加锁；领域事件 `OrderSubmitted` 没有标注角色，聚合用单个可空字段暂存事件；应用层没有快速测试的样例。

## 决定

人在 #139 中确认（2026-11-13，三项按推荐；开工核对后两处在会话中补充答复）：

- **仓储冲突约定**：普通修改不加锁，读取时核对版本，保存时以原版本为条件更新；仓储只返回是否写入（零行为 `false`），由应用层抛 409 `VERSION_CONFLICT`（与 IAM 相同的错误码）。异常留在应用层，符合 [ADR-0007](0007-适配器的依赖方向.md) 的依赖方向。IAM 的账号、角色、组织、菜单、邀请五个仓储同步改为返回 `boolean`，冲突由 `ExpectedVersion.saved` 在应用层判定。版本条件保证不了的约束才加锁并写明原因（[P-09](../rules/05-持久化.md#p-09-并发约束由数据库保证)），模板中只有凭证数上限（先计数再插入）锁定订单；IAM 现有的锁保护组织树、范围内唯一等约束，本次不动。
- **包结构**：命令与查询共用的 `OrderAccess`、`OrderPermissions`、`OrderRejected` 移到 `application/order`。原答复让 `ReadOrderFiles` 移到 `application/query/order`，但它要加载订单做资源授权，[S-09](../rules/02-系统设计.md#s-09-纯查询走短路径) 的自动检查禁止 `application.query` 依赖领域仓储，人改为留在 `application/usecase/order`。
- **领域事件**：`OrderSubmitted` 标 jMolecules `@DomainEvent`，实现密封接口 `OrderEvent`；聚合用不可变列表暂存事件，`withoutEvents()` 返回不含事件的新实例，`Order` 保持不可变。应用层保存成功后用穷尽的 `switch` 把每种领域事件映射为集成事件。为此引入 `org.jmolecules:jmolecules-events:1.10.0`（只含注解，与 `jmolecules-ddd` 同版，人在会话中同意），领域层允许依赖 `org.jmolecules.event`（[S-02](../rules/02-系统设计.md#s-02-领域层不依赖框架)）。
- **应用层测试样例**：`OrderLifecycleTest` 用内存 Fake 替代仓储与事件端口，覆盖成功、范围外按不存在处理、版本冲突（含读取后被他人修改）与非法迁移，断言拒绝时没有写入、没有发布事件。

不采用：

- 模板改为在基础设施层抛冲突（IAM 原写法）：基础设施层要依赖应用层异常，方向与 ADR-0007 相反。
- 去掉 `usecase` 包、把读取凭证改为 SQL 内判断范围的纯查询：改动更大，样例中也就没有“需要加载聚合的查询用例”的写法。

## 后果

- 模板版本 0.18.0。订单版本冲突的错误码由 `ORDER_CONFLICT` 改为 `VERSION_CONFLICT`，属于不兼容的接口变更；首版尚未发布，不保留旧代码。
- 已从旧模板生成的服务不自动升级，按需对照模板调整。
- 新增需要锁的场景时，在用例的类注释中写明“版本条件为什么不够”。
