# 0025 Outbox 中继改为租约认领

- 状态：已接受（2026-11-11）
- 关联 issue：#150（来源 #115 的 D9）
- 补充：[0014](0014-消息与Outbox的取舍.md) 的“可靠发送”，规定中继如何发送

## 背景

中继原来在一个事务里 `FOR UPDATE SKIP LOCKED` 抢占一批记录、逐条同步发送 RocketMQ、再记录结果，整批发送期间一直占着数据库连接和行锁。RocketMQ 变慢时，连接池和行锁被中继拖住，影响同库的业务事务。

## 决定

- **认领、发送、标记分开**：短事务内 `FOR UPDATE SKIP LOCKED` 选出到期且没有有效租约的记录，写入租约截止时间（`claimed_until`）和本批令牌（`claim_token`）后立即提交；在事务外发送；发送成功或失败后各用一个短事务写结果。
- **租约时长固定 60 秒**，不新增配置项：远长于 RocketMQ 单次发送超时，且一批遇到第一次失败就停止。
- **结果按记录 ID＋令牌写回**：租约过期被其他实例接手后，原实例迟到的结果不覆盖新结果。
- **按键保序不变**：同一顺序键前一条未发送时后续记录不可见，与租约无关；前一条被认领期间同样不可见。
- **一批中出现发送失败仍停止本批**：失败的记录按原退避规则重试，同批未发送记录的租约随即释放，下一轮即可认领。
- **数据变更只加两个可空列**，无回填。

不采用：RocketMQ 事务消息（0014 已定不依赖）；发送前不认领、只靠 `SKIP LOCKED` 的事务（即原做法）。

## 后果

- 发送期间中继不持有连接与行锁（`OutboxLeaseIT`）。
- 重发的机会多了一种：发送超过 60 秒、或中继在发送中被终止，租约过期后由其他实例（或重启后的本实例）重新认领，可能重发同一事件 ID。仍是“至少一次、消费方去重”的既有合同。中继停止时被中断的那一批，要等租约过期（至多 60 秒）才会再发。
- 已建表的服务须新增迁移 `alter table domainforge_outbox add column claimed_until timestamptz, add column claim_token varchar(36)`，不能修改已执行的迁移。
- 合同与用法见[消息与 Outbox](../reference/components/messaging.md)。
