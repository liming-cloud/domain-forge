# 0009 失败模型与协议

- 状态：已接受（2026-11-05）
- 关联 issue：[#93](https://github.com/liming-cloud/domain-forge/issues/93)、[#105](https://github.com/liming-cloud/domain-forge/issues/105)

## 背景

失败没有统一的类型：领域层有 54 处通用异常；业务拒绝返回 200 加业务码，与 HTTP 语义和 RFC 9457 不一致；业务异常要按确切类型逐个登记映射。

## 决定

- 失败分为业务拒绝、依赖不可用、程序错误三类。`shared` 定义业务规则违反和依赖不可用两个基类；web-support 是唯一分派点，组件不注册全局异常处理。
- 业务拒绝改用 4xx 和 Problem Details（RFC 9457），属于不兼容的合同变更；与失败模型在同一任务中完成。

- 成功响应不再使用外壳，直接返回资源（无响应体用 204）；`shared.ApiResponse` 已删除。错误码放在 Problem Details 的扩展字段 `code`。
- 状态码：输入格式错误 400，未认证 401，无权限 403，资源不存在 404，状态冲突与并发冲突 409，业务规则不满足 422，请求体过大 413，限流 429，依赖不可用 503，程序错误 500（2026-11-08 确认，见 [#105](https://github.com/liming-cloud/domain-forge/issues/105)）。
- 第三方框架的原生异常通过 web-support 的 `FailureTranslator`（`ServiceLoader` 登记）转为上述类型，使分派点仍然只有一个。
