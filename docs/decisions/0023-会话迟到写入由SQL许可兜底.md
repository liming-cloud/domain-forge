# 0023 会话迟到写入由 SQL 许可兜底

- 状态：已接受（2026-10-23）
- 关联 issue：#35

## 背景

Sa-Token 原生 Redis 写入在客户端超时、账号 SQL 锁释放后才到达，会覆盖新登录的终端列表，之后按列表撤销会遗漏仍有效的 token。

## 决定

- 保留"SQL 会话许可 + credentialVersion"作为授权的必要条件，原生会话有效、许可未撤销未过期、账号启用、凭据版本一致必须同时成立；权限从 IAM 主库读取，跨请求不缓存允许结果。在此前提下，迟到写入只影响终端列表的完整性，不会造成越权。不采用自写 DAO、会话 CAS／代际／墓碑或第二套 token 索引。

## 后果

- P2 已将此组合定为最终设计，不再追求删除 SQL 许可。原专项探针 IT 已删除，必要场景（许可提交失败不返回令牌、改密／禁用与登录交错）并入 `IdentityPersistenceIT`，随 `mvn verify` 执行。
- 合同与用法见[身份权限](../reference/身份权限.md#sql-与会话状态的生效合同)。
