# 0022 扩展路径的取舍

- 状态：已接受（2026-11-03，同日修订；2026-11-05 补充 SPI 范围）
- 关联 issue：#111

## 背景

各类能力需要明确默认实现与经验证的扩展路径，以及是否需要正式 SPI。

## 决定

- **是否需要正式 SPI**：需要。可替换的能力提供方以正式 SPI 定义：组件公开提供方接口，平台现有实现作为其中一个提供方并保持默认，业务项目可以实现并接入新的提供方，组件不需要修改。机制为 Spring Bean SPI，范围为短信服务商与文件存储后端（2026-11-05 决定，见 #111）
- **配置中心**：默认且只用 Nacos，不列为扩展路径
- **链路导出**：不列为扩展路径（OTLP 导出保持为可选配置）
- **清单由谁确认**：下表由实现方起草，人在 #111 中确认后作为首版验收清单

## 后果

合同与用法见[扩展路径](../reference/扩展路径.md)；机制见 [0008](0008-组件扩展机制.md)。
