# 0012 API 网关的取舍

- 状态：已接受（2026-10-27）
- 关联 issue：#43

## 背景

新增网关后，身份传递、防直连、路由来源、Nginx 分工与限流依赖不可用时的行为需要定下。

## 决定

- **身份传递合同**：原样转发 `Authorization: Bearer <token>`。网关只做登录前置校验，后端继续按“原生会话＋SQL 许可＋当前授权”判定（[身份设计](../reference/身份权限.md#sql-与会话状态的生效合同)），撤权、改密、禁用立即生效的语义不变；不签发内部凭据
- **防止绕过网关直连后端**：Sa-Token Same-Token＋网络隔离：网关转发和服务间调用都携带 Same-Token，后端统一校验，缺失或不符即拒绝；后端仍不暴露主机端口
- **路由来源**：网关的 Nacos 配置集中维护路由；仓库维护种子，模板生成服务时向种子追加路由
- **Nginx 路由迁移**：Nginx 只做边缘：整个 `/api/` 转给网关，只负责请求体上限、`/healthz` 和 HTTPS（覆盖文件 `compose.https.yml`）；删除 `deploy/nginx/services/`，模板改为生成网关路由
- **限流依赖的 Redis 不可用**：限流放行，记录错误日志与指标并告警，不返回 429 或 503；理由见[限流](../reference/components/gateway.md#限流)

## 后果

合同与用法见[API 网关](../reference/components/gateway.md)。
