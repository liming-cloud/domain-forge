# 0029 工程北极星与度量口径

- 状态：已接受（2026-11-19）
- 关联 issue：[#137](https://github.com/liming-cloud/domain-forge/issues/137)
- 补充：[0002](0002-双北极星与反馈时间目标.md) 的指标口径

## 背景

2026-11-09 综合本仓库与 rag-pilot 定了一份工程北极星，两个仓库的度量口径要一致。0002 的口径与它有三处不同：一次通过率还要求评审轮次为 1；反馈时间只看单模块、本地完整门禁和 CI 墙钟，不看本地快速门禁；编译告警不是指标。

## 决定

- 工程北极星正文放在平台仓库 `docs/platform/工程北极星.md`，规则卡只写可执行条目，北极星页列出每条规范对应的卡。和现有卡重复的不新增卡，在原卡上补条文。
- 一次通过率改为“没打 `rework` 的已合并 PR ÷ 全部已合并 PR”，不再看评审轮次：PR 由同一账号开，“要求修改”的评审几乎不会出现。价值北极星中在全新副本里的 AI 一次通过，仍按 AI 交付验收（平台仓库 `docs/platform/AI交付验收.md`）逐次记录。
- “原则可执行率”改称“规则可执行率”，口径不变。目标：「工程优化」里程碑结束时 ≥ 40%，首版收尾时 ≥ 50%（人 2026-11-13 定）。
- 快速反馈增加本地快速门禁时长，由 `scripts/dev_metrics.py --fast-gate` 在本机实测；CI 完整门禁取 `mvn verify` 作业和整次运行的墙钟。T-13 的目标不变。
- 编译告警为 0 作为指标，由 C-18 的编译参数保证，报告核对该参数仍在。
- 日志消息格式采用 `event=snake_case 键=值`（人 2026-11-19 定），存量改写见 [#186](https://github.com/liming-cloud/domain-forge/issues/186)。

## 后果

- 卡片补写的条文：P-08（后台窄更新）、S-10（GET 不写库）、H-10 检查行补登记已有的自动检查、C-07（降级记 warn）、F-05（日志格式）、T-05（应用层快速测试）、T-09（上下文复用、不 sleep）、H-05（接口契约由机器校验）。
- 现状与条文不符的，由后续 issue 实施：测试中的 sleep [#185](https://github.com/liming-cloud/domain-forge/issues/185)、日志格式 [#186](https://github.com/liming-cloud/domain-forge/issues/186)、接口契约 [#187](https://github.com/liming-cloud/domain-forge/issues/187)。
- 历史 PR 没有统一打 `rework`，一次通过率的早期数值偏高。
