# 0013 跨服务调用的取舍

- 状态：已接受（2026-10-28）
- 关联 issue：无单独 issue，见路线图 P6

## 背景

服务之间的同步调用需要统一身份传递与无用户上下文的调用方式。

## 决定

- **用户令牌**：当前 HTTP 请求带有 `Authorization` 时，组件自动转发给所有 Feign 调用；被调方以同一用户身份认证授权，权限与数据范围由被调方判定
- **服务身份**：按 Sa-Token 官方用法，Same-Token 就是服务间调用的身份凭证：组件为每个调用写入当前值，被调方用 `SaServletFilter` 校验
- **没有用户上下文的调用（定时任务、消息消费）**：支持，但只能调用被调方的服务专用接口：位于 `/internal/**`、以 `@SaIgnore` 声明的接口。网关只路由 `/api/**`，外部到不了；`/api/**` 上的 `@SaIgnore` 仍是公开匿名
- **模板示例**：生成器 `--call-example <被调服务>`：在新服务中生成以当前用户身份读取被调服务便笺的示例；闭环验证用两个生成服务

## 后果
