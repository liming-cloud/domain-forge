# 0006 一个事务只修改一个聚合

- 状态：已接受（2026-11-05）
- 关联 issue：[#93](https://github.com/liming-cloud/domain-forge/issues/93)、[#106](https://github.com/liming-cloud/domain-forge/issues/106)、[#107](https://github.com/liming-cloud/domain-forge/issues/107)

## 背景

原有规则允许在同一本地事务中由公开合同协调多个聚合，与 Vernon 的聚合规则冲突；IAM 的 `AcceptInvitation` 在一个事务中消费邀请并建号。

## 决定

严格执行一个事务只修改一个聚合。已知违例 `AcceptInvitation` 通过重新建模邀请消除：邀请作为一次性凭据，由唯一约束防止重复使用。属于安全语义变更，具体设计在 [#106](https://github.com/liming-cloud/domain-forge/issues/106) 中确认。

## 后果

- 规则写入 [S-11](../rules/02-系统设计.md#s-11-一个事务只修改一个聚合)；自动检查[单聚合事务]（一个用例方法不得调用两个仓储的写方法）已由 [#107](https://github.com/liming-cloud/domain-forge/issues/107) 建立。
- 由 [#106](https://github.com/liming-cloud/domain-forge/issues/106) 修订：[身份权限](../reference/身份权限.md)中的 S02 邀请和注册、`RegistrationInvitation` 模型与生命周期；[P-09](../rules/05-持久化.md#p-09-并发约束由数据库保证) 的正例；[W-01](../workflow/01-开发流程.md#w-01-先写清目标和验收场景再设计) 正例中的“两者同一事务提交”。
