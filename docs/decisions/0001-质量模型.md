# 0001 质量模型

- 状态：已接受（2026-11-05）
- 关联 issue：[#93](https://github.com/liming-cloud/domain-forge/issues/93)、[#100](https://github.com/liming-cloud/domain-forge/issues/100)

## 背景

“高质量工程”需要一个公认的骨架，否则原则与检查各自为政，无法判断覆盖了哪些方面。

## 决定

以 ISO/IEC 25010:2023 的可维护性为骨架，补充可靠性中的容错：

| 维度 | 含义 | 在本仓库中的体现 |
|---|---|---|
| 模块性 | 修改一个组件，对其他组件的影响最小 | 高内聚、低耦合 |
| 可复用性 | 资产能用于多个系统 | 平台组件与服务模板被多个业务项目复用 |
| 可分析性 | 能评估变更的影响、诊断缺陷 | AI 编码工具和评审人能快速读懂代码；失败能诊断 |
| 可修改性 | 修改不引入缺陷、不降低质量 | 可扩展：经扩展点接入，不改写已有代码 |
| 可测试性 | 能有效建立测试准则并执行 | 反馈快且结果确定 |
| 容错 | 依赖故障时行为确定 | 统一的失败分类与协议结果 |

性能见[性能基线](../architecture/14-性能基线.md)，安全见[安全与访问控制](../rules/07-安全与访问控制.md)。

## 后果

[规则卡索引](../rules/00-索引.md)按这些维度组织原则与规则卡。每条判据要么由 `mvn verify` 自动检查，要么标“评审”并写清评审看什么；能够自动检查时，就从“评审”改为“自动”（适应度函数与系统一起演进）。
