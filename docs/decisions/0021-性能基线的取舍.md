# 0021 性能基线的取舍

- 状态：已接受（2026-11-03）
- 关联 issue：#112

## 背景

首版压测需要预先确定资源、场景、工具与执行方式。

## 决定

- **资源与部署形态**：单机 Docker Compose，即部署参考（`deploy/compose.yml` 与模板生成服务的覆盖文件）；整机限定 4 核 8G，各容器的 CPU 与内存配额写进复现说明
- **场景与数据量**：登录、带数据范围的查询、创建（同事务写 Outbox）、跨服务调用；数据量为 1 万个账号、10 万个示例聚合。文件上传不在本轮。压测对象为模板的订单示例（[#108](https://github.com/liming-cloud/domain-forge/issues/108) 完成后执行，见路线图（平台仓库 `docs/platform/路线图.md`））
- **工具与门槛**：k6。先跑一次取得基线，再由人确定门槛；参考初值为单接口 200 RPS 时 P95 < 200ms、错误率 < 0.1%
- **执行方式**：手动执行，不进 CI（CI 机器资源不稳定，结果不可比）；脚本、复现说明与每次结果提交到仓库

## 后果

合同与用法见性能基线（平台仓库 `docs/platform/性能基线.md`）。
