# ADR-0001：统一 IAM 与部署边界

- 状态：Proposed（待讨论）
- 日期：2026-09-19
- 决策负责人：用户（产品与架构职责）；整理：AI
- 需求：C02、C06、C10、C11；评审：R1 / Q01

## 背景

首批没有真实业务域，只有账号、组织与授权规则。单部门、多角色、超管统一授权存在共同的数据一致性需求，尚无独立团队、独立发布或规模压力要求拆开认证、账号和权限管理。

## 推荐决定

部署独立 Gateway 与一个 IAM 服务。IAM 内部管理身份、组织与授权模型；Gateway 属于技术入口，不被称为独立业务限界上下文。未来业务服务拥有自己的模型和数据，通过稳定授权协议消费 IAM。

服务模板的跨服务验收通过测试专用消费服务完成，不把示例业务系统列入产品运行拓扑。

## 备选与取舍

| 方案 | 优点 | 本轮不优先的原因 |
|---|---|---|
| 统一 IAM（推荐） | 单一规则所有者，授权变更可在一个数据边界完成 | IAM 可用性和扩容会影响授权链；需明确故障语义 |
| 认证、账号/组织、权限分别部署 | 可独立扩容与交付 | 当前无需求收益证据，引入身份禁用和权限变更的跨服务一致性 |
| 嵌入各业务服务的账号权限模块 | 初始接入路径短 | 规则和数据重复，不符合统一可升级权限基础的目标 |

## 后果与重评条件

IAM 数据只由 IAM 写入；下游不读 IAM 表，公共包不携带 IAM 聚合。出现独立身份提供者接入、不同团队/发布周期、实测容量瓶颈或语义冲突时重评，不以文件数增长作为拆分理由。
