# ADR-0004：以 IAM 在线判定保证首批授权语义清晰

- 状态：Proposed（待讨论）；日期：2026-09-19
- 决策负责人：用户；整理：AI；评审：R2 / Q04
- 需求：C05–C10；验证：T01–T09、P01–P07、F01–F04

## 背景与推荐

权限变更、账号禁用和部门变更需要明确生效边界。推荐 IAM 使用 Sa-Token 管理会话，Redis 会话只由 IAM 操作；其他服务通过稳定当前用户协议查询身份及权限，不共享 IAM 表或会话写权限。

授权规则从数据库按请求读取，只在本次请求内复用。变更提交后新开始的判定使用新状态；已通过判定的请求不强制中断。会话失效、credentialVersion、故障处理和超管跨域边界的规范内容见[安全模型](../design/03-iam-domain-security.md)，本 ADR 不复制细则。

## 备选与取舍

| 方案 | 优点 | 代价 |
|---|---|---|
| 在线判定（推荐） | 权威集中、生效语义简单，不分发可变权限缓存 | IAM 成为可用性依赖，网关与消费服务可能各一次调用，需要测量成本 |
| 各服务共享 Redis 并缓存角色权限 | 少一次远程判定，可利用 Sa-Token 分布式模式 | 各服务扩大存储信任面，权限失效及并发回填需要独立一致性设计 |
| Token 内嵌权限/离线判定 | 热路径依赖少 | 角色变更和撤销存在陈旧窗口，需要额外版本/撤销协议 |

## 后果与重评条件

IAM 或必需存储不可用时不放行。首版不把协议端口伪装为支持 Sa-Token 所有 API 的万能远程代理；仅公开真实需要的身份与操作授权能力。

若实测授权延迟、数据库成本或可用性不满足明确 SLO，再比较有版本的缓存或签名短期上下文，并重新确认撤销窗口与风险。不能在实现中自行添加容错放行。

## 尚需人工确认

Q04 同时确认：新判定立即生效而不追溯中断在途请求、会话期限与并发登录政策、超级管理员权限仅属于 IAM，以及组织/资源生命周期候选。未确认前不能把这些行为写成产品承诺。
