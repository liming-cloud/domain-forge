# ADR-0002：模板、组件与服务的复用和发布边界

- 状态：Accepted（2026-09-20，DESIGN-v0.1 / H02）
- 日期：2026-09-19
- 决策负责人：用户；整理：AI
- 需求：C01、C12、C13；评审：R1 / Q02

## 背景

用户需要模板加可升级组件。直接复制基础设施源码会造成升级分叉；把可部署 IAM 实现当通用库嵌入又会模糊数据和服务所有权。

## 决定

平台源码集中在一个私有仓库管理 BOM、已证明可复用的 starter、IAM 和 Gateway。首个研发版本发布时，维护一个独立轻量 GitHub Template 仓库，引用已发布 BOM/组件，并说明如何接入版本化 IAM/Gateway 服务。

平台仓库已创建为 `liming-cloud/domain-forge`，模板候选名称为 `domain-forge-template`；私有仓库套餐、模板与制品权限在研发准备中核实。2026-09-20 用户单独授权将现有设计文档提交到个人私有仓库，见[H01](../governance/review-register.md)；H01 当时未接受双仓库方案。之后 H02 已接受本 ADR 的设计；模板创建与制品发布仍在对应任务获得执行授权后开展。

分发设计采用 GitHub Packages（Maven）与 GHCR（镜像），实际消费权限和运行能力仍待验证。库、服务及模板的兼容组合记录为一份发布清单；初期协调版本发布，不意味着各产物必须永远共享生命周期。模板升级通过单独 PR 更新依赖与说明。

## 备选与取舍

| 方案 | 优点 | 代价 |
|---|---|---|
| 平台源码仓库 + 轻量模板仓库（已采用） | 消费方无需复制平台实现，升级边界清晰 | 两个仓库的版本清单和消费验证需要维护 |
| 全部源码作为一个 GitHub Template | 首次复制简单 | 新项目携带公共组件源码，难保持统一升级 |
| 一个源码仓库发布模板压缩包 | 仓库数少 | 缺少原生 GitHub Template 使用流程，需自定义分发说明 |

## 后果与重评条件

GitHub Maven 包拉取需要认证，跨私有仓库消费不能默认已有权限。应提供不含凭据的接入说明；发布凭据仅在受控发布路径使用。官方事实见[兼容矩阵](../design/04-technology-compatibility.md)。

模板不回写已有业务项目；已有项目更新 BOM、库和服务版本，并执行自身回归。若私有制品分发成本不符合使用环境，重评 Nexus 等仓库，不提前增加多种分发实现。

## 后续证据

验收 R01、R02、R03：独立构建、版本升级、模板差异处理。确认本 ADR 只确定产品分发设计，不授权远程创建、发布或购买套餐。
