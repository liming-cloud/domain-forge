# 阶段三身份权限切片

## 目标与确认

2026-10-22 用户确认修订后的完整整改方案 D01—D09、REV01—REV07、M1—M6 与 R-A01—R-A20，授权按顺序分步本地实施。shared 保持单模块、单包；先验证原生会话失败语义与 Redisson 多级缓存，未证明前保留旧安全机制。固定方案摘要与原文来源见 `.run-artifacts/scaffold-realignment-2026-10-22/authorization.json`；C1 替代设计另获本地验证批准，见同目录 c1-authorization.json。

允许方案内源码、现行文档、部署、测试及 M6 本地 CI 文件调整；只有 M6 覆盖映射闭合后才调整 CI。不扩展完整组织／RBAC／菜单业务、不写入人工验收通过。原 IAM 人工拒绝继续保留。

当前 M2 边界：验证账号行锁内串行签发、部分失败及未知结果；优先复用原生能力，不新增自研会话协议，安全条件闭合前保留 SQL 许可。本轮不修改 CI 或写入验收通过。用户随后明确要求“提交推送代码”，授权将当前 M1／M2 已实施内容作为研发快照提交并推送至 origin/main；这解除此前提交推送限制，不表示 M2 安全条件或完整适用门禁已通过。不主动触发额外远端运行，推送触发的既有 CI 按实际对象核对。

## 当前整改方案

现行设计见[总体架构](../architecture/01-总体架构.md)与[身份权限](../architecture/04-身份权限.md#最小整改方案)。当前顺序：M1 文档／版本 → M2 shared／原生组合先证 → M3 IAM／事务／HTTP／雪花 ID → M4 缓存完整能力 → M5 公开部署与性能 → M6 门禁收敛与语义核对。步骤是依赖顺序，不增加逐文件审批。关键实证失败只暂停依赖该结论的变更；新协议或安全放宽需另行决定。

本轮实际结果统一维护于 `.run-artifacts/scaffold-realignment-2026-10-22/02-本地实施与验收清单.md`。B0—B1 和 MIN 旧证据分别保留于 `.run-artifacts/iam-b0-b1-final/`、`.run-artifacts/minimal-remediation-2026-10-21/`；旧性能、真实 CI 及失败报告只适用于原输入，不能移植为新输入通过。原生漏洞告警、NVD 更新失败和历史证据缺口不因整改删除。

| R-A08 审计与事务 | 管理状态与审计同事务，SQL 仍在 XML／合法链式方法中 | 正常写入、审计故障回滚、提交不确定不伪报成功；删除的补录／回执接口不继续暴露 |
| R-A09 ID | 业务实体及引用统一雪花 Long／BIGINT／JSON 字符串 | 真实插入及关联查询、审计 ID、游标分页、大于 JS 安全整数范围的往返、双 worker 并发、非法配置及框架时钟行为 |
| R-A10 数据与恢复 | 新库基线可用，旧库不被修改或清空 | 迁移检查；正常重启业务数据保留；隔离恢复业务备份后空会话登录；无自动 clean／repair；原数据库不参与测试清理 |
| R-A11 质量与行为覆盖 | 四层 DDD、查询短路径、源代码质量及有效安全断言保持 | 合法／违规依赖、SQL 注解反例、敏感日志、未知路由与安全错误；每个旧必要检查映射到保留／替代／撤回理由 |
| R-A12 性能 | 正常路径仍满足原适用负载目标，并记录实际调用成本 | 两 IAM 各 2vCPU／1GiB；300 秒登录合计 2 次／秒、经业务服务授权 20 次／秒；正常 p95 登录≤1秒、授权≤300ms且无非预期错误；突发及恢复另测，不以减负载提速 |
| R-A13 本地／CI | 三类责任使用同入口、当前输入制品，无 NVD 对功能集成的串行阻断 | 本地执行及 CI 静态验证；故障退出、漏选、缺报告和旧制品反例；比较实际耗时／构建扫描次数；远端 CI 未授权则明确未执行 |
| R-A14 风险与验收 | 不冒充无漏洞、部署完成或人工验收 | 原生漏洞提示、NVD 失败、历史缺口与旧 IAM 拒绝保留；delivery-evidence 对未完成项不放行；用户针对新精确候选另作人工验收 |
| R-A15 事务 | 无自建统一事务状态机；本地事务绑定明确，后续分布式接入不被全局唯一性误拦截 | REQUIRED 参与、全异常回滚、真实代理与短事务；存在无关第二管理器仍可使用明确绑定，错误资源不得静默回落；Redis 不被误当 SQL 原子参与者；分布式方案只验设计不冒充已实现 |
| R-A16 缓存资源 | 基础缓存 API 可复用，access-control 直接依赖 cache，统一 Redisson 资源 | 真实 Redis 读写／TTL／按键失效、类型化序列化与故障；写事务回滚无填充、提交后失效；回调失败不伪报 SQL 回滚，晚回填按明确合同验证；普通缓存 API 不触及安全键；缓存、Lua、锁、官方 SaTokenDaoForRedisson 使用同一个受管客户端，无 Lettuce 或独立会话客户端；原生会话、注销、续期及登录保护回归 |
| R-A17 使用规范 | shared 只有一个 Maven JAR 模块和 org.domainforge.shared 包；业务使用组件公开接口 | artifactId 与目录同为 shared，无下层 POM 或旧坐标兼容壳；POM／BOM／模板引用一致；依赖图无环，shared 无 Starter／HTTP 执行行为，领域标识保持纯 Java，领域不误用传输对象；应用越过接口访问 internal／SDK 的反例失败；正确接口注入、原生事务声明、服务自有 Feign 及查询短路径正例通过 |
| R-A18 多级缓存 | 默认关闭、按 region 可选开启，TTL／失效及故障语义明确 | 使用社区版固定依赖验证 L1 命中减少真实 Redis 读取、有限容量、近到期填充、跨实例更新／删除、并发填充、断连重连与混合开关；核对各层驻留与组合窗口，关闭 L1／L2 的当前事实读取正确，认证／锁不进入 L1；无 PRO 或第二客户端的隐含依赖 |
| R-A19 Lua与锁 | 使用原生 RScript／RLock，小接口可供服务基础设施复用 | Lua 成功与原子并发、非法参数、运行错误已有写入不伪称回滚；锁竞争／有限等待、异常解锁、watchdog／固定租约、持有者终止和后续恢复；不以锁通过代替 SQL／Redis 跨资源一致性 |
| R-A20 回源防护 | 穿透、雪崩、击穿有明确策略和实际负载证据 | 不存在键重复／随机请求、空值后创建、异常不缓存、批量到期抖动、Redis 停机、热点跨实例并发、loader 异常／中断及后续重试；观测真实回源次数／峰值、有限等待／拒绝与合并记录回收，不只断言 Redis 成功；不同查询维度／值类型不混用；可选分布式锁关闭／开启均验证 |

确认事项为 D01—D09、REV01—REV07 的处置、M1—M6 与 R-A01—R-A20。其中关键替代是：完整源码复用、入口 TLS、原生共享会话、原生本地事务与同事务审计、新库雪花 ID、Redisson 缓存／可选多级缓存／Lua／锁及回源防护、shared／能力接口边界，以及基于保留行为重新组织检查。分布式方案本轮仅定边界、不引入协调器；多级缓存是可关闭但仍须完成启用验证的交付能力。确认后按 M1—M6 本地实施，包含末步必要 CI 文件收敛；当前研发快照提交推送已获授权，业务扩围、额外远端运行和人工验收仍需各自明确授权或结论。
