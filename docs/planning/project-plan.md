# 项目执行规划

文档 ID：PLAN-PROJECT。类型：规划。修订：v0.1。状态：Draft / 待评审。负责人：用户；规划整理：AI。日期：2026-09-20。输入：已接受的 DESIGN-v0.1（[H02](../governance/review-register.md)）以及本轮仓库内文档治理要求。本文不构成编码、远程写入或发布授权。

## 1. 项目终点与当前前沿

首个可复用版本要使消费方按说明创建独立服务，使用发布的组件并接入 IAM/Gateway；同时获得继续研发所需的文档与规则，升级时能保留业务定制。产品边界维护在[项目定位](../design/01-project-scope.md)，此处仅规划推进方式。

当前已完成：设计材料编写与文档静态检查、个人私有 GitHub 仓库提交、现有设计内容人工接受。当前正在完成：文档控制面和整体项目规划。应用、构建工程、兼容试验和产品发行都未开始。

下一项人工决策是接受或调整本轮治理方案。AI 可以继续核对文档映射与任务输入，不需要等待用户代查事实。设计接受不使尚缺字段或依赖验证自动完成；详细设计随最近将实施的切片推进，不预先编造后续能力的完整 API。

| 阶段 | 阶段交付组合 | 执行与确认 |

## 4. 任务输入、输出与交接

任何可执行任务必须有：目标与非目标、负责人、输入基线/规则 ID、允许修改范围、前置条件、输出位置、验收方式、实际证据和剩余事项。填写方式沿用[协作流程](../governance/ai-development-workflow.md)，新文档治理字段见 [GOV-DOC](../governance/document-control-plane.md)。

AI 开始任务时核对当前批准版本与任务分支差异；结束时更新任务结果、变更规范、验证证据和下一阻断点。交接只链接事实源，不再复制全部领域模型或生成一份新的“最终方案”。

变更管理的具体流程只在 GOV-DOC 维护。任务若碰到已接受设计之外的产品选择，提交具备影响分析的方案供用户决定；可独立执行的事实调查继续进行。

## 5. 各切片的文档责任

| 切片 | 必需输入文档 | 随工作更新的长期文档 | 过程证据与交付增量 |
|---|---|---|---|

| E01 | ADR-0002/0003、PLAN-03、工程与迁移设计 | 结构/依赖约束、配置说明、研发指南、实际可执行检查映射 | 构建/架构检查证据；最小工程和规则 |
| E02 | IAM 身份生命周期、PLAN-02 契约、T01–T09 | 登录/退出/禁用/撤销的实际使用文档；准确配置与安全限制 | 真实会话与并发验证；身份能力 |
| E03 | 角色/组织规则、该切片字段契约、P/O 场景 | 授权管理及组织说明、权限目录与审计契约 | 授权、组织、最后超管等证据；管理能力 |
| E04 | 数据范围模型、ADR-0006、D01–D15 | 资源接入规范、SQL 支持清单和写入约束 | 真实 MySQL 证据；数据权限能力 |
| E05 | 导航契约、模板消费边界、N 场景 | 菜单/API/接入说明、独立消费指南 | 端到端消费证据；首版使用旅程 |

API 行为规范与最终 OpenAPI 的字段约束应建立单一字段来源和差异检查方案，在 PLAN-02/PLAN-03 明确；不预先维护两份人工可自由修改的同内容 schema。Markdown 保留原因、业务语义和无法由 schema 表达的约束。
