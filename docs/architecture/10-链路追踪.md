# 链路追踪

服务统一依赖 `domain-forge-tracing` 组件：一次请求从网关开始形成一条链路，经同步调用、Outbox 消息和消费方延续；定时任务的每次执行各自是一条新链路。日志与响应头带同一 traceId，排查时按它关联；链路数据是否导出、导出到哪里由业务项目配置。规则卡见[故障与可观测性 F-05](../standards/09-故障与可观测性.md#f-05-结构化日志能串联一次调用)。

## 已确认的决定（2026-10-29）

| 问题 | 决定 |
|---|---|
| 框架 | Micrometer Tracing＋OpenTelemetry 桥接（Spring Boot 自带的追踪自动配置），传播格式只用 W3C `traceparent` |
| 与请求标识的关系 | traceId 取代原来的 `X-Request-Id`：删除 web-support 的请求标识过滤器，响应头改为 `X-Trace-Id`，日志上下文改用 Boot 的 `traceId`／`spanId` |
| 导出 | 默认不导出；配置 OTLP 地址后启用。部署参考不内置采集端，采集、存储与查询由业务项目提供；验证脚本临时加入 Jaeger |
| 采样 | 新链路默认 10%，经 Nacos 动态调整；带上游采样决定的请求沿用上游决定。导出失败不影响业务 |

## 链路的起止

| 位置 | 行为 |
|---|---|
| Nginx | 删除客户端带来的 `traceparent`、`tracestate`、`baggage`：链路从网关开始，外部不能指定 traceId 或强制采样 |
| 网关 | Spring Cloud Gateway 的观测为每个请求开启根 span 并向后端发送 `traceparent`；访问日志 `gateway_access trace_id=… method=… path=… status=… route=… millis=…`；响应头 `X-Trace-Id` 只保留网关写入的一个值（后端响应中的同名头在复制前删除） |
| 后端 HTTP 入口 | Spring MVC 观测沿用传入的 `traceparent`（本地开发不经网关时自行开启新链路）；响应头 `X-Trace-Id` |
| 同步调用 | OpenFeign 的 Micrometer 观测（`feign-micrometer`，由[跨服务调用组件](07-跨服务调用.md)带入）为每次调用开启客户端 span 并发送 `traceparent` |
| Outbox 消息 | 发布时把当前链路的 `traceparent` 写入 Outbox 行（列 `trace_parent`）；中继发送时以它为父开启 `send <主题>` span，并写入消息属性 `traceparent`；消费方以消息属性为父开启 `consume <主题>` span（标签 `messaging.consumer.group`），处理者内的日志与后续调用都在这条链路中。见[消息与 Outbox](08-消息与Outbox.md) |
| 定时任务 | 每次执行开启一条新链路的根 span `task <任务名>`（标签 `task.instance` 为 PowerJob 实例 ID），失败时记录异常。见[定时任务](09-定时任务.md) |

没有当前 span 的后台线程（例如 Outbox 中继轮询本身）不开启链路，日志中的 traceId 为空。

## 日志与响应头

- Boot 在有追踪组件时把日志关联字段默认设为 `[<traceId>-<spanId>]`，无链路时为空白；服务可用 `logging.pattern.correlation` 覆盖。
- `X-Trace-Id` 只用于关联日志与链路，不作为幂等键或安全依据；未采样的请求同样有 traceId，日志与响应头照常输出。
- 网关是响应式应用，组件默认开启 `spring.reactor.context-propagation: auto`，使网关日志也带 traceId。

## 采样

| 项 | 说明 |
|---|---|
| 新链路采样率 | 动态配置组 `domainforge.tracing`，`sampling-probability` 默认 `0.1`，取值 0—1；在 Nacos 中修改整组校验后生效，非法值保留原值（见[配置中心](05-配置中心.md)） |
| 采样器 | `parentBased(按当前采样率的 traceIdRatioBased)`：带 `traceparent` 的请求与消息沿用上游决定，因此实际上由网关（或任务、本地直连的入口）决定整条链路是否采样 |

## 导出

| 项 | 说明 |
|---|---|
| 启用 | 设置 `management.opentelemetry.tracing.export.otlp.endpoint`（环境变量 `MANAGEMENT_OPENTELEMETRY_TRACING_EXPORT_OTLP_ENDPOINT`，如 `http://collector:4318/v1/traces`，OTLP/HTTP）后才创建导出器；未设置时不导出、不连接任何地址 |
| 失败 | 批量异步导出，采集端不可用时丢弃该批链路并记录框架日志，不阻塞、不影响请求与消息处理 |
| 内容 | 框架观测的默认标签（方法、路由模板、状态、主题、任务名等）；不记录请求体、请求参数、令牌与请求头（[F-06](../standards/09-故障与可观测性.md#f-06-不记录敏感内容)） |

## 组件

| 部分 | 行为 |
|---|---|
| 依赖 | `domain-forge-tracing` 带入 Boot 的追踪自动配置、OpenTelemetry 桥接与 OTLP 导出器；网关、IAM 与模板生成的服务都依赖它 |
| 默认值 | `META-INF/domain-forge/tracing-defaults.yml` 以最低优先级加入：W3C 传播、采样率、Reactor 上下文传播；服务配置可覆盖 |
| 响应式取 traceId | `ReactiveTraces.traceId(exchange)` 从请求的观测上下文读取（网关访问日志使用） |
| 未依赖组件时 | 消息与任务组件使用 `Tracer.NOOP`，行为不变、Outbox 行的 `trace_parent` 为空 |

## 验证

| 场景 | 证据 |
|---|---|
| 采样率随动态配置变化、非法值拒绝 | `DynamicRatioSamplerTest` |
| 响应头 traceId 与日志一致；沿用传入的 `traceparent` | `TracingIntegrationTest`（真实 Boot＋Spring MVC） |
| 网关响应只有一个 `X-Trace-Id`，后端收到同一链路的 `traceparent` | `GatewayIT` |
| 跨服务调用的对方收到本服务链路的 `traceparent` | 模板 `NoteDigestIT` |
| 消费方与发布方在同一链路 | `MessagingIT` |
| 每次任务执行各有 traceId | `SchedulingIT` |
| 部署：入口丢弃客户端的追踪头，响应 traceId 见于网关访问日志 | `scripts/verify_deploy.sh` |
| 完整链路：一条链路贯穿 gateway、note-service、iam 与 board-service（消息消费） | `scripts/verify_closure.sh`，经 `scripts/compose.tracing-verify.yml` 临时加入 Jaeger 并全量采样 |
