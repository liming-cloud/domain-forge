# 跨服务调用

服务之间的同步 HTTP 调用统一经 `domain-forge-service-call` 组件（OpenFeign）：身份与链路上下文传递、超时、不重试与失败分类在组件中一次实现，服务只声明 Feign 客户端并翻译成自己的结果。身份传递沿用[API 网关](06-API网关.md)定下的合同；规则卡见[安全与访问控制 A-14](../standards/07-安全与访问控制.md#a-14-服务间调用的身份)与[接口与错误 H-09](../standards/06-接口与错误.md#h-09-服务间调用经跨服务调用组件)。选型与验收见[路线图](../product/02-路线图.md#p6-实施计划)。

## 已确认的决定（2026-10-28）

| 问题 | 决定 |
|---|---|
| 用户令牌 | 当前 HTTP 请求带有 `Authorization` 时，组件自动转发给所有 Feign 调用；被调方以同一用户身份认证授权，权限与数据范围由被调方判定 |
| 服务身份 | 按 Sa-Token 官方用法，Same-Token 就是服务间调用的身份凭证：组件为每个调用写入当前值，被调方用 `SaServletFilter` 校验 |
| 没有用户上下文的调用（定时任务、消息消费） | 支持，但只能调用被调方的服务专用接口：位于 `/internal/**`、以 `@SaIgnore` 声明的接口。网关只路由 `/api/**`，外部到不了；`/api/**` 上的 `@SaIgnore` 仍是公开匿名 |
| 模板示例 | 生成器 `--call-example <被调服务>`：在新服务中生成以当前用户身份读取被调服务便笺的示例；闭环验证用两个生成服务 |

## Same-Token 的用法（对照 Sa-Token 官方文档）

[内部服务外网隔离](https://sa-token.cc/doc.html#/micro/same-token)一文给出三处做法，平台按原样采用：

| 环节 | 官方做法 | 平台实现 |
|---|---|---|
| 网关转发 | 全局过滤器为请求加 `SA-SAME-TOKEN: SaSameUtil.getToken()` | 网关 `SameTokenRelayFilter`（先删除客户端自带的同名头） |
| 子服务校验 | 注册 `SaServletFilter`，`setAuth` 中 `SaSameUtil.checkCurrentRequestToken()` | access-control 组件注册该过滤器（顺序 -100，在 Sa-Token 上下文过滤器之后），`setError` 返回平台外壳：不符 401，存储不可用 503 |
| 服务间调用 | Feign `RequestInterceptor` 加 Same-Token；需要被调方有会话时同时加用户令牌 | 本组件的 `IdentityPropagation` |
| 刷新 | 专门的定时任务按固定间隔 `refreshToken()`，间隔低于有效期；集群中不要多处重复刷新 | 网关每 30 分钟（`domainforge.gateway.same-token-refresh-interval`）在分布式锁内刷新，当前值未满一个间隔则跳过 |

刷新时旧值作为“上一个值”保留到下次刷新，转发途中遇到刷新的请求仍能通过。

## 组件合同

| 方面 | 行为 |
|---|---|
| 请求头 | `SA-SAME-TOKEN` 每次读取当前值（读取失败不发出请求，报 `UNAVAILABLE`）；`Authorization` 取自当前请求，客户端方法已显式声明时不覆盖，没有请求上下文时不带；`traceparent` 由 OpenFeign 的 Micrometer 观测（`feign-micrometer`）发送，见[链路追踪](10-链路追踪.md) |
| 超时 | 连接 1 秒、读取 2 秒，不跟随重定向；个别客户端在 `spring.cloud.openfeign.client.config.<contextId>` 覆盖 |
| 实例列表 | 关闭负载均衡层的实例缓存，直接取 Nacos 发现客户端订阅的列表，被调服务重建后不再使用旧地址 |
| 重试 | Feign 与负载均衡层都不重试；是否重试由调用方按接口的幂等合同决定（[F-03](../standards/09-故障与可观测性.md#f-03-一条调用链只有一处负责重试)） |
| 失败 | 统一抛出 `ServiceCallException`，分类见下表；消息为固定文本，不带对方的提示、地址或令牌 |
| 外壳 | `ServiceCalls.data(response)`：只有 `SUCCESS` 返回数据，其他代码为对方的业务拒绝 |

| 分类 | 来源 | 含义 |
|---|---|---|
| `UNAUTHENTICATED` | 401 | 对方判定未认证（用户令牌失效，或 Same-Token 不符） |
| `FORBIDDEN` | 403 | 对方判定无权限 |
| `REJECTED` | 其他 4xx；200 外壳中的非 `SUCCESS` 代码 | 对方的拒绝，`code()` 为对方代码 |
| `UNAVAILABLE` | 连接失败、无可用实例、5xx（504 除外）、响应缺失 | 请求确定没有被处理 |
| `UNKNOWN` | 读取超时、连接中断、504 | 请求已发出，远端可能已经执行（[F-02](../standards/09-故障与可观测性.md#f-02-超时不代表没有执行)） |

传输层异常由组件包装底层客户端（Feign `Capability`）直接翻译，不经 Feign 的可重试异常；非 2xx 响应由 `ErrorDecoder` 翻译，只读取响应体前 4 KiB 提取代码。

## 服务中的写法

```
application/port/<对方>/...        端口：技术无关的读取或命令，失败以本服务的语义报告
infrastructure/acl/<对方>/...      Feign 客户端（只声明路径与参数）＋ 端口实现（ServiceCalls.data 与失败翻译）
```

- 以当前用户身份调用时，调用方入口至少要求登录；能读到什么由被调方按同一用户的权限与范围决定，调用方不放宽。
- 对方的 401、403 一般保持语义；`UNAVAILABLE` 与 `UNKNOWN` 对读取都可按依赖不可用（503）处理，对写入不能报告成功或失败，按[S-15](../standards/02-系统设计.md#s-15-结果未知不能当成功)核对结果。
- 跨服务调用不在本地事务回滚范围内（[S-12](../standards/02-系统设计.md#s-12-跨资源跨服务没有原子性)）；需要可靠的跨服务副作用时用消息与 Outbox（P6-5）。
- 服务专用接口放在 `/internal/**` 并以 `@SaIgnore` 声明；它没有用户身份，不能依赖当前用户，也不能接受调用方提交的账号或权限字段作为授权依据。

## 验证

| 场景 | 方式 |
|---|---|
| 身份传递、显式或缺失用户令牌、响应分类、连接被拒与超时不重试、无实例 | `ServiceCallIntegrationTest`（真实 Boot＋OpenFeign＋本地 HTTP 替身） |
| 子服务 Same-Token 校验、服务专用接口只凭 Same-Token 调用、部署环境不能关闭 | access-control `SameTokenFilterTest` |
| 生成的调用方：令牌、Same-Token 到达对方，对方收到本服务链路的 `traceparent`；对方 401／403 保持、不可用与超时为 503 | 模板 `NoteDigestIT`（`scripts/verify_template.sh` 生成两个服务） |
| 两个生成服务的真实部署：同一用户身份读取对方便笺并受其范围限制、对方无权限 403 原样到达、对方停机 503 并在恢复后正常 | `scripts/verify_closure.sh` |
