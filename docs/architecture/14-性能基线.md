# 性能基线

首版按预先确定的资源、场景、数据与门槛做一次真实压测，结果与复现说明进入仓库；不替代业务项目自己的性能验收。产品要求见[性能验收边界](../product/01-产品定义.md#性能验收边界)，规则卡见[测试与验证 T-10](../standards/10-测试与验证.md#t-10-性能结论绑定条件)，跟踪见 [#47](https://github.com/liming-cloud/domain-forge/issues/47)。

## 已确认的决定（2026-11-03）

| 问题 | 决定 |
|---|---|
| 资源与部署形态 | 单机 Docker Compose，即部署参考（`deploy/compose.yml` 与模板生成服务的覆盖文件）；整机限定 4 核 8G，各容器的 CPU 与内存配额写进复现说明 |
| 场景与数据量 | 登录、带数据范围的查询、创建（同事务写 Outbox）、跨服务调用；数据量为 1 万个账号、10 万个示例聚合。文件上传不在本轮。压测对象为模板的订单示例（[#80](https://github.com/liming-cloud/domain-forge/issues/80) 完成后执行，见[路线图](../product/02-路线图.md#收敛2026-11-03-决定)） |
| 工具与门槛 | k6。先跑一次取得基线，再由人确定门槛；参考初值为单接口 200 RPS 时 P95 < 200ms、错误率 < 0.1% |
| 执行方式 | 手动执行，不进 CI（CI 机器资源不稳定，结果不可比）；脚本、复现说明与每次结果提交到仓库 |
