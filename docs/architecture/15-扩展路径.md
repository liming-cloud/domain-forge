# 扩展路径

每类能力提供真实可用的默认实现与经过验证的扩展路径：业务经公开配置或合同接入扩展，并回归默认实现。产品要求见[实现支持与扩展范围](../product/01-产品定义.md#实现支持与扩展范围)，跟踪见 [#45](https://github.com/liming-cloud/domain-forge/issues/45)。

## 已确认的决定（2026-11-03，同日修订）

| 问题 | 决定 |
|---|---|
| 是否需要正式 SPI | 需要。可替换的能力提供方以正式 SPI 定义：组件公开提供方接口，平台现有实现作为其中一个提供方并保持默认，业务项目可以实现并接入新的提供方，组件不需要修改。机制与适用范围在切片中设计（范围见 #45 的未决问题） |
| 配置中心 | 默认且只用 Nacos，不列为扩展路径 |
| 链路导出 | 不列为扩展路径（OTLP 导出保持为可选配置） |
| 清单由谁确认 | 下表由实现方起草，人在 #45 中确认后作为首版验收清单 |

## 清单（草稿，待 #45 确认）

| 能力 | 默认实现 | 扩展路径（公开配置或合同） | 现有验证 |
|---|---|---|---|
| 文件存储 | 本地目录 | 配置切换为 S3 兼容存储，同一 `FileStore` 合同；待 SPI：存储后端作为提供方接入 | `FileStorageIT`（本地与 S3 两种实现通过同一合同） |
| 缓存 | 只用 Redis | 配置开启 L1 本地缓存（Caffeine＋Redis 失效通知） | `NativeCachingIT`、`LocalCachingIT` |
| 关系持久化 | 服务自己的库 | 配置附加数据源（`@AdditionalMapper`，各自事务） | `AdditionalDataSourceIT`、`scripts/verify_closure.sh`（归档库） |
| 业务错误 | 平台错误外壳 | 实现 `BusinessRejectionMapping` 把业务异常映射为业务拒绝 | `ResponseContractTest`、模板 `NoteRejectionMapping` |
| 异步消息 | RocketMQ＋Outbox | 实现 `EventHandler` 消费事件、经 `EventPublisher` 发布 | `MessagingIT` |
| 定时任务 | PowerJob | 实现 `ScheduledTask` 登记任务，周期在控制台调整 | `SchedulingIT` |
| 网关路由与限流 | 种子路由 | 在 Nacos 的网关配置中增加路由与接口限流规则，动态生效 | `GatewayIT` |
| 短信 | 阿里云 SendSms | 待 SPI：服务商作为提供方接入（见上方决定） | 现无（默认实现不可替换） |

验收时逐项核对“经扩展路径接入”与“回归默认实现”两侧都有在 CI 中执行的验证；缺一侧的项转为切片补齐。
