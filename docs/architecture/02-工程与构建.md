# 工程与构建

## 技术基线

| 项 | 版本 |
|---|---|
| JDK | 21（编译目标 `release 21`，更高版本 JDK 可用于构建） |
| Maven | 3.9.16，经 `platform/mvnw`（Wrapper 3.3.4）获取，校验分发摘要 |
| Spring Boot | 4.0.8（内部 parent 导入其 BOM，不继承 Boot parent） |
| Spring Cloud / Spring Cloud Alibaba | 2025.1.3 / 2025.1.0.0 |
| 持久化 | PostgreSQL 18.4、MyBatis-Plus 3.5.17、Flyway |
| 缓存与会话 | Redis 8.8.1、Redisson 4.8.0、Sa-Token 1.46.0 |

选型原则和新增依赖的要求见[技术与构建规范](../standards/03-技术与构建.md)。

## Maven 结构

`platform/pom.xml` 是内部 parent 和聚合入口：管理 JDK、依赖版本（Boot、Cloud、Alibaba BOM）和构建插件。各级聚合（`framework`、`services`、`verification`）只列直接子模块，模块目录名等于 artifactId。只有可运行服务启用 Boot `repackage`。

`domain-forge-build-rules` 例外：它不继承 platform parent（parent 要依赖它，继承会形成循环），自行导入 Boot BOM，版本与 parent 保持一致。

`domain-forge-bom` 只管理平台组件版本，不引入依赖。服务按需显式声明组件，代码直接用到的依赖都要显式声明。

## 质量门禁

`mvn verify` 就是完整门禁，本地与 CI 相同。

| 检查 | 工具 | 阶段 | 配置位置 | 失败表现 |
|---|---|---|---|---|
| 架构规则：职责包归属、依赖方向、技术边界、internal 访问、跨上下文、SQL 注解与原始 SQL 拼接 | ArchUnit（`ModuleArchitectureTest`） | test | `domain-forge-build-rules/src/main/java` | 测试失败，逐条列出违规类与目标 |
| 单元测试 | JUnit 5 / surefire（`*Test`） | test | 各模块 | 测试失败 |
| 集成测试 | failsafe（`*IT`），依赖由 docker-maven-plugin 启动 | integration-test | parent `pluginManagement` | 测试失败 |
| 格式 | Spotless + google-java-format 1.28.0 | verify | parent | `spotless:check` 失败，用 `spotless:apply` 修正 |
| 类型说明、复杂度、Java 中的 SQL 文本 | Checkstyle 14.3.0 | verify | `domain-forge-build-rules/src/main/resources/checkstyle/` | 列出文件与行号 |
| 直接使用的依赖须显式声明 | `dependency:analyze-only` | verify | parent | 列出未声明的依赖 |

架构规则通过 parent 中的 `architecture-rules` profile 自动作用于所有含 `src/main/java` 的模块：profile 给模块加上规则 JAR 的测试依赖，并让 surefire 扫描其中的 `ModuleArchitectureTest`。新模块不需要任何额外配置。

规则的正反例在 `domain-forge-build-rules/src/test/java`。修改规则时必须同时补充正例和反例。

`platform/.mvn/jvm.config` 为 google-java-format 开放 `jdk.compiler` 内部包（JDK 16 及以上在 Maven 进程内运行格式检查需要），不要删除。

## 集成测试

集成测试需要 Docker。docker-maven-plugin 在 `pre-integration-test` 阶段启动 PostgreSQL 和 Redis 容器（镜像与 `deploy/compose.yml` 相同，固定摘要），映射到随机回环端口，并通过环境变量传给测试：

| 变量 | 含义 |
|---|---|
| `POSTGRES_PORT`、`POSTGRES_PASSWORD` | 数据库 `domainforge`，用户 `domainforge` |
| `REDIS_PORT`、`REDIS_PASSWORD`、`REDIS_CONTAINER` | Redis 端口、密码，以及供 `docker exec` 使用的容器名 |
| `IAM_DB_*`、`IAM_REDIS_*`、`IAM_FINGERPRINT_KEY` | IAM 应用配置所需的同一组依赖 |

需要容器的模块在自己的 POM 中声明 docker-maven-plugin，并用 `<filter>` 选择 `postgres`、`redis` 或两者。容器在 `post-integration-test` 阶段删除。

本机没有 Docker 时使用 `-DskipITs -Ddocker.skip=true`，集成测试由 CI 执行。

## CI

`.github/workflows/ci.yml` 在 PR 和推送 `main` 时运行两个作业：

- `verify`：`platform/mvnw -f platform/pom.xml verify`，失败时上传测试与 Checkstyle 报告。
- `docs`：`python3 scripts/check_doc_links.py`，检查 Markdown 相对链接与锚点。

依赖更新与漏洞提示由 Dependabot（`.github/dependabot.yml`）每周以 PR 形式提出，不阻断构建。
