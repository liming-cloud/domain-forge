# 总体架构

本页描述目标架构与已定设计原则。实施状态和阶段计划见[路线图](../product/02-路线图.md)，构建与质量门禁见[工程与构建](02-工程与构建.md)。

## 仓库分区与管理边界

以下为目标布局；尚未交付的能力不提前创建空模块。

```text
platform/
  pom.xml、mvnw、.mvn/         # 内部 parent、BOM 及聚合入口
  domain-forge-build-rules/    # 统一架构规则与 Checkstyle 配置
  shared/                     # 单个 JAR，org.domainforge.shared 一个包
  domain-forge-bom/            # 只管理依赖版本
  framework/
    domain-forge-web-support/
    domain-forge-persistence/
    domain-forge-cache/
    domain-forge-access-control/
    domain-forge-config/
    domain-forge-service-call/
    domain-forge-messaging/
    domain-forge-scheduling/
    domain-forge-tracing/
    domain-forge-file-storage/
    domain-forge-notification/
    domain-forge-idempotency/
  services/iam/               # 四层业务服务
  services/gateway/           # API 网关（只有 bootstrap 与 infrastructure）
  templates/ddd-service/      # 生成一个本系统业务服务
  verification/              # 必要跨模块／部署／性能验证
deploy/                      # Compose、Nginx、Nacos 种子、镜像与环境说明
scripts/                     # 仓库辅助脚本
docs/                        # 当前有效结论
```

### 命名与构建边界

保留 platform 名称。模块目录严格等于 artifactId，内部聚合只列直接子模块，Java 源目录不另建 POM。shared 不再下设 Maven 模块或预建子包；仅放已有领域标识与公共传输对象，不放账号实体、配置或客户端。源码合并时同步引用，不留旧坐标／旧包转发壳。

### Maven 层级组织

platform 管 JDK、Boot BOM 与构建插件；framework／services／verification 聚合各自直接子模块。内部模块继承直接父级；只有实际运行服务启用 Boot repackage。BOM 只管版本，不注入全部 Starter。组件直接使用到的 API 显式声明依赖，不能隐藏在传递依赖中。默认从完整源码构建，不要求外部 parent 组合或私有仓库先发布。

## 产品交付单元与依赖

### 能力清单及交付形态

首版完整能力清单仍见[产品定义](../product/01-产品定义.md#首版通用能力清单)。IAM 是业务服务，组织、角色、菜单和数据范围归 IAM。

| 单元 | 使用方式与责任 |
|---|---|
| shared | 直接依赖纯共享类型；领域只用三个纯 Java 标识，传输类型不进入领域 |
| web-support | HTTP 入口调用公开响应／错误适配；ResponseEntity 工厂留在本组件 |
| persistence | 业务仓储／查询接口由服务定义，基础设施复用 MyBatis-Plus／XML／Flyway；本地事务使用 Spring 原生入口 |
| cache | Redisson 基础缓存、可选多级缓存、Lua、锁；小接口、不拥有业务一致性规则；具体合同见下节 |
| access-control | 普通组件；原生 Sa-Token 会话／权限执行、默认拒绝及安全错误、后端入口 Same-Token 校验（见[API 网关](06-API网关.md#same-token)），直接依赖 cache |
| IAM／调用服务 | IAM 提供本地权限 SPI；调用服务在自身 infrastructure 定义 Feign＋Nacos，不再保留 iam-client 包装模块 |
| scheduling | 普通组件；定时任务登记与分派，调度由 PowerJob 服务端负责，见[定时任务](09-定时任务.md) |
| tracing | 普通组件；Micrometer Tracing＋OpenTelemetry 的默认值、动态采样率与 `X-Trace-Id` 响应头，见[链路追踪](10-链路追踪.md) |
| messaging | 普通组件；同事务 Outbox、中继、消费去重与死信告警，传输为 RocketMQ 5，见[消息与 Outbox](08-消息与Outbox.md) |
| service-call | 普通组件；所有 Feign 调用共用的身份与链路上下文传递、超时、不重试、失败分类，见[跨服务调用](07-跨服务调用.md) |
| file-storage | 普通组件；本地目录或 S3 兼容存储的文件存取、文件信息同事务提交、清理任务，授权由业务负责，见[文件存储](11-文件存储.md) |
| notification | 普通组件；短信发送（阿里云接口适配）与通用验证码（Redis 摘要、使用限制），见[短信与验证码](12-短信与验证码.md) |
| idempotency | 普通组件；入口标 `@Idempotent`，按 `Idempotency-Key` 只执行一次、重复返回首次结果，记录在会话 Redis，见[请求幂等](13-请求幂等.md) |
| 后续能力 | 消息／恢复、限流／幂等、多数据源、配置／发现／观测按真实用例逐项实施；不提前建空壳或给每项建微服务 |

### 制品拆分与装配

普通能力先一个 JAR，通过公开能力接口及依赖注入使用；仅有业务语义转换时定义服务自己的端口。原生事务、权限注解与 SPI 直接使用，不再包装同义接口。shared 为单模块单包，能力配置／实现留在组件；ApiResponse 纯数据与 CurrentSubject 等公共类型进入 shared，HTTP 工厂留在 Web。字段与序列化注解不让传输对象成为领域模型。

### 三种消费方式

组件：内部 BOM 固定版本，显式添加所需模块，配置差异，通过公开接口使用。服务：同一系统部署 IAM，调用服务的基础设施通过 Feign／Nacos 请求当前用户权限。模板：在完整源码中生成一个服务骨架并验证接入，不现场注入隐藏源码，不预建业务聚合。独有组件行为测试保留在所属模块；两种 parent／私有仓库的例行验证按已批准合同退出。

### 依赖方向与边界原则

```text
服务 → 按需声明 web-support、access-control、persistence、cache、shared
access-control → cache、shared、web-support
web-support → shared
cache → Redisson、必要 Spring 装配／事务同步 API
persistence → MyBatis-Plus、Flyway、必要 Spring 数据／事务 API
业务 domain → shared 中纯 Java 领域标识
调用服务 infrastructure → 本服务 Feign、Nacos、shared 传输类型、service-call 公开接口
service-call → shared（不依赖 access-control、IAM）
```

cache 与 persistence 无相互依赖；shared 不依赖组件／服务，组件不依赖 IAM、业务表、模板或 Harness。application 只调用技术无关公开能力，不直接使用 Redis／Mapper／Feign。infra 在适配职责内使用必要原生 SPI；interfaces 处理协议、调用应用，不直达数据库。所有层不得绕过 internal。完整有向依赖和真实源码用途共同验证，不能只看包名放行。

## 缓存与事务使用合同

一个 domain-forge-cache 模块提供 CacheOperations、RedisScriptOperations、LockOperations 三类小接口，底层复用 Redisson 社区版。access-control 直接依赖 cache，官方 SaTokenDaoForRedisson 与普通缓存共用同一个客户端；安全状态不走 L1、空值缓存或降级，禁止并存第二套 Lettuce／DAO。业务调用组件公开接口，Lua 与 SDK 仅在基础设施职责使用。

cache 的 META-INF/domain-forge/cache-defaults.yml 管唯一 Redis 连接及客户端资源，access-defaults.yml 只管 sa-token。原生 EnvironmentPostProcessor＋YamlPropertySourceLoader 加到最低优先级；服务 YAML、profile、环境、启动参数可覆盖，组件不使用 application.yml，不再维护第二套默认值或配置框架。

- 基础缓存使用类型固定的 region＋完整业务键，RBucket 保存有限 TTL。get／put 不自动防护外部回源，getOrLoad 才提供合并和负载保护。
- L1 默认关；开启使用 Caffeine 3.2.4 管理有限容量与 TTL，通过同一 RedissonClient 接收 Redis 原生 keyevent；不建自定义同步总线或按键监听器。启用前核对 E$gx 通知（淘汰模式还需 e）；无配置或无权核对明确拒绝。重订阅清空 L1，按固定 region 集合创建并关闭。L2 TTL 从写入计时，L1 从本地填充计时；失效通知不等于强一致，晚回填／断连可能陈旧。严格当前事实绕过两层，不能以 TTL 承诺距 SQL 提交固定时间内必定最新。
- 穿透：入口参数校验；明确 NotFound 可选短空值缓存（默认关），异常／超时／未授权不能变空值。创建提交后失效空值。随机键仍需回源上限，布隆过滤器不作默认前置。
- 雪崩：普通 TTL 默认在上限内向下 10% 抖动，可关闭；每实例／region 有限回源并发与等待，无无界队列。Redis 失败默认报错，只有明确可丢弃缓存可开启受限回源。
- 击穿：同进程／region／键／固定类型合并查询加载，结束或异常移除记录，键集合受并发上限约束；可选跨实例 RLock，获锁后再读 L2。无副作用 loader，不承诺丢锁后全局只运行一次，不建新线程池。
- Lua 为已评审 classpath 资源，固定 KEYS／ARGV／模式／返回类型，不接受外部脚本。脚本原子执行不等于异常回滚，超时不等于取消，不盲目重试。不得通过脚本绕过 L1 或操作 Sa-Token 私有键；命名空间不是脚本沙箱。
- 锁为原生 RLock，有限获取等待、finally 由持有线程释放；默认 watchdog，显式 lease 不假称自动续期。不能替代 SQL 约束、行锁或分布式事务。
- 写事务中不得 put／getOrLoad 填入未提交数据；evict 有事务时经原生 afterCommit 延后。回调失败只记录实际缓存失效失败，不能把已提交 SQL 伪报回滚／触发重试。旧读晚填与旧空值回填仍可能出现，按普通查询陈旧合同处理，不新增双删队列、栅栏协议或缓存 Outbox。

事务默认应用入口 @Transactional REQUIRED、全异常回滚；慢哈希在事务外，短持锁部分使用原生 TransactionOperations。绑定实际 DataSource／SqlSessionFactory／事务管理器／Flyway，不以全容器唯一数目或固定管理器类代替资源检查。当前不引入分布式协调器；跨服务最终一致优先评估真实业务状态＋同事务 Outbox，需要协调提交时再验证 AT／TCC／XA 实际组合，HTTP／Redis 不自动加入 SQL 原子提交。

当前状态：已实现。Redisson 4.8.0 原生 RClientSideCaching 不满足容量／TTL 要求，因此 L1 采用 Caffeine＋原生通知。

接入：依赖 `domain-forge-cache`，在服务 YAML 中声明区域，注入 `CacheOperations`、`LockOperations`、`RedisScriptOperations`（`org.domainforge.cache.api`）。

```yaml
domainforge:
  cache:
    regions:
      product:                      # region 名
        type: com.company.catalog.application.query.ProductView   # 值类型，JSON 保存
        ttl: 10m                    # 必填，1 秒至 7 天，默认向下 10% 抖动（ttl-jitter）
        null-ttl: 0s                # 明确不存在的短期缓存，默认关闭，至多 5 分钟
        local-capacity: 0           # L1 容量，默认关闭；开启需 Redis E$gx 通知
        local-ttl: 30s
        load-concurrency: 16        # 每实例本区域同时回源上限
        load-wait: 1s               # 等待回源许可、合并结果与跨实例锁的上限
        cross-instance-lock: false
        fallback-on-failure: false  # Redis 故障时 getOrLoad 是否直接回源，仅限可丢弃缓存
```

`CacheRegion` 提供 `get`、`put`、`evict`、`getOrLoad`；Redis 故障、回源并发已满或等待超时抛出 `CacheUnavailableException`。锁等待上限 30 秒，等不到抛出 `LockUnavailableException`。脚本以 `RedisScript(location, resultType, keyPrefix)` 声明，返回 Long、String 或 Boolean，键须在服务自己的前缀内（`satoken:`、`domainforge:` 保留）。

## DDD 边界与代码映射

采用轻量 CQRS：命令与查询按职责、合同和模型分开，默认同库、同步方法调用。独立读库、异步投影、事件溯源、命令总线和通用分发框架都不是默认依赖；有真实需求时另行设计一致性和恢复。

### 上下文、模块与模型

IAM 首版仍是一个身份权限限界上下文和一个服务，其账号／会话、组织／成员、角色／授权、菜单声明及审计是内部职责，不因包名就拆成多个上下文。业务客户、员工等模型属于消费项目；与身份关联时使用稳定标识，不共用可变 User 实体。网关是技术入口，组件是技术能力，都不天然等同于领域上下文。

默认一个服务一个 Maven 模块，以包约束上下文边界；只有独立发布、独立消费或必要技术隔离时拆模块。单上下文服务直接以服务根包为 context，其下采用 interfaces、application、domain、infrastructure 四层；不再额外嵌套 `<context>` 或 `iam/iam`。层内按真实业务与职责适度分组，不把账号、邀请、会话等内部职责改成各自再套四层的上下文。内容随真实用例创建，IAM 聚合及生命周期须在具体设计中确定。

```text
platform/services/iam/
├── pom.xml
├── src/main/java/org/domainforge/iam/      # 唯一 context 根包
│   ├── bootstrap/                          # 启动、配置与适配器接线
│   ├── interfaces/
│   │   ├── http/                           # Controller、协议请求／响应转换
│   │   ├── message/                        # 入站消息与反序列化
│   │   └── job/                            # 任务触发适配
│   ├── application/
│   │   ├── command/<usecase>/              # Command、Handler、结果；不强制接口对
│   │   ├── query/                          # Queries、Filter、View；必要编排用例
│   │   ├── event/                          # 内部事件处理、对外事件转换及协调
│   │   ├── port/                           # 本上下文需要的外部业务能力接口
│   │   └── contract/event/                 # 需要公开的集成事件数据合同
│   ├── domain/
│   │   ├── model/<aggregate>/              # 聚合根、实体、值对象、状态转换
│   │   ├── policy/                         # 可独立表达的纯业务规则
│   │   ├── service/                        # 无法归属单实体的领域行为
│   │   ├── repository/                     # 聚合仓储接口
│   │   └── event/                          # 本上下文内部的不可变领域事实
│   └── infrastructure/
│       ├── persistence/                    # 仓储实现、PO、Mapper、模型映射
│       ├── query/                          # 查询合同实现、SQL 投影
│       ├── acl/<external-system>/          # 防腐适配、外部协议与错误翻译
│       └── messaging/                      # 序列化、传输、Outbox 接线
├── src/main/resources/
│   ├── db/migration/                       # 本服务拥有的版本化迁移
│   └── contracts/                          # 所需协议源；与 Java 表示只选一种权威源
└── src/test/                               # 模型、用例、适配及运行契约测试
```

**装配归属决定**：在现有 context 职责中增加明确的 `bootstrap`，它属于本 context，不再同时登记嵌套 assembly；保持模块根包唯一、互不重叠。bootstrap 可依赖本上下文四类实现及公开装配入口，四类职责均不得反向依赖 bootstrap。bootstrap 只负责启动、配置、接线与生命周期，不承载业务判断、命令／查询执行或 SQL。结构检查证明依赖方向，职责语义由真实场景及评审证明，不能声称包分类能自动识别全部业务逻辑。

职责包归属与依赖方向由 `domain-forge-build-rules` 自动检查（见[工程与构建](02-工程与构建.md#质量门禁)）；不能把整个服务声明为 assembly 来绕过检查。职责语义由用例与评审判断，包名不能证明业务归属正确。

启动类放 bootstrap 时须显式覆盖本服务根包的组件发现范围并验证真实启动，不能只依赖默认扫描或扫描全部 `org.domainforge`。将来确有多个上下文同部署时，各 context 使用互不嵌套的兄弟根包，独立 assembly 位于这些根包之外；这不是当前 IAM 默认布局。网关和纯技术探针仍按真实装配模块管理，不伪造领域上下文。

只在已有内容确有不同业务／职责、分组有助于查找与修改时增加 `<usecase>`、`<aggregate>` 等子包；少量同责类保持同包，不给每个类建目录，不机械复制各层业务目录或预建空包。领域模型不依赖 HTTP、Spring、ORM、平台客户端、序列化或消息框架。应用允许必要装配／事务注解；不为移除注解再生成事务包装层。消息入口负责技术接收，应用负责业务消费语义与去重事务，不能只在 Listener 内捕获异常并确认成功。

| 对象 | 必须承担的责任 | 不应承担的责任 |
|---|---|---|
| 聚合根 | 维护本次一致性边界内的不变量，提供业务行为；引用其他聚合时优先用 ID | 按数据库表机械生成；暴露任意字段 setter；调用远程 SDK／发 MQ |
| 值对象／实体 | 身份、值相等性、合法状态及真正业务规则 | 继承框架 PO、承载 HTTP 或数据库生命周期 |
| 领域策略／服务 | 真实业务判断；应用准备外部事实后传入，以确定输入验证 | 将全部业务移到一个万能 DomainService；隐藏网络调用 |
| 应用 Handler | 授权、业务编排、调用规则所有者、事务与失败结果 | 自己重复聚合规则；直接调用 Mapper／SDK；只转发且毫无职责 |
| Repository | 按聚合需要加载、保存，明确不存在／并发冲突等语义 | 充当报表查询、通用 CRUD 超集或返回 PO／IPage |
| Query 合同 | 按用例表达筛选和展示数据，技术无关 | 暴露 SQL、Wrapper、ORM 分页对象或绕过权限 |
| 防腐适配 | 翻译外部模型、协议、状态和失败语义 | 取代本地业务决策；把外部错误直接当作本地成功 |

编译依赖为：入口 → 应用公开方法／查询合同；应用 → 本领域、自己的出口及允许的组件 API；基础设施 → 所实现的应用／领域接口及技术库；bootstrap → 所需实现。基础设施实现查询合同是依赖反转，不是 Controller 直接依赖 SQL。跨上下文只能引用明确公开的用例／协议，不能引用对方 Repository、领域实体或内部查询实现。

### 命令路径

`HTTP／消息入口 → CommandHandler → 聚合／领域行为 → Repository 合同 → 持久化实现`

Command 表达业务意图，Handler 负责授权、编排及事务边界，聚合维护业务不变量，基础设施保存状态并处理技术转换。需要业务事件时才定义事件；不为单个方法生成接口／实现对、总线或通用基类。简单维护若没有复杂不变量，允许轻量应用用例，不伪造聚合；一旦存在状态约束、并发或业务决策，就须有明确所有者和验证，不能当普通字段更新绕过。

客户端只提供命令输入，不直接提交可保存的聚合／PO。输入格式由入口校验，业务合法性由模型／用例判断；两者不能互相代替。持久化适配负责聚合与 PO 的往返映射；模型和 PO 分开，不因同字段而合并。唯一约束、条件更新或乐观版本处理与业务并发规则配合，不能只靠先查后写防止竞争。

### 纯查询最短路径

`Controller → Query 合同的读取实现 → SQL／Mapper → ReadDTO`

示例：`AccountQueries.list(filter)` 是应用侧技术无关查询合同；`SqlAccountQueries` 在基础设施实现并直接投影 `AccountView`。Controller 依赖查询合同，不依赖 MyBatis；接口是边界，不是额外执行层。没有编排时，不再包一层只转发的 QueryHandler、QueryService、领域仓储或聚合；有真实转换需求才额外创建对象，不强制 PO→Entity→BO→DTO 多次复制。

| 查询类别 | 允许路径／必须保留的责任 |
|---|---|
| 本上下文列表、详情、筛选、统计等纯展示 | 读取实现可直接使用本上下文 SQL／Mapper 并返回最终展示结果；可以联查本上下文拥有的表，不加载领域模型 |
| 有权限及数据范围要求 | 在查询用例边界执行授权，SQL 使用可信的服务端范围约束；外部请求不能自行提供可信授权范围。默认拒绝及范围过滤必须真实验证，不能以缩短调用链为由略过 |
| 需要跨源编排、资源授权决策或业务判断 | 增加确有职责的查询 Handler／应用用例；需要领域规则时调用规则所有者，不把决策偷偷塞进基础设施 |
| 需要其他上下文数据 | 使用公开查询合同或合法投影；不能通过同库联表读取其他上下文私有数据 |

查询不得修改业务状态；必要安全审计与观测按各自合同处理。分页、排序白名单、参数化查询、字段可见性、范围过滤和依赖故障仍需验证。查询权限的实际框架绑定须在实现中核查，不能假设接口注解或 HTTP 入口检查自然覆盖全部调用方。写操作必须重新校验当前条件，不能把之前查询成功当作写入授权或业务条件永久有效。

采用此短路径需要把具体公开查询合同及基础设施实现关系纳入源码／架构规则，防止合法短路径被误报，也防止借 query 包名绕过技术隔离或业务写入要求。

纯查询授权若可由统一用例拦截器承担，须验证 HTTP、内部调用等实际入口都生效；若需要加载资源后进行策略判断，则使用有职责的查询用例，不能为追求三段路径把授权塞入 SQL 适配器。数据库只读设置或 `readOnly` 元数据都不能替代无业务写入断言。首版默认查权威存储；若后续引入只读副本／异步投影，先确定延迟、读己之写及过期结果的用户合同。

查询性能从筛选、分页、索引和执行计划开始验证；批量查询消除 N+1，并约束最大结果量。简单查询不经过聚合重建；复杂统计允许直接 SQL，但仍只访问本上下文拥有的数据。

### 领域事件与集成事件

| 类别 | 所有者与用途 | 事务／可靠性责任 |
|---|---|---|
| 领域事件 | `domain/event` 表达本上下文业务变化；由聚合返回或暂存，应用处理 | 产生时可能尚未提交；事务内处理可随主事务回滚，不能提前宣称对外已生效 |
| 集成事件 | `application/contract/event` 表达愿意向其他上下文承诺的已提交事实 | 应用选择必要字段并映射；需可靠发布时与业务同事务写入 Outbox；传输实现归基础设施 |
| 任务／消息命令 | 要求接收方执行动作，具有明确处理者与结果合同 | 接收成功不等于业务完成；同样需要重复、部分完成及恢复设计 |
| 安全审计／普通观测 | 安全行为记录／技术诊断，各自有独立责任 | 不能用普通日志替代审计，也不能因订阅一个领域事件就声称可靠审计已完成 |

事件使用过去式业务名称和不可变数据，不携带聚合对象、凭证或全部表字段。集成事件最小信封包含稳定事件 ID、事件类型与合同版本、来源和发生时间；按实际需要增加聚合 ID／版本及关联 ID。合同版本不是聚合版本；重发同一事件不生成新 ID。发布方拥有公开含义，接收方通过自己的翻译适配使用，不共享发布方内部领域事件类。[领域事件与集成事件的区别](https://learn.microsoft.com/en-us/dotnet/architecture/microservices/microservice-ddd-cqrs-patterns/domain-events-design-implementation)

只有真实订阅者或业务副作用才引入事件；单一、明确的同步步骤可直接调用应用方法。事务内订阅不得暗含跨服务写入或不可回滚发送，也不能依赖未声明的监听器顺序维持不变量。无需建立强制所有实体继承的事件基类或统一命令总线。

**可靠发布采用本地事务 Outbox（表、中继、RocketMQ 组合与投递合同见[消息与 Outbox](08-消息与Outbox.md)）：**

```text
命令用例
  └─ 同一个本地数据库事务
       ├─ 读取并改变聚合，保存业务状态
       ├─ 处理必须同事务完成的内部领域反应
       └─ 映射需要公开的事件，写入 Outbox
     提交成功 → 返回本地已完成结果

发送器读取已提交 Outbox → 发布消息 → 记录发送结果
消费者接收 → 本地去重记录＋业务变更同事务提交 → 确认接收
```

Outbox 写入失败使包含该必需消息的业务事务回滚；事务回滚不能留下可发送事件。提交后进程中断由发送器恢复；发布成功但记录发送结果前中断会重复发送，因此按至少一次设计，不能承诺全链路 exactly-once。消费去重记录与业务效果只有加入同一实际事务才能防止本地重复；短信等外部副作用仍需服务商幂等键、状态查询或独立恢复方案。[Transactional Outbox](https://microservices.io/patterns/data/transactional-outbox.html)

可靠性边界还须固定：发送抢占／租约与多实例竞争、有限重试及退避、毒消息隔离和人工重放、积压告警、已完成记录清理、去重保留期。不清理仍待发送的必要记录。若用例要求顺序，按聚合／业务键明确排序和版本处理，不能假定所有消息全局有序。

`@TransactionalEventListener(AFTER_COMMIT)` 可用于提交后的本地通知或唤醒发送器，但单独使用不提供持久恢复；进程可以在提交后、监听执行前退出。必需发送事实已在事务中保存，唤醒丢失仍能扫描恢复。监听绑定的阶段和无事务调用也必须验证。[Spring 事务事件说明](https://docs.spring.io/spring-framework/reference/data-access/transaction/event.html)

### 事务边界与一致性

事务由应用用例决定，数据访问实现加入实际资源。默认围绕一个聚合维持本地不变量；不是强制“一事务只能写一张表／一个对象”。确有原子要求且同一实际本地事务资源可参与时，可由公开合同协调多个聚合或上下文，保留已有授权原则，说明锁范围、所有权和拆分代价。

| 情形 | 方案原则与必须证明的结果 |
|---|---|
| 单库写入 | 明确事务管理器、连接／数据源、异常回滚策略；事务真实入口上验证成功与中途失败回滚，不以注解存在代替 |
| 并发更新 | 由业务语义决定条件更新、乐观版本、唯一约束或锁；冲突明确返回或进行有界安全重试，不能覆盖别人结果 |
| 同进程跨上下文 | 只能经公开合同；若参与同一事务须实际证明，不能只凭数据库地址相同推断；频繁强耦合时重新评估上下文划分 |
| 多数据源／跨服务 | 默认无全局事务；每步本地提交，明确中间状态、成功时点、重复、补偿／人工恢复；不默认引入 XA、Saga 框架或分布式事务平台 |
| 网络、文件、短信 | 不属于数据库回滚范围；尽量不在持锁事务里等待远程调用；需要先后保证时使用明确状态机与恢复，不把同步调用包装成原子性 |
| 长流程 | 只有跨步骤确有持久进度和恢复需求才建立应用流程协调器；保存必要状态和重试键，不把普通多行方法升级成工作流引擎 |

Spring 事务代理、自调用、异常吞掉、线程切换与数据源切换都可能使预期边界失效；以实际调用路径验证。确定重试安全后才重试整个命令，并重新加载状态；不要重放已经发生但不可幂等的外部副作用。[Spring 事务声明说明](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/annotations.html)

IAM 的禁用、撤权、改密及旧会话失效沿用已确认生效条件，不能因采用集成事件就改为“后台最终失效也算成功”。SQL 与会话状态的协调必须在 IAM 设计中固定权威判断、部分失败、恢复和成功时点；Outbox 本身不解决两个存储的即时原子性。授权检查的时点与操作期间并发变化也须明确，不能承诺不存在的全程锁定。

**关键安全审计与业务同事务**：关键安全管理变更与其审计在同一数据库事务中提交，审计写入失败则业务回滚，不建设缺口告警或补录（见[安全规范](../standards/07-安全与访问控制.md)）。普通观测（日志、指标）故障不改变业务成功定义。

### 防腐接口与适配

防腐层用于隔离外部语义；默认是消费方上下文内的适配器，不新增独立防腐微服务。接口归需要能力的一方，采用本地业务语言，返回本地事实和失败结果；外部 DTO、SDK、状态码和认证细节留在实现中。[防腐层模式](https://learn.microsoft.com/en-us/azure/architecture/patterns/anti-corruption-layer)

```text
应用用例 → application/port/<业务所需能力>
                         ↑ 实现
              infrastructure/acl/<外部系统>
                   ├─ 协议／客户端连接
                   ├─ 外部数据 → 本地事实
                   └─ 超时／不存在／拒绝／未知结果的翻译
                         ↓
                   外部公开合同
```

例如消费项目需要“当前操作者可管理的组织范围”，本地用例使用自己的范围事实，IAM access 适配返回的授权事实不直接变成本地域的 Account／Role。若通用短信或文件 API 已完全满足调用目的，直接使用其公开技术无关接口，不额外建立没有翻译职责的 SmsPort＋SmsAdapter。

| 协作类型 | 具体落位与约束 |
|---|---|
| 远程读取／命令 | 出口位于 application/port，HTTP／SDK 实现在 infrastructure/acl；设置总调用预算、超时和必要重试；结果未知不能当不存在或成功 |
| 同进程其他上下文 | 适配器调用对方已公布用例／查询合同；不进入其私有表、Repository 或内部包；没有语义差异时可直接使用明确公开合同 |
| 入站集成事件 | interfaces/message 解码公开合同，转换成本地命令／事实，交给应用用例；原始来源不自动获得本地业务权限，拒绝和毒消息有处理结果 |
| 外部错误与枚举 | 已知业务拒绝映射为本地明确结果；未知状态拒绝或进入待处理，不静默映射到成功默认值；技术细节留在脱敏诊断 |

防腐适配不拥有领域规则，不借适配绕过事务边界；缓存、批量请求或降级必须符合事实的新鲜度及失败合同。IAM 当前授权失败时拒绝的既有边界不能被“可用性降级”改写。

### 结构必须通过真实例子证明

模板完整交付至少有命令、纯查询、需要编排的查询三条经过验证的路径；领域行为、事务回滚、聚合往返、并发冲突和外部失败有实际断言。需要消息恢复的交付单元再加入事务后进程退出、重复投递和消费中断例，不为最初启动模板强装消息中间件。

架构检查只约束可判定边界：领域引 SDK、应用引 Mapper、引用其他上下文私有类型、合同泄漏 PO、组件依赖服务等必须失败；合法 bootstrap、Query 实现、应用事务元数据和直接复用已声明的技术无关能力 API 应通过；领域／应用依赖 bootstrap、应用使用 HTTP 合同以及跨组件 internal 调用应失败。业务语义仍由用例和评审负责，不能以目录齐全证明 DDD 正确。

技术参考仅支持 CQRS 的一般机制：[Microsoft CQRS](https://learn.microsoft.com/en-us/azure/architecture/patterns/cqrs)说明可共享数据存储及额外复杂度；[查询设计](https://learn.microsoft.com/en-us/dotnet/architecture/microservices/microservice-ddd-cqrs-patterns/cqrs-microservice-reads)说明读侧可独立投影。上述 Java 包结构、授权责任和短路径选择为已批准的本项目目标设计，不照搬其技术栈。

## 身份权限部署与调用方案

单套系统内部共享 Sa-Token Redis 会话；IAM 独占身份业务表。后端默认 HTTP，入口 TLS、证书挂载与轮换由 Nginx／部署基础设施负责，不维护 projectId、后端 mTLS 或服务证书身份协议。纯登录校验不调用 IAM，权限／角色通过调用服务自身 Feign 读取当前用户，失败拒绝、不跨请求缓存允许结果。原生会话替换的安全前提见[身份设计](04-身份权限.md#sql-与会话状态的生效合同)。

deploy 使用固定镜像的 Compose，默认组合 Nginx、API 网关、IAM、PostgreSQL、Redis、Nacos、RocketMQ、PowerJob；Nginx 只做边缘，路由、登录前置校验、限流与 Same-Token 由网关负责（见[API 网关](06-API网关.md)）。local 仅回环发布调试端口；production 仅公开入口，不能继承本地端口。普通 down 保留卷；旧库不 clean／repair。测试复用这些资产，不临时重建另一套部署。实际启动与恢复须单独验证。

## 模板与源码复用

业务项目以同仓库源码复用为主（2026-10-23 决定）：模板在本仓库 `platform/services/<name>` 生成服务，继承内部 parent，加入 `services` 聚合，自动执行架构规则；不要求发布组件到私有仓库，也不以独立仓库消费作为首版目标。IAM 远程调用定义于调用服务自己的 infrastructure。以干净源码构建、部署和一个模板服务接入 IAM 证明可用。
