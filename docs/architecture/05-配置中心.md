# 配置中心（P6-2 设计）

接入 Nacos 配置中心，集中管理服务的非敏感运行参数，并让明确列出的配置项不重启生效。产品范围见[运行配置与 Nacos](../product/01-产品定义.md#运行配置与-nacos)，规则见[配置与运行 O-09、O-10](../standards/08-配置与运行.md#nacos)，实施状态见[路线图](../product/02-路线图.md#p6-实施计划)。已实施（组件、IAM 接入、部署、模板）。

## 已确认的决定（2026-10-27）

| 问题 | 决定 |
|---|---|
| 无法应用的发布值（越界、类型错误） | 整组配置不应用，继续使用当前生效值，记录错误日志与指标；发布方修正后自动生效。O-09 相应修订，仍不做内容审核或拒收 |
| 启动时连不上 Nacos | 启动失败，不用本地默认值或客户端快照代替 Nacos 的值；Compose 重启策略负责重试 |
| 初始配置来源 | 仓库维护种子，`nacos-init` 只在 dataId 不存在时发布；之后以 Nacos 中的内容为准，重新部署不覆盖 |
| 服务读取配置的账号 | 共用现有服务账号，增加命名空间内配置只读权限；发布只由 Nacos 管理员进行 |

## 配置分层

每类配置只有一个来源，不并行维护权威值。

| 层 | 内容 | 例子 | 变更方式 |
|---|---|---|---|
| 环境变量 | 凭据、密钥、连接目标、Nacos 自身的地址与账号 | `IAM_DB_PASSWORD`、`IAM_FINGERPRINT_KEY`、`IAM_NACOS_SERVER_ADDR` | 改环境文件后重启 |
| Nacos | 非敏感的运行参数 | IAM 登录防护阈值、日志级别；后续网关路由与限流 | 控制台发布；动态项立即生效，其余项重启生效 |
| 组件与服务 YAML | 结构性默认值和装配细节 | 超时、连接池、Flyway 选项 | 改代码后发布新版本 |

Nacos 中不放凭据、密钥或个人数据。服务 YAML 中对 Nacos 管理项保留的默认值只供本地开发（不启用配置中心时）使用；启用后以 Nacos 的值为准，不用本地值纠正。

## 数据组织与访问

- 每个服务一个 dataId：`<spring.application.name>.yaml`，分组 `DEFAULT_GROUP`，命名空间沿用服务发现的命名空间（每套环境一个）。
- 服务账号在命名空间内的权限：服务发现读写（已有）＋ 配置只读（新增）。服务之间能读到彼此的配置，因此 Nacos 中只放非敏感内容。
- 种子文件：`deploy/nacos/config/<dataId>`，与服务一起维护；模板生成服务时一并生成。

## 接入方式

- 服务依赖 `domain-forge-config`（它引入 `spring-cloud-starter-alibaba-nacos-config`）。服务 `application.yml` 中的 `config-center` profile 文档以 `spring.config.import=nacos:<dataId>?refreshEnabled=true` 导入（非 optional），并声明 `domainforge.config.expected-source: nacos`；部署时以 `SPRING_PROFILES_ACTIVE=config-center` 启用，本地开发默认不启用。
- 组件 `domain-forge-config` 提供“动态配置快照”：服务在 bootstrap 中以 `DynamicSettingsBinder.bind(prefix, Record.class)` 声明配置组，得到 `DynamicSettings<T>`；组件在启动时绑定并校验（前缀缺失、未知键、取值非法都阻止启动），此后每次 `EnvironmentChangeEvent` 涉及该前缀时重新绑定整组；成功则原子替换快照，失败则保留当前快照、记录错误并计数。使用方每次读取 `current()`，不缓存旧引用。
  - 不用 `@RefreshScope`：刷新后首次访问才重建 Bean，失败会落在业务请求上。
  - 不用可变 `@ConfigurationProperties` 的原地重绑：逐字段更新会让并发读取看到新旧混合的值。
- 日志级别使用 Spring Cloud 自带的 `logging.level.*` 重绑定，不另做。
- Nacos 客户端自带的日志配置向 `${user.home}/logs/nacos` 写文件；容器中的服务用户没有主目录，创建失败会让 Spring Boot 日志初始化报错退出（模板服务实测）。组件在加载配置前设置 `nacos.logging.default.config.enabled=false`，客户端日志随应用日志输出到标准输出。
- 指标：计数器 `domainforge.config.refresh`（标签 `group`、`result=applied|rejected`），以及最近一次成功应用的时间 `domainforge.config.applied.time`（标签 `group`）；就绪状态不因一次应用失败而下降（O-06：可选能力出错不判进程失效）。

### 启动行为

| 情况 | 结果 |
|---|---|
| Nacos 不可达 | 启动失败（import 非 optional）。Nacos 客户端默认在服务端不可达时读取本地快照，已实测会让启动以上次的值成功；组件在加载配置前调用 `SnapShotSwitch.setIsSnapShot(false)` 关闭快照，集成测试以“先成功读取、再断开 Nacos、再启动”验证启动失败，并以去掉该开关时测试失败作为对照 |
| dataId 不存在 | 启动失败。Nacos 对不存在的 dataId 返回空内容而不报错，因此组件要求配置中存在标记键 `domainforge.config.source: nacos`（与 `expected-source` 一致），缺失即失败 |
| 值非法（越界、类型错误） | 启动失败（O-05） |

### 运行行为

| 情况 | 结果 |
|---|---|
| 发布合法的新值 | 动态项在应用侧生效；验证以实际行为为准（O-10），不以收到通知为准 |
| 发布无法应用的值 | 整组不应用，保持当前值，记录错误与 `rejected` 计数；修正后的下一次发布正常生效 |
| 运行中 Nacos 断开 | 继续使用当前值；恢复连接后客户端重新同步，断开期间的发布在恢复后生效 |
| 修改了只重启生效的项 | 当前进程不变，重启后生效；文档逐项标注 |

## 首批动态项

| 服务 | 配置组 | 动态项 | 只重启生效 |
|---|---|---|---|
| IAM | `iam.login-protection` | `account-attempts`、`account-window-seconds`、`address-attempts`、`address-window-seconds` | `iam.password-hashing` 的 `workers`、`queue-capacity`、`wait-millis`（线程池与队列容量；从原 `iam.login-protection.hash-*` 拆出，环境变量名不变） |
| 所有服务 | `logging.level.*` | 全部 | — |

登录防护的取值范围（只允许收紧）保持不变：启动时越界阻止启动，运行时越界的发布按“无法应用”处理。

## 部署

- `nacos-init` 增加两步：为服务账号授予配置只读权限；对 `deploy/nacos/config/` 中每个种子，dataId 不存在时发布，并等到客户端读取路径能读到再退出（实测发布后约数百毫秒内读取仍返回不存在，否则紧随其后启动的服务会因缺少来源标记而失败）。
- 服务的 Compose 定义打开配置中心开关；`depends_on` 已包含 `nacos-init` 完成。
- 备份：`backup.sh` 经管理接口导出全部配置（含控制台修改）为 `.nacos.json`，`restore.sh` 一并恢复，见[部署参考](../../deploy/README.md#备份与恢复)；部署场景验证覆盖删除 Nacos 卷后的恢复。

## 验证计划

| 场景 | 方式 | 判定 |
|---|---|---|
| 启动读取 | `ConfigCenterIT`：真实 IAM＋PostgreSQL＋Redis＋开启鉴权的 Nacos | 登录防护按 Nacos 中的阈值生效（而非 YAML 默认值） |
| 动态生效 | 运行中发布更严格的阈值 | 之后的登录按新阈值返回 429 |
| 无法应用的值 | 发布越界值或非数字 | 继续按原阈值工作，`rejected` 计数加一；修正后新值生效 |
| 运行中断开与恢复 | 暂停并恢复 Nacos 容器（随机端口映射在重启后会变化） | 断开期间登录照常；恢复后发布的新值生效 |
| 启动时不可达、dataId 不存在 | 启动应用 | 启动失败并给出原因 |
| 日志级别 | 发布 `logging.level` | 对应日志器级别实际改变 |
| 部署 | `verify_deploy.sh` 扩展 | 种子首次发布、重新部署不覆盖控制台修改、备份恢复后配置保留 |
