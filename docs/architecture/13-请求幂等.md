# 请求幂等

业务命令的重复提交（客户端超时重试、用户重复点击、网关重试）统一经 `domain-forge-idempotency` 组件处理：入口方法标 `@Idempotent`，客户端在请求头 `Idempotency-Key` 中给出唯一键，同一键的请求只执行一次。产品要求见[缓存与额外通用能力](../product/01-产品定义.md#缓存与额外通用能力)，决定与验收跟踪见 [#37](https://github.com/liming-cloud/domain-forge/issues/37)。

## 已确认的决定（2026-10-29）

| 问题 | 决定 |
|---|---|
| 合同 | `Idempotency-Key` 请求头（与 IETF Idempotency-Key 草案一致），重复请求原样返回首次结果 |
| 范围 | 键与账号、接口绑定，保存 24 小时；处理中的并发重复 409，同一键但请求不同 422 |
| 验证用例 | 模板便笺示例的创建接口 |

## 合同

| 情况 | 结果 |
|---|---|
| 不带 `Idempotency-Key`，或入口没有标 `@Idempotent` | 照常处理，不做幂等 |
| 首次请求 | 照常处理；结果（状态码、内容类型、响应体）保存 24 小时 |
| 重复请求（同一账号、方法、路径与键，请求体相同） | 不再执行，原样返回首次结果，响应头 `Idempotent-Replayed: true` |
| 首次请求仍在处理中 | 409 `IDEMPOTENCY_IN_PROGRESS` |
| 同一键但请求体或查询参数不同 | 422 `IDEMPOTENCY_KEY_REUSED` |
| 首次结果为 5xx，或处理中抛出异常 | 不保存，允许用同一键重试（会再次执行） |
| 首次结果超过 1MB | 不保存，允许重试 |
| 键不合法（1—255 个可见 ASCII 字符之外） | 400 `INVALID_REQUEST` |
| 请求体超过 1MB | 413 `PAYLOAD_TOO_LARGE` |
| 未登录 | 照常交给入口，由登录校验拒绝（401）；幂等只用于已登录的接口 |
| Redis 不可用 | 503 `SERVICE_UNAVAILABLE`，不执行；不退化为“不做幂等”，避免重复执行 |

- 业务拒绝（HTTP 200＋稳定代码）与 4xx 也是“首次结果”，重复请求得到同样的拒绝。
- 处理租期 60 秒：首次请求在租期内没有结束（如进程中断），记录过期后同一键可以重试。租期须长于入口的最长处理时间。
- `IDEMPOTENCY_IN_PROGRESS`、`IDEMPOTENCY_KEY_REUSED` 是平台保留代码，业务拒绝不能使用（见 [Web 组件](03-Web组件.md#结果映射)）。

## 组件

| 部分 | 行为 |
|---|---|
| 注解 `@Idempotent` | 标在入口方法上；组件在首次请求时从 MVC 映射表读取标注入口的方法与路径模式 |
| 过滤器 | Servlet 过滤器，排在会话与 Same-Token 等安全过滤器之后、进入 MVC 之前；读出请求体计算指纹后交还后续处理 |
| 账号 | 取自 Sa-Token 原生会话（一次 Redis 读取，不调用 IAM） |
| 记录 | 服务的会话 Redis 中，键为 `domainforge:idempotency:<摘要>`（摘要含服务名、账号、方法、路径与键，不暴露原值），字段为状态、请求指纹与首次结果；开始、保存、放弃各为一次 Lua 原子操作，多实例共享 |
| 配置 | `domainforge.idempotency.ttl`（24h）、`lease`（60s）、`max-request-size`（1MB）、`max-response-size`（1MB） |

## 服务中的写法

```java
@SaCheckPermission(NotePermissions.WRITE)
@Idempotent
@PostMapping("/api/notes")
public ApiResponse<NoteChangeResponse> create(@RequestBody CreateNoteRequest input) { ... }
```

- 只给“重复执行会产生重复效果”的命令加（创建、支付、发送）；查询与天然幂等的修改（按版本更新）不需要。
- 客户端为每次用户操作生成一个新键（如 UUID），重试时沿用同一个键。
- 组件只保证同一键不重复执行；业务本身仍需对并发与重复的业务含义负责（如唯一约束）。

## 验证

| 场景 | 方式 |
|---|---|
| 两个应用实例之间：重复返回首次结果、请求体不同 422、处理中 409、5xx 不保存可重试、账号与接口隔离、无键与非幂等入口照常执行、键格式与未登录 | 组件 `IdempotencyIT`（真实 Redis） |
| 记录存储故障时 503 且不执行业务、键格式 400、请求体超限 413 | 组件 `IdempotencyFilterTest` |
| 便笺创建：重复提交只有一条便笺与一个事件，换了内容 422 | 模板 `NoteServiceIT` |
| 经 Nginx 与网关重复提交返回首次结果并标记重放，之后的便笺数与便笺统计均为 1 | `scripts/verify_closure.sh` |
