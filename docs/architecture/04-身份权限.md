# 身份权限首个切片设计

## 确认与范围

2026-10-21 用户确认修订后的 D01—D10 与 A01—A14，批准方案 SHA-256 为 `2dee984a7b9a906a1b3a4460ee9b255cb444b4b96b02a16649dd9a15e23a6cbf`；本轮只实施 B0—B1。IAM 作为业务应用复用公共访问控制组件，优先使用 Sa-Token 原生能力；阶段三已确认的初始化、邀请注册、登录保护、最小直接授权、跨实例失效、审计和独立后端接入合同继续有效。完整组织／RBAC／菜单／数据范围的设计已确认，B2—B4 实施仍需阶段三人工验收和后续启动授权。

用户已确认过度设计排查后的[最小整改方案](#最小整改方案)，本地实施授权及获批正文摘要由任务记录维护；MIN-D01 的额外承诺已明确撤回。目标与当前实现／验证事实分别核对，方案确认不产生产品或人工验收通过。

本页维护现行设计，沿用[总体架构](01-总体架构.md#身份权限部署与调用方案)和[访问控制](../standards/07-安全与访问控制.md)。实际实现、验证、剩余问题及当前操作边界只以[身份切片任务](../work/06-身份切片.md#唯一任务记录)为准。原 IAM 代码人工验收拒绝继续保留；M2 样例认可、Q01 配置批准和旧候选本地通过均不代表新实现或阶段验收通过。

IAM 保持单一上下文和四层，层内按真实职责适度分包。常规用例和 SQL 适配采用构造器注入，bootstrap 只接线公共组件、HTTP／安全资源及 Mapper。CLI 经启动回调取得非 Web 上下文，不反向依赖 bootstrap。自定义 SQL 维护于 Mapper XML，简单操作可使用类型安全 MyBatis-Plus 链式方法，禁止 Java SQL 注解或拼接 SQL。领域只标识 Account、RegistrationInvitation 等真实聚合；SQL 会话许可是认证适配的内部安全记录，保留事实语义而移出业务聚合分类。当前授权仍由 application.authorization 集中编排，权威时间复用 DatabaseTime；密码规则归纯领域策略，摘要和有界计算归基础设施。本地事实源承接公共组件的请求安全回调，归 interfaces.security，与同令牌私有请求上下文协作；真实数据库／Redis 适配仍归 infrastructure，不为跨层取回再造接口。

## 战略边界与统一语言

对业务产品而言，身份是通用支撑能力：成熟认证、密码和会话机制复用现有框架，平台自行负责账号、邀请、授权、生效和审计规则。没有独立语义或发布压力，不拆认证／权限／组织等微服务。IAM 上游通过公开协议向消费项目提供身份和授权事实；下游拥有自己的资源归属与业务规则，在有语义差异时于 `infrastructure/acl/iam` 翻译。双方不共享实体、表、会话键或服务实现 JAR。

| 术语 | 上下文 | 规范含义 | 不表示什么 | 别名 | 正反例 | 来源 |
|---|---|---|---|---|---|---|
| 账号 | IAM | 项目内稳定 AccountId 对应的登录主体，含状态、凭据版本及直接权限 | 员工、客户或组织成员 | 无 | 同一人可在两个项目有独立账号；不共用全局 User | 产品与总体架构 |
| 注册邀请 | IAM | 管理者允许指定登录名在有效期内自行注册一次的授权 | 已建好的账号或已认证自然人 | 邀请 | 使用后不能重放；仅知道登录名不能注册 | 3-D01 |
| 会话许可 | IAM 安全适配 | 原生令牌可用于本项目授权的最小 SQL 事实及撤销状态 | 新令牌协议、第二套会话引擎或业务聚合 | SessionGrant | Redis 有令牌但 SQL 无许可时拒绝 | D03／S2 |
| 直接权限 | IAM | 账号可执行的有限操作码集合 | 对任意业务资源都有权限 | 无 | account:read 不等于 grant:manage | 最小授权范围 |
| 当前授权 | IAM／调用方 | 该次检查所见的有效会话、当前账号及权限；调用方再核对自己的资源 | 永久通行证或在途操作全程锁定 | 无 | 撤权提交后发起的新检查拒绝；此前已完成检查的在途请求不强制中断 | 既定生效原则 |

IAM 不拥有员工、客户、订单或消费项目数据；组织树和菜单树属于已确认完整 IAM 模型，B1 尚不实现。独立消费者只验证真实身份查询调用，不新增演示业务聚合。权限码以 `iam:` 为命名空间；本单元目录固定为 `iam:invitation:create`、`iam:account:read`、`iam:account:state`、`iam:grant:manage`、`iam:audit:read`，未知权限不可分配。普通注册账号初始无管理权限，仅可登录、退出、改密及读取自己的最小资料；无默认组织、角色或租户。

初始管理员仅取得上述五项明确权限，不使用超级用户绕过分支或通配符。具有 grant:manage 的管理者只能分配自己当前持有的目录权限，不能借授权提升自身权限；变更用例在同一事务内重新核对当前操作者的有效依据和可分配集合。初始化命令不开放HTTP，凭据经交互输入或受保护文件读取，不放命令参数／日志；审计把来源标为受控部署命令，不把操作者自填名字伪装成已认证自然人。

账号标识采用随机 UUID；登录名推荐 ASCII 小写 `a-z0-9._-`、3—64 字符，按合同显式规范化，数据库唯一约束兜底，公开响应不泄露不存在／禁用／密码错误的差别。密码本单元采用 15—128 Unicode 码点，允许空白及 Unicode，不 trim、不截断、不隐式规范化，最多 512 UTF-8 字节；创建与修改使用同一规则并拒绝随制品提供的固定常见密码列表，列表版本及摘要可查，不调用第三方提交明文密码。本单元没有 MFA／找回密码；失去全部管理凭据的运维恢复另行设计，不能提供后门。

不为清单制造 DomainService、Factory、Specification 或空事件类。领域行为留在 Account／Invitation；许可保留最小认证数据与存储出口，不标为 AggregateRoot；仓储按真实一致性边界提供，不按每张表造 Repository。审计记录是审计事实，不冒充领域事件。没有真实外发事件消费者，本单元不引入 MQ／Outbox；未来需要可靠外发时另定同资源保存与重放合同。

命令路径：`interfaces/http → application/command → domain 行为＋仓储 → infrastructure/persistence`。事务归属应用，真实代理入口、checked 异常回滚及并发冲突必须验证。B1 保留“至少一个启用且持有全部五项管理权限的管理者”这一跨账号规则；可能移除最后管理者的操作与初始化在同库事务先锁唯一 administration_guard，再按固定顺序锁受影响账号。普通改密、邀请、补录不因属于“管理”而共享该全局锁；仍须保留当前操作者资格、每账号锁、版本和幂等结果核对，并用真实并发验证移除全局锁后的授权时点。它是显式协调，不伪装成每个账号自己的不变量，也不引入分布式锁。

纯账号列表查询：`Controller → application.query.AccountQueries → infrastructure.query 单次投影 SQL → ReadView`，固定字段、参数绑定、白名单排序、最多100条、稳定键分页，不查询总数，禁止 N+1。身份及操作权限先由统一执行机制校验；因此“单次SQL”指该业务投影，不隐去在线授权 SQL。本人资料用当前可信主体限定 ID；存在资源决策的查询用例可以承担真实编排，不能允许客户端任意 ID 伪装为本人。Controller 不直接调 Mapper，应用不暴露 PO／Sa-Token／Redis／HTTP 客户端类型。

## 完整身份权限模型与后续实施

以下是已批准的 B2—B4 设计，尚未实施，不将原生角色机制夹具当成真实 RBAC 产品证据。B1 继续固定五项直接权限、当前最后管理者规则，真实账号角色集合仍为空。完整账号密码与邀请注册包括初始化、邀请失效／重发／一次消费、登录防护、退出、改密及跨实例生效；开放注册、短信／邮箱登录、找回密码、MFA、OAuth 和跨项目 SSO 不在本轮范围。

| 模型及所有者 | 关键规则与一致性边界 |
|---|---|
| IAM Account／RegistrationInvitation | 完整 RBAC 时 Account 不再保存直接权限集合；邀请消费与建号同库原子，无默认部门或角色 |
| IAM OrganizationUnit | 单项目一棵树，节点以 parentId 关联；无环、根受保护。本节点及全部祖先启用才是有效部门；移动／停用后新检查取新归属 |
| IAM Membership | 账号可无部门、可属多部门；存在成员关系时恰一主部门。成员修改按账号协调；主部门只作默认展示，不改变范围起点 |
| IAM Role／账号角色关系 | 角色维护权限授予，分配关系只持 ID、不重复，无角色继承或组织自动授角；已分配角色先停用／撤销后再删 |
| IAM 权限目录／PermissionGrant | 服务发布命名空间内精确操作码与资源／范围语义，由有权管理员受控安装；未知码不可授予，不用通配符自动获得未来权限。每次授予将权限与范围绑定 |
| IAM MenuItem | 目录／页面／按钮树，无环、按钮不得作父节点；受保护页面和按钮关联真实权限。可见投影不授予 API 权限，直连仍由后端执行 |
| IAM 安全审计与内部许可 | 保留必要变更审计、缺口／补录及最小 SQL 许可；关联行、DTO／PO 和技术记录不一律标聚合 |
| 业务服务自己的资源 | 员工、客户、订单等模型、资源归属、业务状态、查询过滤和写入约束；IAM 不拥有其实体、表或事务 |

组织使用邻接表与 PostgreSQL 递归查询，不并行维护闭包表、路径串和 Redis 树。删除有子节点、成员或自定义范围引用的节点时拒绝，先迁移／解除引用。组织停用只撤除由该组织归属产生的范围，不禁用账号或移除其独立角色；成员部门全部失效时不升级为 ALL。组织结构和成员／范围引用写入使用必要的组织协调与外键／条件更新，授权读取不占全局管理锁。

B2 引入受保护 SYSTEM_ADMIN，只显式拥有当前 IAM 管理权限，不默认拥有业务权限或 ALL。至少保留一名启用且有可用凭据的系统管理员，但没有本人密码证据时不保证其一定可登录。普通 CRUD 不能停用／删除／改码、撤必要权限或停用目录以绕过保全；目录升级用显式迁移。首版只有 SYSTEM_ADMIN 可修改组织、成员、角色、账号角色和角色范围，普通账号管理员不得自授角色或修改系统管理员安全属性；本人改密保持本人路径。B1 不提前替换现有五项管理语义。

数据范围支持 SELF、DEPARTMENT、DEPARTMENT_AND_DESCENDANTS、CUSTOM_DEPARTMENTS、ALL；NOT_APPLICABLE 仅适用于目录声明的非数据操作，不是 ALL。部门型范围以当前全部有效成员部门为起点；CUSTOM 只包含列出的有效部门，不隐含子树。按某个精确权限合并有效角色中该权限的范围，再与业务资源／状态条件相交；无匹配授权为空，解析失败不能放行。角色 A 的订单 SELF 与角色 B 的发票 ALL 不能组合成订单 ALL。ALL 仍限于本项目和该权限资源类型。

公共 current() 返回可信主体、角色和精确权限，scope(permissionCode) 按精确权限取范围；范围合同不含 SQL、字段名或自由表达式，范围事实源只在 B3 按实际调用增加。current 单次边界为 20 个角色、1000 个精确权限码和 256KiB；范围批量最多 32 项、每项 1000 个组织 ID、总响应 2MiB。超限明确失败，禁止截断后继续允许；B2—B3 必须按最大形状实测，不用 B1 旧规模证明新合同可用。

每次授权由主库单条 SQL／CTE 在同一语句快照中计算许可、账号、角色、权限、成员和组织有效性，不拼多个 READ_COMMITTED 语句制造混合授权图。范围响应与其主体、精确权限及校验时点绑定，不拼接旧入口角色。业务 Query 将可信范围映射为参数绑定 XML 谓词，列表、数量、分页、导出、单条与写入同样受限；写入还验证本地对象与状态。首版不建通用 SQL 拦截器、策略 DSL 或 DENY 引擎。

固定加锁顺序为“管理员保全（需要时）→组织协调（需要时）→幂等键→按 ID 排序的账号／角色／组织行”，具体用例在 B2 核验，不中途倒序补锁。只有真实订阅者出现时再设计领域／集成事件和可靠外发；事件、Outbox 或审计不能承担新检查立即生效。协议、SDK、BOM 及消费者输入成套演进，有旧客户端时显式版本化，不对严格解码端点无声加字段。

## SQL 与会话状态的生效合同

采用 S2：原生 Redis 会话与最小 SQL 安全事实取交集。原生仍负责令牌格式和生命周期，SQL 许可只补足已批准的签发提交、持久撤销及旧快照保证；不把双写包装成原子成功。

| 替代方式 | 结论与代价 |
|---|---|
| 只保留原生 Redis 会话、权限读 SQL | 可支持普通跨实例登录／退出，但 Redis 清理失败、旧快照及退出未知结果需要不同恢复合同，不能等价删除许可 |
| 原生 Redis＋SQL 许可，采用 | 每登录写许可、每授权读主库，增加清理和两个必要依赖；保留既定持久拒绝及旧快照不能复活的保证 |
| 改为 PostgreSQL SaTokenDao | 新 DAO 的 TTL、序列化、事务和性能均须设计验证；同库不自动加入业务事务，且改变既定 Redis 基线，本次不采用 |

现有小负载实测只能作为原候选基线，不存在纯 Redis／S2 对照，不能推算删除 SQL 的收益；B1 重测原生 Redis、SQL／连接等待、HTTP/TLS 和哈希成本，并探测有界饱和，不外推生产 SLA。

1. **授权**：IAM 先用 Sa-Token 验证原生 Redis 会话，再从 PostgreSQL 主库用本次新语句读取 SQL SessionGrant、账号状态／凭据版本及所需权限，所有条件同时成立才允许。不得从副本、跨请求缓存、旧事务快照或客户端自报主体取允许依据；并发校验完成时点按既有在途规则解释。
2. **登录**：有界密码计算在长事务之外；记录所校验的凭据版本。原生令牌和邀请令牌在SQL只保存摘要；邀请使用成熟安全随机源生成至少256位随机值，明文只交付一次，不把弱密码摘要方式套在高熵令牌上。创建原生 Redis 令牌后，SQL 短事务锁账号重新核对启用状态及凭据版本，再插入许可；SQL 提交并确认后才交付令牌。若密码在计算后被修改，拒绝绑定旧结果。Redis 有令牌但 SQL 无许可时一律拒绝，失败清理只降低残留资源，不能成为安全前提。禁止用户间或登录间复用已有令牌。SQL许可有效期由数据库时间确定，并与原生令牌的更早到期条件取交集；时钟漂移不能延长授权。
3. **撤权**：SQL 同一事务更新账号权限和并发版本；之后的新授权从主库读到新集合才是有效依据。无需等待跨实例权限缓存失效，因为根本不缓存允许结果。
4. **禁用／改密**：状态／新摘要和 credentialVersion 原子提交；所有旧 SessionGrant 的版本马上不符。后续清理 Redis 仅作资源清理；即使清理失败或旧 Redis 快照恢复，旧令牌仍不能重新授权。启用账号也不恢复旧版本会话。
5. **退出**：SQL 撤销当前许可提交后再尝试原生 Redis 退出；SQL 拒绝事实持久存在。有效期默认8小时、无自动续期，多会话允许；改密失效全部旧会话，退出只影响当前会话。过期记录按有界清理删除；无法找到许可时仍拒绝，不能重新推导补建。
6. **事务结果／恢复**：事务未建立且工作未执行、工作中止并由原生确认回滚，以及原生明确的 UnexpectedRollback，归确定失败。工作已返回后的提交异常仍须核对原生完成事实；提交故障后的补偿回滚不能证明此前提交未发生，不能仅按异常父类型判定。无法确认提交时返回503及不含秘密的 operationId，不报告未发生或成功。管理写入和邀请注册以 operationId＋可信主体＋请求摘要登记于同一业务事务，重复相同请求返回已确定结果，重用ID配不同输入拒绝。密码摘要不参与外部可见指纹；敏感请求指纹使用服务端密钥HMAC，仅在内部留存。登录结果未知不重放令牌，重新登录生成独立会话。读取操作结果要求原操作者当前仍有适用访问资格；失去资格时由有权管理者核对，不能用 operationId 绕过授权。

邀请注册的重复请求在账号尚不存在时绑定有效邀请秘密的摘要，不信任自报AccountId。敏感命令指纹密钥属于必要部署凭据，禁止默认值，收据保存24小时并按有界任务清理；收据不保存原始密码或令牌。创建邀请响应丢失后，只能核对“已创建／密钥不可重读”，不能从摘要还原秘密；有权管理者显式重发邀请，在同库事务使旧邀请失效并创建新邀请。重发与接受并发时只有一个转换成功，已经消费的邀请不能重发去重置已有账号。该结果边界也适用于初始化命令输出，不能因客户端未收到响应就再次提升权限。

SQL、Redis 任一必要依赖不可用时相关登录／受保护访问拒绝或503，匿名且不依赖它们的存活检查独立。SQL恢复到旧备份可能恢复旧凭据／许可，不在热故障恢复保证中：恢复流程须维护停机边界、清空会话Redis及SQL许可，再放行；不能宣称任意数据库回滚仍保持撤权。真实连接恢复要验证，不把“重新启动所有组件”当唯一恢复证据。

## 默认登录防护及审计

本单元采用正常路径默认启用以下有界防护；以每项目独立 Redis 和多实例原子脚本维持状态，不依赖本机计数。窗口使用服务端时间，按原子读改写结果判定，禁止先读再写导致竞争越限。计数键不存明文登录名。可信客户端地址默认是直接连接地址；未经明确部署合同，不信任 Forwarded／X-Forwarded-For。

- 账号维度：同一规范化登录名10分钟最多5次失败／未完成的密码校验尝试；并行尝试先原子预占，成功仅消除本次预占，失败保留至窗口恢复，不能用并行请求或成功请求清空他人失败。超限返回429及 Retry-After，不创建永久锁号。不存在账号采用同一键语义及固定假摘要校验，响应不透露账号存在性。
- 地址维度：同一来源每分钟最多30次登录尝试；账号限制覆盖分散来源，地址限制降低多账号喷洒。有限容量及TTL控制高基数，不以有状态字典无限增长换取“拦截”；Redis noeviction，写入拒绝／状态未知返回503，不能当零失败次数。
- 本实例 Argon2 工作池默认最多2个并发、队列8、等候最多1秒，饱和拒绝，不无限创建线程。初始本单元采用参数 m=19456KiB、t=2、p=1、独立16字节盐和32字节输出；它们是首轮资源验证起点，若声明环境不满足安全与时延出口，提交实测取舍，不能自行降参数。
- Redis失败状态恢复不得清空限制后悄悄继续：正常重连保留状态；数据丢失／恢复旧快照须受控关闭登录并经过完整计数窗口后再开启；默认10分钟，调参遵守[有限配置恢复规则](#有限登录配置与受控切换)。用SQL持久化项目防护恢复截止时刻，使切换实例／重启不能跳过；缺少Redis运行代次或无法确认延续性时进入此保守恢复路径，不假设空Redis是正常新用户。
- 项目可通过有限配置调整阈值、窗口和工作池，启动校验边界，不能设为0或关闭保护。有限配置与受控切换已获批准，具体边界见下节；实现与验证状态以任务记录为准。默认会造成共享出口及遭攻击账号暂时无法登录，明确为接受成本；不宣称能防所有分布式攻击，不新增验证码、MFA、网关或通用限流组件。

恢复机制首轮按单Redis主节点运行代次与SQL防护状态对照验证；全新空项目由显式初始化建立首代记录，其后缺失／变化按恢复处理。自动主从切换和任意代理隐藏节点身份不在本切片支持拓扑内；不能将此有限单节点恢复结论宣称为Redis高可用保证。共享保护配置调整需同时评估恢复窗口，不能让窗口短于仍可能有效的失败计数；仅调整本实例哈希资源不触发共享策略切换。

必要审计覆盖初始化、邀请、注册、授权／撤权、状态和凭据变更／退出；记录 operationId、可信操作者、对象ID、动作、发生时间、实际结果及脱敏字段摘要。禁止密码、令牌、邀请密钥、凭据摘要或完整请求入审计。

普通审计在业务 `execute` 正常返回、原事务资源释放后，通过现有管理器的独立事务保存；不在仍占业务连接的提交后回调中二次借连接。可信操作者和实际新写入事实由事务内带出，幂等重放不新增完成审计；本次 UNKNOWN 不伪造 completed，也不删除已有可核对事实。审计单独故障不回滚已完成业务，失败计数与结构化错误走独立日志通道，不能依赖失效的审计表。可恢复错误最多有界重试2次；仍失败则标为审计不完整。补录仅由 audit 权限的显式管理命令执行，附原始事实来源、缺失字段和补录时间，不伪造原始全量信息；本单元不承诺进程崩溃前未持久事实可完整找回。正常查询保留分页和访问控制，保留期本单元采用90天、到期按有界批次清理；它是默认运维参数，不是合规结论。

## 有限登录配置与受控切换

用户已确认 Q01 保守边界：只允许收紧防护或减少哈希资源，不改变 Argon2id 强度或既有默认值。七项部署配置统一使用原生 Spring Boot 绑定，非法输入拒绝启动。

| 属性（前缀 `iam.login-protection`） | 默认 | 允许范围 |
|---|---|---|
| `account-attempts` | 5 | 1—5 |
| `account-window-seconds` | 600 | 600—3600 |
| `address-attempts` | 30 | 1—30 |
| `address-window-seconds` | 60 | 60—600 |
| `hash-workers` | 2 | 1—2 |
| `hash-queue-capacity` | 8 | 1—8 |
| `hash-wait-millis` | 1000 | 100—1000 |

前四项形成版本化确定性摘要，保存在 SQL 防护行，每次登录在既有行锁中核对。不同策略实例返回503，不能自动覆盖已登记策略；哈希池参数只属于本实例，不进入共享摘要。初始化管理者时登记当前配置。追加数据库迁移保留 V1 校验和，将旧固定策略登记为原默认值。

变更共享策略须先停止全部实例登录、排空在途请求，在目标配置下运行非 Web 命令 `login-policy status` 查看当前／目标摘要，再运行 `login-policy apply --expected-digest=<当前摘要> --confirm-login-stopped`，最后以一致配置启动全部实例。确认参数是操作者的停登录声明，不能代替部署环境证明；没有 HTTP 维护入口。摘要不符、未初始化、重复应用同一策略均拒绝。事务锁定并核对旧摘要后，保存新策略及恢复截止，恢复期取旧、新账号／地址窗口最大值，既有更晚截止不得缩短；恢复期间503，实例或 Redis 重启不能跳过。未经命令直接改配置只会拒绝登录。

账号／地址计数和剩余等待由同一 Redis 原子脚本计算，429 的 `Retry-After` 为实际窗口剩余秒数上取整，至少1秒；哈希饱和／超时建议1秒。依赖失败、策略不一致及恢复窗口仍为503。重试建议不保证下一次成功，其他维度和并发请求仍可能限制。验证覆盖默认、收紧、非法值、跨实例不一致、最大恢复窗口、截止不缩短、误重放及真实恢复。

## 服务接入与故障边界

首个独立消费者由现有模板生成，以自己的 parent 或无 parent 通过新 BOM 引入 backend 适配，不复制 IAM。IAM 公开 HTTP 提供 `/api/auth/invitations/accept`、`/api/auth/login`、`/api/auth/logout`、`/api/auth/password`、`/api/me`，以及有操作权限的邀请、账号查询／状态／授权、审计入口；精确方法、请求、幂等和错误码在实施首步固定合同并由 Java/OpenAPI 同源校验。邀请不放 URL 查询串；注册与登录响应 no-store，不记录请求体。

内部当前状态接口与公开业务接口分开策略。TLS由服务原生终止，采用客户端证书可选、内部接口强制有效客户端证书的配置；证书校验包含可信链、有效期和固定服务身份到projectId／允许操作集合的映射，不信任客户端Header或只检查“有证书”。公开登录不要求客户端证书；内部调用必须使用mTLS。只有同项目已登记服务可请求授权检查。私钥与CA是部署必要输入，验证环境动态生成，生产不附默认私钥；本阶段不造证书签发平台。无密钥／CA／项目绑定时配置失败，不回退明文或共享默认密钥。

IAM 与其他应用都引用公共 backend，组件承担同一条“声明检查 → 完整事实解析 → 请求内可信上下文 → 原生注解执行 → 安全失败映射”管线。IAM 选择本地模式并提供 `CurrentSubjectSource.resolve(token)`，调用 CurrentAuthorization 校验正常原生会话与 SQL 许可；其他应用显式提供远程事实源。模式显式择一，不依赖 Bean 覆盖顺序或故障降级；组件不依赖 IAM 实现／实体／私表，也不拥有专用 HTTP 传输。IAM 不经 HTTP 查询自己，不创建远程客户端资源或要求远程 TLS 输入。

### 微服务调用与发现

2026-10-21 用户确认保留 Boot4，先整改 Nacos／Feign；暂缓 Undertow。沿用 Boot4.0.8／JDK21，固定 Cloud2025.1.3、OpenFeign／LoadBalancer5.0.3、Alibaba2025.1.0.0 和其管理的 Nacos client3.1.1；精确组合以最终依赖与真实运行验证，版本存在不等于组合已通过。

独立业务服务进程内的访问组件调用 `CurrentSubjectSource`，由基础设施中的 IAM Feign 适配通过 LoadBalancer 选择已发现实例，并直接 HTTPS 请求 IAM `/internal/access/current`。Nacos 提供注册与发现，不转发业务 HTTP，也不代替服务身份认证。共享薄客户端 `domain-forge-iam-client` 只依赖纯Java事实合同和原生调用库，不依赖 IAM 服务JAR；业务应用在 bootstrap 显式装配，不把 Feign／Nacos 放入领域和应用合同。IAM 保持本地事实源，只增加标准注册。

当前候选同步调用原生 Feign，使用原生发现、负载均衡、SSL bundle、HC5 连接池和阶段超时；Source 不再拥有额外执行器、Future 等待／取消或整体截止。唯一端点校验位于原生 HC5 delegate 执行前，覆盖 LoadBalancer 重建后的 URL 及 OpenFeign 原生 URL 配置解包 delegate 的分支；发送 Bearer 前须满足 HTTPS、GET、固定当前事实路径且无 userInfo／query／fragment。公开消费路径仍采用具名服务发现。调用方只向该客户端传递当前 Bearer，不全局透传；严格有限解码、项目绑定和失败拒绝保留。服务注册采用项目／环境隔离的 namespace／group，HTTPS 实例元数据和证书身份一致。注册中心短断可以使用原生缓存中的实例地址，每次仍访问 IAM 当前权威事实；不能将实例地址缓存误写成身份允许缓存。

Nacos 配置中心与服务发现独立，本批不扩动态配置治理。容器保留当前实现，必要请求大小／超时／TLS用原生配置，不在IAM增加专属容器安全机制；原生漏洞告警保留，换容器不作为漏洞或性能已解决的证明。

### 原生执行与组件装配

- IAM 删除 IamStpLogic，使用组件装配的正常 StpLogic；SaNativeSessions 注入同一实例，原生负责签发、解析、到期及退出。远程模式只保留内部身份读取差异，业务代码使用 CurrentAccess，不开放远程签发、会话管理或任意 token／loginId 查询。
- 权限／角色由唯一 StpInterface 桥接完整事实源，原生执行匹配、AND／OR 和 orRole；IAM 不复制公共请求缓存、默认拒绝或安全异常处理。本地事实源不反向调用 CurrentAccess，IAM 私有 tokenDigest／credentialVersion 不进入公共 DTO；公共和私有上下文均绑定实际 token。入口阶段每请求至多一次完整事实源／SQL 授权加载，敏感命令保留事务复核；原生 Redis 读取仍如实计量。
- 首版每进程由组件独占受管 `login` 类型。正常会话资源先独立建立，再通过方法参数装配事实源及管线，避免循环；原生 Spring 生命周期安装唯一逻辑／提供者，不在构造器替换全局对象。检查重复自定义定义、实际注册结果及上下文重建；框架静态默认对象不是冲突。确需进程级合成解析策略时由唯一所有者安装并验证，无法证明则停止此项，不能增加隐式 hook。
- 默认拒绝在原生执行前独立检查有效声明。支持方法／类／合成的 SaCheckLogin、SaCheckPermission、SaCheckRole，以及只由三者组成的 SaCheckOr；直接及嵌套 type 仅空值或受管 login。Basic／Digest／Safe／Disable 声明逐项拒绝，覆盖直接／合成／混合声明及 OR 嵌套分支，不依赖可变化的 handlerMap。只要求 Login／Permission／Role／Or 的必要原生处理器和关键解析／匹配策略完整，不冻结未使用且未支持的 handler。其他 type、空 OR／权限／角色拒绝启动；SaIgnore 仅表示明确匿名，不能与保护声明混合。匿名登录／注册仍执行自身防护／邀请规则。
- 可选 current 只把无身份变为空；匿名 hasPermission／hasRole 保持原生 false，check／注解的无身份及无效许可转 NotLoginException；权限／角色不足分别403。依赖故障独立503，不能被 OR 吞成另一个分支成功；组件执行和数据桥接边界的原生异常保留分类并脱敏，后续原生读取失效同样不能携带 token。公共 Advice 明确先于 IAM 兜底处理，IAM 只保留业务冲突、未知提交、登录429及脱敏兜底。此合同不改写宿主直接调用裸 StpLogic 时的厂商异常；应用入口使用公共当前身份，原生生命周期只在受控适配中处理，不记录原始凭证异常。
- IAM 的 StpUtil.getLoginId 等读取只表示原生会话，不能替代额外 SQL 许可。全部受保护入口及公共当前身份都须经过完整链，原生主体必须与许可主体相同；跨请求不缓存允许，入口修改凭证后不复用旧快照。新组合先证明本地／远程两模式、无环依赖、原生语义和 S2 故障矩阵，再迁移其余入口。

当前候选 HTTP 连接和 TLS 握手各默认300ms、原生响应／读取默认1秒、连接池20、池等待200ms；这些是原生阶段边界，不保证任意 DNS／发现／慢滴故障整次1秒或全过程最多20任务。不自动重试认证／写入调用。Redis连接与单命令300ms；SQL沿用现行池与语句边界，身份查询使用更短显式预算500ms。默认值与资源负载下的性能结论分别验证，不把它们升级为任意故障的生产SLA。无令牌／令牌失效401，权限不足403，格式400，业务冲突409，保护超限429，必要依赖不可用503，未知错误安全500；外部不泄露框架／SQL／凭据，内部保留脱敏原因。健康端点遵守已有运行安全责任，不自动以宽泛匿名策略放行管理端点。

### 当前HTTP合同

本切片具体状态／版本冲突沿用已批准方案的409；没有改变其他能力的通用业务拒绝合同。普通JSON继续使用既有 `code/message/data` 外壳。密码、邀请及登录结果均不缓存，请求JSON最多16KiB；本人接口不接受客户端主体ID。

## 使用路径

部署本项目PostgreSQL＋专用Redis → 配置服务证书／凭据和Nacos发现 → 运行迁移和显式初始化管理者 → 启动并注册两实例IAM → 管理者登录并发邀请 → 受邀者注册登录 → 消费者以Bearer经Feign调用受保护查询。部署运行及验证均复用有限本地脚本；本批只接入Nacos发现，不要求网关、邮件或GitHub执行资源。非Web初始化不启动HTTP或服务注册。

IAM是普通可启动Spring Boot服务：主类扫描本上下文，应用服务、仓储适配使用原生构造注入；只保留应用HTTP／服务端TLS、Mapper及安全资源生命周期的必要配置，公共访问机制交由组件。CLI以非Web上下文调用初始化用例并关闭上下文，不启动HTTP控制器或清理调度。四层内部仅按现有职责分包，不按每个用例建立一套四层。

部署变量与默认值以[实际服务配置](../../platform/services/iam/src/main/resources/application.properties)为准；数据库、Redis、指纹密钥、服务证书、信任库和项目绑定必须来自部署输入。初始化使用 `java -jar iam-0.3.0-iam.2.jar initialize-admin --login-name=<管理员登录名> --password-file=<私有密码文件>`；随后正常运行同一JAR。密码文件是初始化输入，不放入命令参数、仓库或日志；重复初始化不重置管理员。

独立服务通过BOM选择 `domain-forge-access-control-backend` 与 `domain-forge-iam-client`，在自身bootstrap显式导入 `BackendAccessConfiguration` 与 `IamClientConfiguration`；实际使用公开 `CurrentAccess`／`CurrentSubject` 或原生注解的源码同时显式声明相应直接依赖。声明IAM服务名、项目绑定、原生Nacos发现属性及客户端SSL bundle，不配置固定IAM URL；准确属性见本轮独立消费夹具。未声明访问策略的业务接口默认拒绝。消费者不导入IAM服务JAR、不持有IAM数据库或Redis凭据、不自建第二套会话和权限引擎。

当前原生Sa-Token默认每账号最多12个并发会话，新增登录达到上限会淘汰较早会话；它不等于账号禁用或SQL许可撤销。正常负载验证使用独立登录主体与固定授权主体，避免把预期会话淘汰误记为正常授权故障。退出、改密、禁用和撤权的现有生效合同保持。

完整本地产品检查使用 `./dev product --check all`，包含身份组件质量、独立消费、真实数据库／TLS与恢复场景。声明资源的性能另运行 `python3 -B platform/verification/iam/performance.py --code platform --output <本轮证据目录>`，前提是已构建当前JAR并固定JDK和Docker环境；检查结果不推导性能、CI或人工验收通过。恢复场景实际等待既定600秒窗口，性能正常负载持续300秒后单独观察突发拒绝与地址窗口恢复。
