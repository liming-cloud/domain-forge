# 身份权限首个切片设计

## 确认与范围

2026-10-22 用户确认职责收敛完整方案，授权 M1—M6 分步本地实施。当前结论替代旧 MIN／B0—B1 中相冲突的项目身份、证书、回执和审计恢复合同；旧候选事实仍由历史证据保存。确认来源和验收标准见[身份切片](../work/06-身份切片.md)。

IAM 是业务应用，复用访问控制与缓存组件；保留四层并按真实职责适度分包。SQL 在 XML／合法 MyBatis-Plus 链式调用；领域仅用 shared 纯 Java 标识。当前初始化、邀请注册、密码、防护、最小直接授权及管理者保全仍必须真实验证；完整组织／RBAC／菜单／数据范围尚不实施。原 IAM 人工拒绝不因方案批准解除。

## 战略边界与统一语言

对业务产品而言，身份是通用支撑能力：成熟认证、密码和会话机制复用现有框架，平台自行负责账号、邀请、授权、生效和审计规则。没有独立语义或发布压力，不拆认证／权限／组织等微服务。IAM 通过公开协议向本系统业务服务提供身份和授权事实；下游拥有自己的资源归属与业务规则，在有语义差异时于 `infrastructure/acl/iam` 翻译。双方不共享实体、表、会话键或服务实现 JAR。

| 术语 | 上下文 | 规范含义 | 不表示什么 | 别名 | 正反例 | 来源 |
|---|---|---|---|---|---|---|
| 账号 | IAM | 系统内稳定 AccountId 对应的登录主体，含状态、密码摘要及直接权限 | 员工、客户或组织成员 | 无 | 账号不等同于业务员工或客户 | 产品与总体架构 |
| 注册邀请 | IAM | 管理者允许指定登录名在有效期内自行注册一次的授权 | 已建好的账号或已认证自然人 | 邀请 | 使用后不能重放；仅知道登录名不能注册 | 3-D01 |
| 直接权限 | IAM | 账号可执行的有限操作码集合 | 对任意业务资源都有权限 | 无 | account:read 不等于 grant:manage | 最小授权范围 |
| 当前授权 | IAM／调用方 | 该次检查所见的有效会话、当前账号及权限；调用方再核对自己的资源 | 永久通行证或在途操作全程锁定 | 无 | 撤权提交后发起的新检查拒绝；此前已完成检查的在途请求不强制中断 | 既定生效原则 |

IAM 不拥有员工、客户、订单等业务服务数据；组织树和菜单树属于已确认完整 IAM 模型，B1 尚不实现。生成服务只验证真实身份查询调用，不新增演示业务聚合。权限码以 `iam:` 为命名空间；本单元目录固定为 `iam:invitation:create`、`iam:account:read`、`iam:account:state`、`iam:grant:manage`、`iam:audit:read`，未知权限不可分配。普通注册账号初始无管理权限，仅可登录、退出、改密及读取自己的最小资料；无默认组织、角色或租户。

初始管理员仅取得上述五项明确权限，不使用超级用户绕过分支或通配符。具有 grant:manage 的管理者只能分配自己当前持有的目录权限，不能借授权提升自身权限；变更用例在同一事务内重新核对当前操作者的有效依据和可分配集合。初始化命令不开放HTTP，凭据经交互输入或受保护文件读取，不放命令参数／日志；审计把来源标为受控部署命令，不把操作者自填名字伪装成已认证自然人。

账号、邀请、审计及外键采用 MyBatis-Plus 雪花 Long／BIGINT，HTTP 为十进制字符串；登录名推荐 ASCII 小写 `a-z0-9._-`、3—64 字符，按合同显式规范化，数据库唯一约束兜底，公开响应不泄露不存在／禁用／密码错误的差别。密码本单元采用 15—128 Unicode 码点，允许空白及 Unicode，不 trim、不截断、不隐式规范化，最多 512 UTF-8 字节；创建与修改使用同一规则并拒绝随制品提供的固定常见密码列表，列表版本及摘要可查，不调用第三方提交明文密码。本单元没有 MFA／找回密码；失去全部管理凭据的运维恢复另行设计，不能提供后门。

## 聚合、生命周期、DDD 与 CQRS

| 聚合根 | 成员 | 身份 | 受保护不变量 | 一致性边界 | 外部引用 | 跨边界协作 |
|---|---|---|---|---|---|---|
| Account | 登录名、状态、凭据摘要、有限直接权限、并发版本 | AccountId | 合法状态转换；改密撤销旧会话；权限只能来自目录；凭据不对外导出 | 单账号状态及授权修改，同一 SQL 事务 | 其他账号只用 ID | 注册创建；管理者保全规则通过同库显式协调 |
| RegistrationInvitation | 登录名、令牌摘要、期限、消费事实、创建者 | InvitationId | 一次消费、未过期、登录名绑定；不保存明文邀请令牌 | 邀请自身；消费＋建号明确使用同一数据库事务 | 创建者与生成 AccountId | 唯一约束与行锁保证并发消费 |

| 当前状态 | 命令 | 前置条件/守卫 | 不变量 | 下一状态 | 事件 | 非法原因 |
|---|---|---|---|---|---|---|
| 邀请未消费 | 接受邀请 | 摘要匹配、未过期、登录名可用 | 一次邀请至多一个账号，失败全部回滚 | 已消费＋账号启用 | 注册成功是业务事实；本单元无异步订阅方，不建事件总线 | 重放、过期、名称冲突 |
| 账号启用 | 禁用 | state权限；不移除最后一个持有全部五项管理权限的有效管理者 | 新授权立即拒绝；再次启用也不恢复旧会话 | 禁用 | 不发布集成事件 | 越权、并发冲突、最后管理者 |
| 账号禁用 | 启用 | state权限、版本匹配 | 不恢复禁用前会话 | 启用 | 不发布集成事件 | 越权或冲突 |

不为清单制造 DomainService、Factory、Specification 或空事件类。领域行为留在 Account／Invitation；仓储按真实一致性边界提供，不按每张表造 Repository。审计记录是审计事实，不冒充领域事件。没有真实外发事件消费者，本单元不引入 MQ／Outbox；未来需要可靠外发时另定同资源保存与重放合同。

命令路径：`interfaces/http → application/command → domain 行为＋仓储 → infrastructure/persistence`。事务归属应用，真实代理入口、checked 异常回滚及并发冲突必须验证。B1 保留“至少一个启用且持有全部五项管理权限的管理者”这一跨账号规则；可能移除最后管理者的操作与初始化在同库事务先锁唯一 administration_guard，再按固定顺序锁受影响账号。普通改密、邀请不因属于“管理”而共享该全局锁；仍须保留当前操作者资格、每账号锁和版本核对，并用真实并发验证移除全局锁后的授权时点。它是显式协调，不伪装成每个账号自己的不变量，也不引入分布式锁。

纯账号列表查询：`Controller → application.query.AccountQueries → infrastructure.query 单次投影 SQL → ReadView`，固定字段、参数绑定、白名单排序、最多100条、稳定键分页，不查询总数，禁止 N+1。身份及操作权限先由统一执行机制校验；因此“单次SQL”指该业务投影，不隐去在线授权 SQL。本人资料用当前可信主体限定 ID；存在资源决策的查询用例可以承担真实编排，不能允许客户端任意 ID 伪装为本人。Controller 不直接调 Mapper，应用不暴露 PO／Sa-Token／Redis／HTTP 客户端类型。

## 完整身份权限模型与后续实施

以下是已批准的 B2—B4 设计，尚未实施，不将原生角色机制夹具当成真实 RBAC 产品证据。B1 继续固定五项直接权限、当前最后管理者规则，真实账号角色集合仍为空。完整账号密码与邀请注册包括初始化、邀请失效／重发／一次消费、登录防护、退出、改密及跨实例生效；开放注册、短信／邮箱登录、找回密码、MFA、OAuth 和跨项目 SSO 不在本轮范围。

| 模型及所有者 | 关键规则与一致性边界 |
|---|---|
| IAM Account／RegistrationInvitation | 完整 RBAC 时 Account 不再保存直接权限集合；邀请消费与建号同库原子，无默认部门或角色 |
| IAM OrganizationUnit | 一套系统一棵组织树，节点以 parentId 关联；无环、根受保护。本节点及全部祖先启用才是有效部门；移动／停用后新检查取新归属 |
| IAM Membership | 账号可无部门、可属多部门；存在成员关系时恰一主部门。成员修改按账号协调；主部门只作默认展示，不改变范围起点 |
| IAM Role／账号角色关系 | 角色维护权限授予，分配关系只持 ID、不重复，无角色继承或组织自动授角；已分配角色先停用／撤销后再删 |
| IAM 权限目录／PermissionGrant | 服务发布命名空间内精确操作码与资源／范围语义，由有权管理员受控安装；未知码不可授予，不用通配符自动获得未来权限。每次授予将权限与范围绑定 |
| IAM MenuItem | 目录／页面／按钮树，无环、按钮不得作父节点；受保护页面和按钮关联真实权限。可见投影不授予 API 权限，直连仍由后端执行 |
| IAM 安全审计 | 保留必要变更同事务审计；关联行、DTO／PO 和技术记录不一律标聚合 |
| 业务服务自己的资源 | 员工、客户、订单等模型、资源归属、业务状态、查询过滤和写入约束；IAM 不拥有其实体、表或事务 |

组织使用邻接表与 PostgreSQL 递归查询，不并行维护闭包表、路径串和 Redis 树。删除有子节点、成员或自定义范围引用的节点时拒绝，先迁移／解除引用。组织停用只撤除由该组织归属产生的范围，不禁用账号或移除其独立角色；成员部门全部失效时不升级为 ALL。组织结构和成员／范围引用写入使用必要的组织协调与外键／条件更新，授权读取不占全局管理锁。

B2 引入受保护 SYSTEM_ADMIN，只显式拥有当前 IAM 管理权限，不默认拥有业务权限或 ALL。至少保留一名启用且有可用凭据的系统管理员，但没有本人密码证据时不保证其一定可登录。普通 CRUD 不能停用／删除／改码、撤必要权限或停用目录以绕过保全；目录升级用显式迁移。首版只有 SYSTEM_ADMIN 可修改组织、成员、角色、账号角色和角色范围，普通账号管理员不得自授角色或修改系统管理员安全属性；本人改密保持本人路径。B1 不提前替换现有五项管理语义。

数据范围支持 SELF、DEPARTMENT、DEPARTMENT_AND_DESCENDANTS、CUSTOM_DEPARTMENTS、ALL；NOT_APPLICABLE 仅适用于目录声明的非数据操作，不是 ALL。部门型范围以当前全部有效成员部门为起点；CUSTOM 只包含列出的有效部门，不隐含子树。按某个精确权限合并有效角色中该权限的范围，再与业务资源／状态条件相交；无匹配授权为空，解析失败不能放行。角色 A 的订单 SELF 与角色 B 的发票 ALL 不能组合成订单 ALL。ALL 仍限于本系统和该权限资源类型。

公共 current() 返回可信主体、角色和精确权限，scope(permissionCode) 按精确权限取范围；范围合同不含 SQL、字段名或自由表达式，范围事实源只在 B3 按实际调用增加。current 单次边界为 20 个角色、1000 个精确权限码和 256KiB；范围批量最多 32 项、每项 1000 个组织 ID、总响应 2MiB。超限明确失败，禁止截断后继续允许；B2—B3 必须按最大形状实测，不用 B1 旧规模证明新合同可用。

每次授权由主库单条 SQL／CTE 在同一语句快照中计算许可、账号、角色、权限、成员和组织有效性，不拼多个 READ_COMMITTED 语句制造混合授权图。范围响应与其主体、精确权限及校验时点绑定，不拼接旧入口角色。业务 Query 将可信范围映射为参数绑定 XML 谓词，列表、数量、分页、导出、单条与写入同样受限；写入还验证本地对象与状态。首版不建通用 SQL 拦截器、策略 DSL 或 DENY 引擎。

固定加锁顺序为“管理员保全（需要时）→组织协调（需要时）→幂等键→按 ID 排序的账号／角色／组织行”，具体用例在 B2 核验，不中途倒序补锁。只有真实订阅者出现时再设计领域／集成事件和可靠外发；事件、Outbox 或审计不能承担新检查立即生效。协议、SDK、BOM 及消费者输入成套演进，有旧客户端时显式版本化，不对严格解码端点无声加字段。

## SQL 与会话状态的生效合同

当前实证阻断：原生账号注销在删除失败后可能丢失终端索引；逐 token 注销虽通过该单点反例，仍不能据此删除 SQL 许可。两个独立 JVM 的真实账号行锁已证明正常签发、改密／禁用串行化，但原生 Redis 写入超时后迟到，仍可越过已释放的 SQL 锁、覆盖新终端索引，导致后续注销成功而新 token 有效。当前 SQL 许可与 credentialVersion 保留。详见当前任务的本地清单；验证探针不等于 IAM 生产调用顺序已切换。

目标为 Sa-Token 1.46.0 官方 Redisson DAO，共享 cache 的一个 RedissonClient；无自写 DAO。删除 SQL 会话许可和 credentialVersion 的条件是先通过原生部分失败与并发实证；未满足时保留旧实现，不宣称已切换。撤回历史 Redis 快照回放仍绝不复活会话的额外保证，恢复空会话后重新登录。

当前保留实现的实际顺序：登录在事务外校验密码并原生签发，再用短事务锁账号重新核对启用状态与已验证凭据版本、登记 SQL 许可，提交成功后才返回随机非共享 token。改密／状态变更提交 SQL 凭据版本；旧许可随后不再满足身份查询。退出仅先提交当前许可撤销，再尽力原生清理，清理故障计数，不恢复许可或假称 Redis 已回滚。权限从 IAM 主库当前事实读取，不缓存允许；在途已完成检查的请求不追溯取消。锁内原生签发／撤销是原探针候选，未切入生产，不能与现行实现混写。

行锁不能约束远端迟到命令。M2 必测双实例登录×改密／禁用、部分签发／撤销、响应丢失／重连和 SQL 提交失败。失败 token 不泄漏，未知结果不自动重试、不报告确定成功。若固定原生能力无法保持安全，停止依赖的删除步骤并提交最小替代设计，不静默放宽或新增双状态协议。

### 迟到写入最小处置提案

状态：2026-10-23 用户确认 **M2-L01—L04／M2-V01—V10，仅先执行本地组合安全验证**。保留 SQL 许可、生产 DAO 与签发顺序，暂缓纯登录绕过 IAM 和 M3 自动删 SQL；不改 CI 或写入人工验收，Git 操作遵循当前任务追加授权。确认与固定提案摘要见 `.run-artifacts/scaffold-realignment-2026-10-22/m2-composite/authorization.json`。源码、固定原生 JAR、官方资料摘要与评审保存在 `.run-artifacts/scaffold-realignment-2026-10-22/m2-late-plan/`，既有失败原文保留。

原反例是账号全部会话撤销探针：旧 Account-Session 的 SET 在客户端超时、账号 SQL 锁释放后才到达，覆盖新登录的终端列表；之后按该列表撤销会遗漏仍有效的 token。它不是“退出 A 必须同时退出后来登录的 B”的产品规则。当前生产 `Logout` 只撤当前 SQL 许可并调用原生 `logoutByTokenValue`；改密／状态变更依靠 credentialVersion。当前 IAM 打包仍含官方 RedisTemplate／Lettuce，Redisson 目标只在探针验证；此前 124 项运行通过不证明目标 DAO 已接入。

|---|---|
| 原生签发、按当前 token 注销及权限 SPI | 保留。已知 token 可直接操作其原生映射；不能把终端列表完整性当成额外安全保证 |

| 封禁、注销前监听器、延长超时／再加锁 | 不作为安全闭合依据。封禁不等于改密或单会话退出；监听器不提供跨存储提交或迟到写入隔离。原反例 retryAttempts 已为 0；等待或锁释放不证明远端旧命令已取消 |

| 自写 DAO、会话 CAS／代际／墓碑、第二套 token 索引或补偿状态机 | 本批不采用。会增加新的安全协议、写路径及恢复责任；升级依赖也不作为未证实的替代方案 |

## 默认登录防护及审计

账号规范化登录名 10 分钟最多 5 次失败／未完成校验，来源地址每分钟 30 次尝试；保持原子预占、成功只释放本次预占、同名不存在账号的同等响应与密码计算。Redis 不可用或容量失败拒绝；安全键 noeviction，不进入普通缓存或 L1。Argon2id 保持 m=19456KiB、t=2、p=1、16 字节盐、32 字节结果，默认并发 2／队列 8／等待 1 秒。计数键仍用 HMAC，不记录秘密。

关键管理变更与必要审计同库同事务，审计失败回滚业务；删除通用 operationId／回执／UNKNOWN 查询、人工补录、提交后独立补偿及其专用清理。SQL 提交不确定仍返回安全错误并读取业务事实核对，不自动重试。审计保留可信主体、业务 ID、动作、时间和脱敏摘要，不存原始密码／token／摘要。邀请一次消费、管理者保全、行锁和版本冲突继续验证。

## 服务接入与故障边界

会话由公共组件复用原生 Sa-Token；账号密码与当前权限事实归 IAM。失败不得转换为匿名或被 OR 备选吞掉。

### 微服务调用与发现

删除独立 iam-client 模块。调用服务自身 infrastructure 定义类型化 Feign＋Nacos，后端 HTTP，原生连接池与有限阶段超时；凭证仅传到该 IAM 接口，不跟随重定向、不自动重试未知写入。无项目匹配、SAN、SSL Bundle 或自写域名解析。

### 原生执行与组件装配

IAM 本地实现 StpInterface，其他服务实现本地 Feign 适配；access-control 不依赖 IAM、Feign、Nacos，不分本地／远程 StpLogic 子类。保留显式访问策略、遗漏拒绝与安全错误；删除框架内部类名和静态所有者形状检查。允许本次实际使用的原生类／方法权限与角色注解，不额外承诺组合注解或多上下文框架。

### 当前HTTP合同

GET /internal/access/current 只读当前 Bearer 本人，不接收任意账号 ID，返回账号 ID、角色、精确权限，无 projectId；仅检查登录与账号有效，不回调权限 SPI。纯登录检查无需 IAM HTTP；权限读取失败拒绝，同请求可绑定 token 复用一次，结束释放。外部 JSON 三字段结果保留；业务 ID 为十进制字符串。
