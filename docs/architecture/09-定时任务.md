# 定时任务

服务的定时任务统一经 `domain-forge-scheduling` 组件交给 PowerJob 调度：服务声明任务，组件在启动时登记，运维在 PowerJob 控制台修改周期、暂停或恢复、手动触发并查看执行记录，不需要重新发布应用。产品要求见[定时任务功能边界](../product/01-产品定义.md#定时任务功能边界)。

## 已确认的决定（2026-10-29）

| 问题 | 决定 |
|---|---|
| 框架 | PowerJob 5.1.7：独立调度服务端（自带控制台），存储使用现有 PostgreSQL；服务引入 worker |
| 执行语义 | 单点执行（同一任务同一时刻只在一个实例上执行，上次未结束不开始新的执行）、停机期间错过的触发不补跑、失败不自动重试（记录并告警，下个周期再执行） |
| 控制台权限 | 使用 PowerJob 自带账号体系（管理员 `ADMIN`），与 IAM 分离；控制台不对外开放，经覆盖文件在主机回环地址发布、SSH 隧道访问 |

## 执行语义（实测）

| 情况 | 表现 |
|---|---|
| 周期触发 | 按 Cron（带秒）触发，分派到一个在线 worker |
| 上次未结束 | 不开始新的执行：触发被跳过，执行间隔随之拉长，从不并发；实例已创建却无法开始时，执行记录为失败 `too many instances` |
| 服务端停机期间 | 错过的触发不补跑，恢复后从下一个周期继续 |
| 没有在线 worker | 执行记录为失败 `no worker available` |
| 执行失败 | 记录为失败（结果为异常类型），不重试；计数 `domainforge.scheduling.run{result=failure}` 并记录错误日志 |
| 手动触发 | 控制台填写的参数作为 `TaskRun.parameters()` 传入，同样受单点执行约束 |

任务因此必须可以安全地重复执行（例如按条件删除、按水位处理），也不能依赖某一次触发一定发生。

## 组件

| 部分 | 行为 |
|---|---|
| 任务接口 | 服务实现 `ScheduledTask`（任务名、初始 Cron、说明、`run`）并声明为 Bean |
| 分派 | 所有任务共用一个 PowerJob 处理器（Bean `domainforgeTaskDispatcher`），按任务参数中的任务名分派；每次执行开启新链路的根 span `task <任务名>`，日志带其 traceId（见[链路追踪](10-链路追踪.md)） |
| 登记 | 启动完成后按任务名查找，不存在才创建，执行语义固定为单机执行、最多一个实例、实例与子任务都不重试、启用；已存在的任务不改动，控制台修改的周期与暂停状态保持有效。服务端不可达、应用未注册或密码不符时启动失败 |
| 启用条件 | `domainforge.scheduling.enabled=true` 且为 Web 应用：服务的维护命令（非 Web）不会启动 worker。部署环境（`config-center` profile）声明了任务却未启用时启动失败 |
| worker | 只用 HTTP 通信（排除 akka、mu）、内存存储、工作目录 `/tmp/powerjob-worker`（容器中的服务用户没有主目录） |
| 指标 | `domainforge.scheduling.run`（标签 `task`、`result`）、`domainforge.scheduling.duration` |

## 部署

| 服务 | 说明 |
|---|---|
| `powerjob-db-init` | 一次性任务：建立 `powerjob` 账号与同名 schema（在 `domainforge` 库中，随 `backup.sh` 备份、`restore.sh` 恢复） |
| `powerjob-server` | 固定地址 `172.31.250.30`（对外声明给 worker）；PostgreSQL 必须使用 `AdpPostgreSQLDialect`，默认方言把大字段建成 `oid`，调度时报 `Unable to access lob stream`；执行记录保留 30 天 |
| `powerjob-init` | 一次性任务：创建命名空间 `domainforge`，按 `deploy/powerjob/apps.conf` 注册应用（共用 `POWERJOB_APP_PASSWORD`）；已存在的保持不变 |

- 控制台：`COMPOSE_FILE=deploy/compose.yml:deploy/compose.console.yml` 在 `127.0.0.1:${POWERJOB_CONSOLE_PORT:-7700}` 发布，经 SSH 隧道访问。
- 应用注册不在 PowerJob OpenAPI 中，`powerjob-init` 以控制台管理员身份调用控制台接口完成；任务登记用 OpenAPI（应用名＋应用密码）。
- 新增服务时在 `apps.conf` 登记（模板生成服务时自动追加）；已部署的环境重新运行 `powerjob-init` 即可（`up -d`）。
