# 身份权限模型

IAM 的边界、统一语言、场景、聚合与组织模型，以及为什么这样划分。接口、权限码、会话与授权合同见[身份权限参考](../reference/身份权限.md)；规则见[安全与访问控制](../rules/07-安全与访问控制.md)。

## 战略边界与统一语言

对业务产品而言，身份是通用支撑能力：成熟认证、密码和会话机制复用现有框架，平台自行负责账号、邀请、授权、生效和审计规则。没有独立语义或发布压力，不拆认证／权限／组织等微服务。IAM 通过公开协议向本系统业务服务提供身份和授权事实；下游拥有自己的资源归属与业务规则，在有语义差异时于 `infrastructure/acl/iam` 翻译。双方不共享实体、表、会话键或服务实现 JAR。

| 术语 | 上下文 | 规范含义 | 不表示什么 | 别名 | 正反例 | 来源 |
|---|---|---|---|---|---|---|
| 账号 | IAM | 系统内稳定 AccountId 对应的登录主体，含状态、密码摘要、角色分配与成员归属 | 员工、客户或组织成员 | 无 | 账号不等同于业务员工或客户 | 产品与总体架构 |
| 注册邀请 | IAM | 管理者允许指定登录名在有效期内自行注册一次的授权 | 已建好的账号或已认证自然人 | 邀请 | 使用后不能重放；仅知道登录名不能注册 | 3-D01 |
| 权限 | IAM | 权限目录中的精确操作码，只能经角色授予 | 对任意业务资源都有权限 | 操作码 | iam:account:read 不等于 iam:account:state | 权限目录 |
| 数据范围 | IAM／调用方 | 授予时与权限绑定的数据可见范围，按精确权限合并 | 业务资源本身的归属判断 | 范围 | 订单 SELF 与发票 ALL 不能组合成订单 ALL | 数据范围合同 |
| 当前授权 | IAM／调用方 | 该次检查所见的有效会话、当前账号及权限；调用方再核对自己的资源 | 永久通行证或在途操作全程锁定 | 无 | 撤权提交后发起的新检查拒绝；此前已完成检查的在途请求不强制中断 | 既定生效原则 |

|---|---|---|---|---|---|---|---|---|---|
| S01 系统首次启用 | 有可追责的初始管理者 | IAM | 初始化管理主体 | 显式运维命令、空初始化状态、安全输入凭据 | 只建立一次；两个进程竞争仅一个成功；不得重跑重置密码 | 初始化用例及数据库唯一守卫 | Account、初始化标记 | PostgreSQL、密码实现 | 集成测试 |
| S02 邀请和注册 | 受邀者自主获得账号 | IAM | 创建邀请、接受邀请 | 管理者当前有邀请权限；邀请未过期且绑定登录名 | 建号一个事务，账号记录所用邀请摘要；重复、过期、篡改拒绝，无半个账号 | RegistrationInvitation、注册用例 | 邀请、Account | PostgreSQL、密码实现 | 集成测试 |
| S03 登录及恢复 | 正常用户建立会话，过量尝试受限 | IAM | 登录、失败防护 | 真实密码、启用账号、保护状态可用 | 正确登录；通用认证失败；超限429；依赖异常503；恢复后重新验证凭据 | 登录用例、保护策略 | Account、原生会话 | Sa-Token、Redis、SQL | 集成测试 |
| S04 真实受保护查询 | 独立服务可取得允许查询的账号视图 | IAM＋业务服务入口 | 本人资料、账号分页查询 | 当前登录；目录查询另需 account:read | 允许、无身份401、无权限403；直连后端也拒绝越权；查询无写入 | IAM 权限及查询合同；消费者本地入口 | CurrentSubject、ReadView | backend适配、IAM公开API、SQL | 集成测试 |
| S05 授权／撤权／禁用 | 管理变更立即影响之后的新检查 | IAM | 角色授予、分配角色、成员归属、禁用／启用 | 当前管理权限、目标存在、版本匹配 | 成功后跨实例拒绝旧权限；禁止撤空最后系统管理员；并发冲突409 | Account、Role、系统管理员保全用例 | Account、Role、版本 | SQL、原生会话清理 | 集成测试 |

## 聚合、生命周期、DDD 与 CQRS

| 聚合根 | 成员 | 身份 | 受保护不变量 | 一致性边界 | 外部引用 | 跨边界协作 |
|---|---|---|---|---|---|---|
| Account | 登录名、状态、凭据摘要、角色 ID（≤20）、成员归属、并发版本 | AccountId | 合法状态转换；改密撤销旧会话；存在归属时恰一主部门；凭据不对外导出 | 单账号状态及授权修改，同一 SQL 事务 | 其他账号只用 ID | 注册创建；管理者保全规则通过同库显式协调 |
| RegistrationInvitation | 登录名、令牌摘要、期限、失效标记、创建者 | InvitationId | 未过期、登录名绑定、一次性凭据；不保存明文邀请令牌；“已使用”由账号上的邀请摘要推导 | 邀请自身；注册只修改 Account 一个聚合 | 创建者与生成 AccountId | 账号表邀请摘要唯一约束保证并发只成功一次；邀请行锁与重发互斥 |

| 当前状态 | 命令 | 前置条件/守卫 | 不变量 | 下一状态 | 事件 | 非法原因 |
|---|---|---|---|---|---|---|
| 邀请未消费 | 接受邀请 | 摘要匹配、未过期、登录名可用 | 一次邀请至多一个账号，失败全部回滚 | 账号启用且记录邀请摘要（邀请即视为已使用） | 注册成功是业务事实；本单元无异步订阅方，不建事件总线 | 重放、过期、名称冲突 |
| 账号启用 | 禁用 | state权限；非系统管理员不能禁用系统管理员；不移除最后一名启用的系统管理员 | 新授权立即拒绝；再次启用也不恢复旧会话 | 禁用 | 不发布集成事件 | 越权、并发冲突、最后管理者 |
| 账号禁用 | 启用 | state权限、版本匹配 | 不恢复禁用前会话 | 启用 | 不发布集成事件 | 越权或冲突 |
| 账号启用 | 改密 | 当前身份、旧密码匹配、新密码合规 | 新摘要提交与原生撤销遵守失败合同 | 启用／新凭据摘要 | 不以异步事件承担失效 | 旧密码不符或冲突 |

不为清单制造 DomainService、Factory、Specification 或空事件类。领域行为留在 Account／Invitation；仓储按真实一致性边界提供，不按每张表造 Repository。审计记录是审计事实，不冒充领域事件。没有真实外发事件消费者，本单元不引入 MQ／Outbox；未来需要可靠外发时另定同资源保存与重放合同。

命令路径：`interfaces/http → application/command → domain 行为＋仓储 → infrastructure/persistence`。事务归属应用，真实代理入口、checked 异常回滚及并发冲突必须验证。“至少一名启用的系统管理员”是跨账号规则；可能移除系统管理员的操作（禁用、改角色）与初始化在同库事务先锁唯一 administration_guard（顺序见[锁顺序](../reference/身份权限.md#锁顺序)）。账号自身的修改（登录登记许可、改密、启停、角色、成员）不加行锁，统一按读到的 `version` 条件更新（CAS），零行即 409；单行 CAS 防不住跨账号的写偏斜，因此“最后一名系统管理员”仍由管理守卫保证。普通改密、邀请不共享该全局锁；仍须保留当前操作者资格与版本核对，并用真实并发验证。它是显式协调，不伪装成每个账号自己的不变量，也不引入分布式锁。

纯账号列表查询：`Controller → application.query.AccountQueries → infrastructure.query 单次投影 SQL → ReadView`，固定字段、参数绑定、白名单排序、最多100条、稳定键分页，不查询总数，禁止 N+1。身份及操作权限先由统一执行机制校验；因此“单次SQL”指该业务投影，不隐去在线授权 SQL。本人资料用当前可信主体限定 ID；存在资源决策的查询用例可以承担真实编排，不能允许客户端任意 ID 伪装为本人。Controller 不直接调 Mapper，应用不暴露 PO／Sa-Token／Redis／HTTP 客户端类型。

## 完整身份权限模型

完整账号密码与邀请注册包括初始化、邀请失效／重发／一次消费、登录防护、退出、改密及跨实例生效；开放注册、短信／邮箱登录、找回密码、MFA、OAuth 和跨项目 SSO 不在范围内。实现合同见[身份权限参考](../reference/身份权限.md)。

| 模型及所有者 | 关键规则与一致性边界 |
|---|---|
| IAM Account／RegistrationInvitation | Account 不保存直接权限集合，权限只经角色授予；注册只新建 Account，邀请不被修改，无默认部门或角色 |
| IAM OrganizationUnit | 一套系统一棵组织树，节点以 parentId 关联；无环、根受保护。本节点及全部祖先启用才是有效部门；移动／停用后新检查取新归属 |
| IAM Membership | 账号可无部门、可属多部门；存在成员关系时恰一主部门。成员修改按账号协调；主部门只作默认展示，不改变范围起点 |
| IAM Role／账号角色关系 | 角色维护权限授予，分配关系只持 ID、不重复，无角色继承或组织自动授角；已分配角色先停用／撤销后再删 |
| IAM 权限目录／PermissionGrant | 服务发布命名空间内精确操作码与资源／范围语义，由有权管理员受控安装；未知码不可授予，不用通配符自动获得未来权限。每次授予将权限与范围绑定 |
| IAM MenuItem | 目录／页面／按钮树，无环、按钮不得作父节点；受保护页面和按钮关联真实权限。可见投影不授予 API 权限，直连仍由后端执行 |
| IAM 安全审计 | 保留必要变更同事务审计；关联行、DTO／PO 和技术记录不一律标聚合 |
| 业务服务自己的资源 | 员工、客户、订单等模型、资源归属、业务状态、查询过滤和写入约束；IAM 不拥有其实体、表或事务 |

组织使用邻接表与 PostgreSQL 递归查询，不并行维护闭包表、路径串和 Redis 树。删除有子节点、成员或自定义范围引用的节点时拒绝，先迁移／解除引用。组织停用只撤除由该组织归属产生的范围，不禁用账号或移除其独立角色；成员部门全部失效时不升级为 ALL。组织结构和成员／范围引用写入使用必要的组织协调与外键／条件更新，授权读取不占全局管理锁。

受保护的 SYSTEM_ADMIN 角色（固定 ID 1），只显式拥有当前 IAM 管理权限，不默认拥有业务权限或 ALL。至少保留一名启用且有可用凭据的系统管理员，但没有本人密码证据时不保证其一定可登录。普通 CRUD 不能停用／删除／改码、撤必要权限或停用目录以绕过保全；目录升级用显式迁移。首版只有 SYSTEM_ADMIN 可修改组织、成员、角色、账号角色和角色范围，普通账号管理员不得自授角色或修改系统管理员安全属性；本人改密保持本人路径。
