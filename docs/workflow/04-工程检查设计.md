# 工程门禁机制与支持边界

本设计规定第五层工程校准的入口、检查事实及支持边界，不定义产品模块。实际结果和未完成项见[当前任务](../00-文档导航.md#当前任务)。校准仅在相关规则、工具或 CI 变化及完整候选验收时执行；普通功能使用适用产品门禁，不重复测试无关上游工具。

## 工具选择与支持边界

| 责任 | 实现与唯一配置 | 边界 |
|---|---|---|
| Java 语法与 Javadoc 结构 | Checkstyle；[工具锁](../../harness/engineering_gate/tools.lock.json)及[注释配置](../../harness/engineering_gate/comments.xml) | 全可见性生产命名类型；不采用 Generated 或 Override 的默认免检 |
| 固定格式 | google-java-format；同一工具锁 | 使用 `--dry-run --set-exit-if-changed`，检查不改源码；不导入整套 Google 编码指南 |
| 类型与成员依赖 | ArchUnit 及[适配器](../../harness/engineering_gate/ArchitectureInventory.java) | 核对实际产物、类型来源、依赖、精确成员及解析完整性；不推断业务语义或动态访问 |
| 声明和使用位置 | JDK 公开编译器 API 及[方法适配器](../../harness/engineering_gate/MethodInventory.java) | 使用实际类型系统和源码位置，不自写 Java 解析器 |
| 构建观察 | Maven EventSpy 及[观察器](../../harness/engineering_gate/MavenScopeSpy.java) | 真实目标、源码、类产物、有效声明、原生解析图及类路径 |
| 执行环境 | 当前校准：Temurin 21.0.12.1+1、Python 3.14.5；工具身份由锁文件核对 | 不是产品版本选择；本地 Darwin 不证明 Linux／Windows 已通过 |

校准限定 Java 21 普通源码与类文件；默认单工程 JAR、普通 javac 类路径及 POSIX Wrapper。父工程、聚合、配置集、生成链、预览形式、替换编译器、fork／toolchain、自定义类路径、多版本输出及发布组合未实测时报告缺口，不静默排除，不把工具边界变成产品禁令。实际产品选定组合在使用前补适用验证，不建设通用语言证明平台。

依据：[Checkstyle](https://checkstyle.org/)、[格式工具](https://github.com/google/google-java-format)、[ArchUnit](https://www.archunit.org/userguide/html/000_Index.html)、[JDK 编译器 API](https://docs.oracle.com/en/java/javase/21/docs/api/jdk.compiler/com/sun/source/util/JavacTask.html)。资料不代替真实正反例。

## 注释与格式的限定校准

[源码入口](../../harness/engineering_gate/calibrate_source.py)处理显式输入；正式用途由[真实编译绑定](#真实编译范围与源码检查绑定)提供，调用方填写 production／test 不能证明实际用途。

| 入口 | 必须核对的行为 |
|---|---|
| `comments --purpose production` | 全可见性命名类型，包括嵌套、局部、匿名体内命名类型及 interface／record／enum／annotation；Javadoc 在全部注解和修饰符前；缺失、空正文、仅空标签及错位拒绝 |
| `comments --purpose test` | 不强制重复 Javadoc；已采用的 Javadoc 仍检查位置和基本正文 |
| `method-presence` | 对明确选择的方法／构造器核对说明，不默认跳过 Override、getter、短方法或紧凑构造器 |
| `format` | 固定排版只检查；整改通过且再次排版无新增变化，保留中文及正确注释位置 |

简体中文、职责准确性、关键行为、省略和文档继承的语义要求按[源码规范](../standards/04-源码质量.md#适用范围与阅读入口)评审，不以汉字检测或正文非空证明准确。不附加统一句号格式。

## 方法规模计量决策

采用圈复杂度和可执行语句数硬门禁；方法行数仅辅助可读性评审。定义与独立实现范围由[计量适配器](../../harness/engineering_gate/MetricInventory.java)和[配置](../../harness/engineering_gate/measure.xml)维护。

- 方法、普通／紧凑构造器、初始化块及真实 lambda 独立计量，嵌套实现不重复计入外层。零语句仍记录；表达式 lambda 的零值不证明表达式简单。
- 复用同一 Checkstyle AST 及决定点定义，补齐原工具未单列的 lambda 范围；分别保存原生 `tool_measurements/tool_coverage` 与适配 `measurements/coverage`，不冒充原生输出。
- switch 箭头不是 lambda；抽象声明、字段普通表达式、方法引用与数据字面量不虚构实现体。所选指标漏采以 `SG_METRIC_COVERAGE` 拒绝。
- `measure` 只采集；其零／负一上限不是质量阈值。`limits` 比较显式试验上限，标为 `explicit-candidate-limits-only`，不产生正式通过。
- [计量回归](../../harness/engineering_gate/test_source_probe.py)验证循环、switch／模式守卫、catch、逻辑与／或、三目、同行／嵌套、零值及边界整改；关闭计量后必须因覆盖缺失拒绝。长表格不因行数成为硬违规，顺序操作仍受语句上限约束。

## 初始上限与校准边界

有效上限只维护于[复杂度配置](../../harness/engineering_gate/complexity.json)，批准来源见[唯一规范](../standards/04-源码质量.md#已确认的复杂度门禁)。生产、测试主体、夹具及辅助逻辑分别校准，不默认放宽测试；当前没有超限例外。

正式 `complexity` 入口只读取该配置，不接受命令行上限覆盖；缺失、重复／未知字段、范围不完整或非正整数拒绝。报告保存配置字节、用途、计量及覆盖，限定为 `approved-complexity-subset-only`。

[数值回归](../../harness/engineering_gate/test_complexity_baseline.py)对生产和测试分别验证两项指标低于、等于、超过正式基线及整改，保留长数据辅助值和漏采拒绝。数值只触发质量审阅，不独自证明职责正确；不得为当前代码通过擅自提高上限、碎片化职责或删减断言。

## 用途与合同识别的落实方案

使用一份集中模块声明与真实构建／类型依赖核对，不由目录名、public、getter 名称或自报用途决定覆盖。只登记真实模块包根、允许依赖及精确合同，不制造空四层、镜像 DTO、入口接口或额外 Maven 模块。

生产／测试取实际编译目标；模块归属取源码包声明与产物来源；合同取已审阅的类型及精确成员。公开输入输出的数据类型通过同一声明的 `data_contracts` 登记，须为 `contract_types` 子集；不把服务对象内部状态当作输出字段。数据角色与登记完整性由源码和消费场景评审，声明本身不证明边界合理。关键内部行为、省略依据、业务归属和公开范围也需语义评审。

## 字节码与直接合同的限定校准

[显式入口](../../harness/engineering_gate/calibrate_architecture.py)接收 schema 1 模块声明和显式类目录，只证明该输入的机械约束。

- 声明包含模块 ID、唯一包根、用途、允许依赖、合同类型及成员，可选 `data_contracts` 登记数据合同；缺失、未知字段、重复或越界数据声明、重叠归属、空目标和不存在合同拒绝。
- 全部显式类文件与 ArchUnit 导入逐项一致，包含嵌套、局部及匿名实现；空／重复目录、同名类型、符号链接、损坏和未解析类型拒绝。模块／包描述文件不静默排除。
- 未声明引用、生产引用测试、依赖环、非合同类型及越界成员访问拒绝。构造器、字段、方法引用与精确签名核对；泛型／数组及直接声明类型纳入公开范围。
- 继承访问同时核对符号目标与实际声明者，不要求复制方法；成功导入的桩不能当作完整类型信息。
- 从精确签名及已登记数据根展开可达自有数据类型的实例字段、泛型与继承，包含私有字段，保留违规路径并防环；不递归展开外部 SDK 的内部实现或服务私有状态。所有可达自有类型须满足公开合同边界。

[架构正反例](../../harness/engineering_gate/test_architecture_probe.py)验证目标诊断及新工程整改。类型与泛型观察复用 [ArchUnit](https://www.archunit.org/userguide/html/000_Index.html)，不自研 Java 解析器。报告保留实际类文件、声明、适配器、工具与运行时摘要；`source_ownership_proven/build_proven/contract_closure_proven` 为 false。未登记或动态序列化成员、外部 SDK 闭包、发布用途及语义完整性不由此证明。

## 真实 Maven 编译范围校准

[范围入口](../../harness/engineering_gate/calibrate_maven.py)固定执行真实 `test-compile`，复用 EventSpy，逐项核对成功目标、维护源码、编译器输入清单、类产物及实际类路径。生产／测试取 `compile/testCompile`，不看文件名或 src/test；同包测试不另建业务模块。

[Maven 工具锁](../../harness/engineering_gate/maven-scope.lock.json)固定发行、插件及摘要；准备只写仓库外专用空目录，不覆盖损坏输入、不清理已有输出。准备实际解析固定资源和编译插件，再执行同一环境预检，保存原生命令及 `prepare.log`；分发下载成功不能代替插件就绪。[范围回归](../../harness/engineering_gate/test_maven_scope.py)覆盖全新目录准备与插件缺失拒绝、合法资源目录、含 test 的生产根、局部／匿名产物及排除、跳过、未归属、额外产物、真实失败、陈旧输出和缺环境。失败保存退出码、具体文件差异和 `target/maven-scope.log`。

报告为 `observed-maven-compilation-scope-only`；语义用途、测试执行、发布、框架入口和独立消费未证明。

## 真实编译范围与源码检查绑定

[源码联合入口](../../harness/engineering_gate/calibrate_maven_source.py)在无输出隔离工程重新编译，内部绑定真实范围与源码检查，不接受外传用途、文件清单或历史报告。

- 全部实际输入执行适用类型 Javadoc 结构／位置与固定格式检查；测试不强制重复说明。
- 同一语法树清单按实际用途执行正式数值基线。无显式实现时仍先校验基线并查注释和格式，复杂度明确不适用，不伪造零值或让独立计量接受空扫描。
- 输入、产物、配置、工具及环境前后核对；规则问题汇总文件、位置、用途及目标，不因第一项失败省略其余已接入检查。

[绑定回归](../../harness/engineering_gate/test_maven_source.py)验证合法同包测试、声明文件、非 public 生产类型、错位说明、格式／数值、零实现坏基线及输入覆盖尝试。报告为 `observed-maven-source-subset-only`，不证明方法语义、关键内部行为、省略合理性、发布或人工验收。

## 真实编译与模块合同绑定

[架构联合入口](../../harness/engineering_gate/calibrate_maven_architecture.py)重新执行真实 Maven、JDK 语义分析及 ArchUnit。schema 2 声明使用 `id/package/depends_on/contract_types/contract_members` 和可选 `data_contracts`、`critical_methods`，不接受 purpose、旧 schema、整包公开或其他字段。

- 合同属于实际生产编译的公开类型及精确成员；测试合同、缺失对象和返回类型漂移拒绝。
- 实际产物集合、来源 URI、源码包声明及 SourceFile 共同唯一绑定维护源码；支持同文件多类型、不同包同名文件、局部及匿名类型，不截外层类名猜测。缺来源、无类型产物或重复二进制名明确报告缺口。
- SDK 解析仅用同次成功编译的原生类路径、用途、专用仓库对象及字节快照；缺失、重复、用途冲突、越界和依赖漂移拒绝。第三方类型不混入自有模块。
- ArchUnit 使用仅含实际产物、依赖及 JDK 的隔离解析上下文；延迟解析也不得借用工具自身同名库。
- 依赖、签名和实际继承声明者的来源必须属于本次产物、已观察依赖或 JDK。JAR 来源用原生 JarURLConnection 提取；清单引入的未观察类型即使可解析，仍以 `SG_DEPENDENCY_ORIGIN` 拒绝，不自动补入证据。
- 数据图沿用上述字段闭包及来源检查；`payload_field_closure_checked` 仅表示已登记图的机械检查，不证明数据角色或运行期序列化完整性。
- 无 debug 来源信息、编译属性越界和无法解析类型不能当作零违规；与默认相同的显式配置允许。

[联合回归](../../harness/engineering_gate/test_maven_architecture.py)按合同、用途、来源和类路径固定分组。报告为 `observed-maven-architecture-subset-only`；`source_bindings_complete/module_ownership_bound/declared_contracts_bound` 仅表示机械关联，完整合同闭包、框架动态入口、发布和语义审阅未证明。

## 源码依赖声明与能力入口校准

复用[依赖核对](../../harness/engineering_gate/dependency_declarations.py)、JDK 语义树及 Maven 原生依赖身份，不增加另一套依赖解析器。

- 实际源码的限定名、导入、源码保留期注解及内联常量绑定到消费者、实际用途、来源 JAR 和坐标；具名／通配静态导入及继承成员保留公开入口，不反推 SDK 内部实现库为用户直接引用。
- 根节点直接依赖与有效声明一致；缺失、矛盾及错误归属拒绝。`system` 用途含属性解析和未使用声明均以 `SG_BUILD_DEPENDENCY_PATH` 拒绝，正常坐标在新工程整改。
- [能力关系基线](../../harness/engineering_gate/maven-lifecycle.lock.json)只登记精确入口、所承诺 API、版本键及用途。当前 JUnit 普通／参数化 API 为校准正例，不是产品选型；测试入口不许可生产，BOM、starter 名称和普通传递库不自动豁免。
- 未校准的官方入口或版本组合报告校准缺口，不误称编码违规；纳入新组件时依据官方承诺及真实正反例校准一次，不逐需求添加豁免。

[依赖回归](../../harness/engineering_gate/test_dependency_declarations.py)覆盖入口／版本、源码／继承、用途／输入，坏配置在构建前拒绝，纯构建机制关联不能遗漏。`dependency_declarations` 保存实际引用与依据；不证明运行期反射、生成链、官方承诺语义或完整源码门禁。

## 默认职责与技术注解校准

[职责入口](../../harness/engineering_gate/calibrate_roles.py)复用同次构建、绑定、合同与依赖观察。schema 3 增加 `kind`：context、component、assembly；默认业务上下文根据真实包声明定位 interfaces/application/domain/infrastructure，组件和装配不强套四层。

- 方向：领域→领域；应用→应用／领域；入口→入口／应用／领域；基础设施可连接这些职责。允许层次方向不豁免跨模块合同和允许依赖。
- [职责基线](../../harness/engineering_gate/role-boundaries.lock.json)登记 Boot 4 方向所需的 Spring 7 类型校准、有限装配／事务注解、枚举关系、技术客户端及已验证通用 API；不按框架整组放行。未知 API 或版本以 `SG_ROLE_CALIBRATION` 报缺口，Spring 类型检查不证明 Boot 及其他组件组合已运行。
- JDK 输出实际所属二进制类型和使用位置；去重包含消费者与位置。注解许可不包含同一类型的类字面量、客户端操作或静态导入枚举后的方法调用。
- 领域拒绝已校准框架绑定及 JDK SQL／数据源／HTTP 客户端；自定义组合注解沿真实源码关系追溯并防环。内联 SQL 常量虽从字节码消失，仍关联领域消费者。
- 私有、局部及匿名实现按实际职责检查；必要应用装配／事务元数据允许。修改 kind 标签不能证明职责合理。
- 技术库按实际 Maven 坐标及精确版本分类，技术与通用身份不得重叠；未知组合报告校准缺口。MyBatis-Plus core／annotation 3.5.17 与 dynamic-datasource-spring 4.5.0 属隔离校准，不作为完整产品组合证明，不泛化到未验证模块；`@DS` 不能作为应用装配元数据放行。
- 业务上下文公开签名与已登记数据图不得暴露已校准技术类型或基础设施类型，包括私有字段、泛型和继承路径；基础设施内部的 Mapper、Wrapper、IPage 和映射注解允许。技术库不能借允许应用装配元数据的规则获得许可。

[职责回归](../../harness/engineering_gate/test_role_boundaries.py)固定策略、元数据使用、归属和输入四组，缺失／矛盾观察拒绝。[持久化边界回归](../../harness/engineering_gate/test_persistence_boundaries.py)用真实 MyBatis-Plus 依赖验证应用继承、非公开领域映射、公开数据字段及合法基础设施用法；依据 [官方模块说明](https://baomidou.com/getting-started/install/)与 [CRUD 接口说明](https://baomidou.com/guides/data-interface/)确定技术身份。报告保存 `role_bindings/role_scope/role_boundaries_checked`；不证明外部注解内部语义、动态入口、真实 Bean 装配、代理、自调用、数据库、回滚或跨库原子性。

## 实际合同方法与源码说明

[方法核对](../../harness/engineering_gate/method_contracts.py)只检查同次真实生产合同的精确方法／构造器，不将全部内部访问器或同包测试一律改成必写注释。

- JDK 原生类型系统解析同次维护源码，路径限实际类路径与 JDK，禁用处理器、隐式加载及类生成。二进制所属类型、擦除签名、参数和结果与 ArchUnit 精确匹配，覆盖隐式 public 接口方法、数组／可变参数、泛型、嵌套及显式紧凑构造器。
- 选中成员必须关联实际显式声明和源位置，不能借另一个重载的说明或虚构隐式成员。
- DocTrees 核对有效正文与解析错误，复用 Checkstyle 核对所有已采用 Javadoc 的位置。注解后的说明不能当作缺省继承而放行。
- 覆盖关系由类型系统识别；缺少自身说明或使用 inheritDoc 时，须定位本次源码中唯一有效来源。仅 Override／继承标记、无来源及降低既有合同可见性拒绝。
- 外部源码说明、多重有效继承来源、生成成员及不符分析环境的扩展未完整支持时报告缺口，不强迫合法产品改写设计。

## 原生访问策略校准

[访问入口](../../harness/engineering_gate/calibrate_access.py)的 `--policies` 接收独立校准合同，由[条件核对](../../harness/engineering_gate/sa_policy_contracts.py)绑定同次实际注册、原生解析与真实 HTTP；不是产品配置格式或新策略语言。没有该合同的旧凭证校准仍只证明渠道，不产生策略通过事实。

- 独立文件固定 `schema: 1`、`entries`；每项声明 `path/method/kind/conditions/cases/login_witness`。条件支持默认账号体系的原生登录、AND／OR 操作权限；实际条件与独立预期逐项比较，权限顺序不改变结果。原生处理器被移除或替换、其他未校准条件须报告缺口，不降级为仅登录或改成产品禁令。
- [原生观察器](../../harness/engineering_gate/SaAccessInventory.java)从实际映射取得处理器，以应用实际采用的 `SaAnnotationStrategy` 解析其声明类及方法，不搜索注解文本或由场景反推扫描范围。`SaIgnore` 按原生优先语义形成匿名策略，类与方法条件共同核对；匿名范围仍须评审。
- 合法类级、继承及组合声明须实际可用。组合夹具由应用通过原生公开解析扩展委托 Spring `findMergedAnnotation`；工具不安装解析器，不将该扩展冒称 Starter 默认行为。未安装扩展且未执行组合权限的对象须拒绝并整改。
- 匿名场景不携带身份；登录策略验证有效 Header 成功及匿名 401；操作权限策略还须验证缺权限的有效身份得到 403。该身份在同次仅登录入口的成功请求作为见证，不能用失效令牌或另一主体冒充。上述状态只用于限定夹具，不替代产品错误码及接口合同设计。
- 实际入口、有效策略和独立合同完整对应；遗漏、空权限、条件漂移及删除／伪装拒绝场景不能通过。受保护入口失去全部声明时，用匿名和有效身份请求核对默认拒绝，同时策略覆盖仍失败；一律拒绝合法访问不能形成通过。
- 原接口及生成合同采集完成后，通过原生 MVC 注册／清理一个工具拥有的临时未声明探针，以匿名和已在同次真实入口成功的 Header 请求它。探针没有鉴权、业务数据或产品接口职责；路径唯一，类型位于被测业务包但独立编译，不声明组件、不进入原 Bean 装配，不覆盖应用类，也不改源码、拦截器或策略。核对两次真实 403 和首次分派，不能用 404、前置失败或现有声明齐全推定默认拒绝；只删除默认拒绝、保留全部正常声明也必须失败。

## 访问控制具体适配

[具体入口](../../harness/engineering_gate/calibrate_access_state.py)补齐限定注解与内存会话之外的第五层访问校准。[合成应用](../../harness/engineering_gate/AccessStateFixture.java)复制到仓库外干净 Maven 工程，由[独立观察器](../../harness/engineering_gate/AccessStateInventory.java)启动三个真实 JVM；同项目两实例使用同一 Redis 库，另一个项目使用另一库。应用通过实际 PostgreSQL 取得账号、角色、权限、资源和审计，使用成熟 Argon2id 校验与原生 Sa-Token Redis DAO；观察器不替应用补登录、授权、状态写入或审计。

[组合锁](../../harness/engineering_gate/access-state.lock.json)固定 Redis 8.8.1 镜像摘要、`sa-token-redis-template`、Spring Data Redis 4.0.7 与 Lettuce 6.8.2.RELEASE；Sa-Token 1.46.0、Boot 4.0.8、Spring 7.0.9、PostgreSQL 18.4／JDBC 42.7.13 和密码组件沿用已有锁。实际应用类路径必须包含匹配依赖，独立工具目录不能补应用缺失；实际 DAO 类及来源、连接工厂、库号、项目、注册入口、JDBC 元数据与同次编译分别核对。只支持此限定原生组合和本地临时容器，未校准形式保持缺口。

独立 JSON 仅含 `schema: 1`、`application`、`profile`；不允许配置期望值、任意 SQL 或省略固定场景。[场景适配](../../harness/engineering_gate/access_state_scenarios.py)固定以下八类合同，详细正反例由[分组回归](../../harness/engineering_gate/test_access_state.py)运行：

| 场景 | 独立观察与拒绝条件 |
|---|---|
| session／expiration | 真实账号登录、跨 JVM 读取、进程重启、登出、Redis 键及原生过期、另一项目隔离；内存 DAO、错库、未登出和错误 TTL 拒绝 |
| authorization | 真实操作权限、资源归属、范围内／外单资源与列表、条件写入及全部资源行值；客户端自报主体／范围无效，漏范围、漏归属、读权限冒充写权限拒绝 |
| changes | 已登录主体在禁用、权限／角色撤销和范围缩小报告完成后的新请求，两实例均读取新状态；旧权限、旧角色、禁用后继续通过拒绝，另一项目仍可访问 |
| password | 两个独立旧会话包括执行更改的会话全部失效，新密码可登录、旧密码拒绝；实际摘要变化及其他账号／项目不受影响，单独保存密码不能证明完成 |
| failures | 暂停本轮 Redis、账号查询失败和恢复；在真实密码 UPDATE 等待期间制造 Redis 故障，数据库提交但撤销未完成必须报告依赖失败，不能借审计容错报告完成 |
| throttle | 真实登录的默认限制、交替实例、其他账号／项目、窗口恢复及合法调整，两实例并发竞争同一限额；恢复后错误密码仍拒绝，未知依赖状态不放行 |
| audit | 安全写入及真实记录的可信主体、对象、动作、结果和时间；审计表故障不回滚已生效变更，必须表达缺失并独立告警；人工补录只记录当前可核对事实，缺失原始主体／时间保持未知 |

合成选择仅用于可重复校准：两个固定项目、Redis 库 0／1、账号与部门范围、三次／两秒窗口、可调一至五次、120 秒会话及过期场景的一秒会话、固定 JSON 401／403／429／503 分类。它们不选定产品阈值、锁定策略、密码接口、审计存储、公开配置或部署算法；普通用户误触限制、恶意触发及生产负载仍须第六层能力设计。合成数据库使用项目字段隔离，Redis 使用库号隔离；物理部署方式没有据此确定。

## 持久化具体适配

[具体入口](../../harness/engineering_gate/calibrate_persistence_adapters.py)由 `calibrate_persistence.py --project ... --adapters ... --connections ...` 调用，复用前节的真实构建、版本、隔离资源和输入绑定。分页明确引入 MyBatis-Plus 同版本 `mybatis-plus-jsqlparser`，解析器固定为 5.2；版本与准备仍由同一[持久化锁](../../harness/engineering_gate/persistence.lock.json)管理。迁移分支还直接核对实际应用的 `spring-boot-flyway`、`flyway-core` 和 `flyway-database-postgresql` 与迁移版本锁一致；独立工具目录的版本不能替应用证明依赖完整。

独立 JSON 使用 `schema: 1`，包含 `application`、`bean`、`factory`、`datasource`、`manager` 和 `profile`。五种 `profile` 对应下表固定合成合同；方法、场景序列和预期关系由校准入口定义，不允许调用方删除场景或填写当前结果作为期望。它是第五层具体适配合同，不是任意 SQL 测试 DSL 或产品字段规范。

| 合同 | 实际执行与验收依据 |
|---|---|
| `mapping` | `numeric(6,2)` 与 BigDecimal 的边界、正负半入舍入和超限拒绝；LocalDate、LocalDateTime、OffsetDateTime 的日期、本地时间和微秒时间点；空值、存储枚举和重建后的行为；数据库返回 ID、插入后回滚产生的序列间隙。核对 Java 往返、真实列类型／精度及每步独立查询结果 |
| `pagination` | 原生 PostgreSQL 分页插件、关联分组的真实 COUNT 与稳定记录排序、范围内外数据、绑定的恶意形状值、空页及负数／超量拒绝。本合同最大页长 2 仅用于有限夹具，不是产品全局配置；自定义查询结果不暴露 IPage |
| `concurrency` | 两个不同数据库会话中的实际 Read Committed 事务读取同一旧版本后竞争；原生版本插件只允许一个更新成功，检查真实行数、版本回写与落库。自定义条件更新、同值更新和未匹配分别解释；两个事务竞争唯一键，由数据库决定一个成功、一个冲突 |
| `batch` | 原生 BATCH 会话在一个应用事务中按 2 条分批，3 条总量上限；读取实际刷新计数，不累计受理哨兵。首批已刷新后的主键冲突和延迟约束的提交失败均须整体回滚；数量超限在写入前拒绝 |
| `migration` | 两个别名各有 Flyway Bean、扫描路径与真实历史；校验空库、保留已有数据的重启／升级、第二源升级失败以及恢复。第一源已经提交不会因第二源失败回滚；失败源的事务性脚本回滚后，用更正的未应用脚本恢复，不能调用 repair、clean 或重写已应用脚本 |

`migration` 还要求 `phase`（`initialize`、`restart`、`upgrade`、`failure`、`recovery`）及按 `master`／`inventory` 分别声明的 `migrations`，每条包含固定版本资源路径及独立 SHA-256。入口核对维护 SQL、实际生产资源、原生 Flyway 物理来源、校验结果、执行历史、结构和保留数据；相同字节从错误位置扫描也不能证明声明来源正确。失败阶段额外从原生 `FlywaySqlScriptException` 绑定失败脚本的实际资源与独立摘要，无关启动异常即使 SQLSTATE 相同也不算迁移回滚证据。

[观察器](../../harness/engineering_gate/PersistenceAdapterInventory.java)仅启动真实应用、调用固定操作、透明记录 Executor／StatementHandler／批次刷新和独立读取两个目标；不安装分页、版本或事务实现，不替应用执行 migrate。并发记录按线程隔离，实际物理连接、Executor 逐次影响行数及提交后的独立状态是结果依据；应用固定返回不能掩盖原生零行结果。公开报告只返回状态、计数、类型化诊断及输入摘要，不包含 SQL、行值、调用返回或凭据。

[应用夹具](../../harness/engineering_gate/PersistenceAdapterFixture.java)和[迁移夹具](../../harness/engineering_gate/PersistenceMigrationFixture.java)只复制到仓库外干净工程。`persistence-gate` 运行同一启动应用从两个空库迁移到实际 Mapper 路由、提交与回滚的组合正反例；五类详细反例由[独立分组](../../harness/engineering_gate/test_persistence_adapters.py)执行。技术隔离沿用已有边界校准；字段含义、查询范围合理性和任意业务模型转换仍由实际源码及场景语义评审承担，不用合成对象替代产品业务模型。

## 真实 Wrapper 构建生命周期校准

[生命周期入口](../../harness/engineering_gate/calibrate_lifecycle.py)固定在无输出隔离工程执行 `mvnw verify`；不接受任意目标或跳过参数。Surefire、JAR、JUnit 等校准版本只维护于[生命周期锁](../../harness/engineering_gate/maven-lifecycle.lock.json)，不是产品版本基线。

观察器汇总各成功目标的请求、阶段、有效声明、项目／插件类路径、原生约束和主产物，不只取会话末集合。项目约束用原生 DependencyResolutionResult，插件约束用成功 RepositoryEvent 请求链；逐项核对坐标、版本、扩展名、分类及文件摘要。固定最终版本不能掩盖生效范围或时间戳快照。只输出必要身份，不导出任意属性、认证或环境。

必需测试合同独立于当次发现结果：`{"schema":1,"required_tests":["包名.测试类#方法名"]}`。固定字段、非空、唯一且纳入输入摘要。Surefire XML 须对应实际编译测试类，计数与用例一致，无失败／错误／跳过，覆盖全部必需测试；允许额外合法测试。清单充分性和断言准确性仍须评审。

| 必须核对 | 原生成功仍须拒绝的目标反例 |
|---|---|
| 固定运行时、核心字节、编译目标及必需插件 | 版本／编译目标偏离、必需目标移出生命周期 |
| 真实编译与必需测试 | 漏选、无发现、跳过、禁用、忽略失败；原生编译／断言失败保留原始非零 |
| 有效声明与原生解析约束 | 直接／传递范围、快照、缺图／漏项／错误归属、机器 JAR |
| 本次主 JAR | 对照全部生产类名称、字节及嵌入坐标，部分漏类拒绝 |
| 固定输入 | 陈旧输出先拒绝；工程、脚本、合同、工具及环境前后变化失效 |

[生命周期回归](../../harness/engineering_gate/test_maven_lifecycle.py)固定执行、测试覆盖、产物、版本基线、依赖解析、输入六组。隔离依赖用临时命名空间，经真实 Maven 解析；整改用新工程，不覆盖失败现场或用户缓存。报告为 `isolated-wrapper-verify-lifecycle-only`，不证明产品发布、重打包、动态测试名或插件动态运行库完整性。

## 真实 HTTP 消费具体适配

[消费入口](../../harness/engineering_gate/calibrate_http_consumer.py)通过 JDK HttpClient 请求真实 Boot Servlet，独立期望核对成功、空数据、HTTP 200 业务拒绝、受理、部分完成、协议失败、身份失败、服务故障、畸形 JSON、未知业务码、超时和重定向。HTTP 状态与完成状态分别保留；受理／部分结果保留查询信息；已产生一次副作用的超时不能触发自动重试。计数按有限结果类别，不能只计 HTTP 2xx。

下载、事件流和运维数据按各自协议核对；当前消费夹具验证 AB 字节和完整 SSE 事件内容，Servlet 观察器会缓冲响应，不声称增量到达、心跳、背压或任意二进制消费完整性。原生 HTTP 合同入口仍承担独立原始二进制结构检查。可信观察器固定在工具目录；外传夹具不能替换观察器。原始响应头／体、原生进程输出均检查本轮已知合成凭证及单层标准 Base64 包裹，失败诊断不回传原始日志；不声称任意未知编码识别。[正反例](../../harness/engineering_gate/test_http_consumer.py)覆盖目标误接受与整改。

## 运行装配与权威配置具体适配

[运行入口](../../harness/engineering_gate/calibrate_runtime.py)绑定实际 Spring Boot 条件装配，验证未启用无需输入、默认实现、必要输入缺失、显式不支持实现不回退、用户覆盖及多实现冲突；无关能力仍可调用。默认实现通过原生自动配置的后置条件生效，不靠观察器装配或偶然加载顺序。

## 原生观测具体适配

[观测入口](../../harness/engineering_gate/calibrate_observation.py)用 OpenTelemetry Java SDK 实际产生日志、指标和链路，经受限 JSON 导出器送至回环 HTTP 接收端。该传输仅供校准，不是产品 OTLP 或观测平台选型；原生 SDK 版本由运行锁固定。原生父子 span、日志关联、服务／版本／项目／环境身份与有限结果维度均从实际接收数据核对，子节点数量与完整关联不能因改名而漏检。累计指标取同一原生累计序列最大值，不能以后台到达顺序代替采样顺序。

故障场景使接收端延迟并拒绝，原生 SDK 有界队列和有限导出等待保留；100 次业务调用继续完成，本地观测降级及导出失败可见，真实数据缺失不被称作零丢失。恢复操作由可信观察器提供独立新上下文，日志和父子链路必须携带它实际到达，重放旧日志或仅连接恢复不能通过。该有限校准负载不是生产吞吐／时延承诺。请求输入及秘密不进入聚合维度；原文及单层 Base64 包裹的已知校准秘密在成功与失败路径都拒绝。无额外自研缓冲队列或通用秘密治理平台。[反例与整改](../../harness/engineering_gate/test_observation.py)使用真实 SDK 和接收端，依据 [Java SDK 官方说明](https://opentelemetry.io/docs/languages/java/sdk/)。

接收端记录指标可能早于客户端发布导出结果。正常与恢复阶段在既有有界等待内同时核对累计指标和实际观测健康状态；超期保留真实状态交由原断言拒绝。延迟发布可以收敛，持续不健康不能因指标已收到而放行。

- 原生日志告警及 target 下 HTML／JSON 为结果。漏洞阈值 11 表示分数 0～10 仅告警；分析执行错误仍失败，不把构建成功当作无风险。
- 保留原生自动更新；不新增漏洞服务账号，关闭要求账号的 OSS Index 分析器。锁定版本使用原生支持的 NVD 2.0 JSON 数据源，不自研下载、导入、评分或上游规则审计。
- [配置测试](../../harness/engineering_gate/test_maven_advisory.py)与[原生测试](../../harness/engineering_gate/test_advisory_runtime.py)分开。正常扫描核对实际组件及报告，不要求永久零漏洞；漏洞反例须定位目标原生告警，资料缺失以原生 NoDataException 拒绝，新工程整改恢复。

[告警薄入口](../../harness/engineering_gate/calibrate_advisory.py)只提供 update-only 准备、限定 check 校准及环境核对，不接受任意目标或跳过参数。准备用显式仓库外专用目录，原生进程预算 45 分钟，失败／超时保留日志。首次真实 CI 从空缓存准备达到原 25 分钟上限，按[已批准的负载预算原则](04-工程检查设计.md#统一执行与证据)调整；该超时只说明准备未完成，不能推导机制失效或产品质量失败。

校准先拒绝旧输出和偏离配置，将原生数据库复制至临时目录；扫描关闭在线更新及与 Java 夹具无关的 RetireJS，单扫描 30 秒。核对真实 HTML／JSON、组件、版本及输入／配置／环境／原库摘要，原库与失败工程不覆盖。

按[已批准责任](04-工程检查设计.md#统一执行与证据)，CI 独立准备 job 为 50 分钟，成功后保存资料及插件依赖缓存；运行／重试键唯一，允许恢复同配置缓存但仍更新。常规 job 依赖本轮准备成功并按精确键恢复，缺失失败，预算按实际负载设置。守卫核对已知布局的命令、依赖、预算、缓存失败策略及重复关键配置，不冒充通用 YAML 语义验证。

原生目录在 runner 上由 shell 使用 `RUNNER_TEMP` 写入 `GITHUB_ENV`，先于缓存和工具使用；job 级 `env` 不引用不可用的 `runner` 上下文。回归执行真实 shell 核对含空格路径的展开，并拒绝原上下文错误；工作流解析仍须由真实 GitHub Actions 结果核验。

固定 `setup-java` 显式设置 `show-download-progress: true`，避免默认注入 `MAVEN_ARGS=-ntp`；校准器继续拒绝隐式 JVM／Maven 参数，不在工具内部静默清除。准备 Maven 失败时回显已保存的 JSON 诊断并保留非零退出，便于区分环境准备与后续断言失败。

原生资料准备失败时，CI 输出专用 `preparation.log` 的末尾 200 行并保持非零退出；成功分支不额外回放日志。失败资料不保存为成功缓存，全部校准、单扫描 30 秒及人工责任保持不变。

原生资料可能滞后、限流或不完整；成功更新／扫描不是实时完整或安全保证。NVD 数据源参数见[官方说明](https://dependency-check.github.io/DependencyCheck/data/mirrornvd.html)，插件行为见[官方参数](https://dependency-check.github.io/DependencyCheck/dependency-check-maven/configuration.html)。本节只规定工具校准；现行产品工程的扫描由[产品入口](../architecture/02-工程基线.md#质量检查接入)执行，精确结果见对应报告及验收依据。不得把校准扫描冒充产品安全结论。
