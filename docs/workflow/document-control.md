# 文档维护与按需使用流程

规范来源与固定输入见[第四层确认记录](../product/rebuild.md#第四层确认记录)；实际实现、验证及未完成项见[当前任务](../tasks/control-plane-verification.md#唯一任务记录)。

## 适用范围与阅读入口

适用于平台研发、消费项目业务研发及能力升级中的文档维护和使用。按任务触发读取：

- 判断现行材料与历史证据、维护任务入口：[已确认的文档生命周期原则](#已确认的文档生命周期原则)。
- 修改规范、设计、使用说明或任务事实：[内容分工与更新责任](#内容分工与更新责任)。
- 核对已验收任务归档、证据及未解决问题：[归档操作与验证](#归档操作与验证)。
- 开始任务、恢复工作或变更任务范围：[已确认的规则覆盖原则](#已确认的规则覆盖原则)及[渐进式加载与覆盖核对](#渐进式加载与覆盖核对)。
- 维护路由或实现、评审覆盖校验器：[规则覆盖验证](#规则覆盖验证)。

目标与责任仍遵守[产品成功标准](../product/product-definition.md#产品成功标准)，设计与验证要求引用相应规范，不由本文重新定义。任务规划、验收及推进、Git 次序和相应操作见[任务流程](task-execution.md#适用范围与阅读入口)，后续前沿见[当前恢复点](../product/rebuild.md#当前恢复点)。使用[总索引](../index.md)及[实际命令](../design/control-plane-mechanism.md#公开命令与记录字段)取得命中小节与必要验证，不将索引、结构检查或清单当作整套规范已经有效。

## 已确认的文档生命周期原则

- 活动任务入口只展示仍在推进或待处理的任务与事项；已验收任务退出活动入口，通过归档入口定位其记录和必要证据，不默认加载全部历史。
- 保留必要验收与整改证据、唯一任务状态及可追溯引用，不建立另一套审批事实，也不把历史任务当现行规则。
- 可以保持有效记录原路径，只调整入口归属；活动、归档及追溯引用须一致。本项不统一规定物理目录或保存期限；失效材料按下述纠正与清理要求处理，不扩大为任意删除授权。
- 现行设计、未解决问题及仍有效规则不能仅因相关任务已验收而失效。文档总量可以随研发增长，当前有效输入与每次加载范围不应因历史积累而无边界增长。

区分针对旧输入的真实结果与已证伪、被替代且不再有用途的材料：先核实事实并纠正结论，必要共性问题落实到现有规则或有效反例，再清理失效正文、索引引用及无用途数据，不另存一套错误全文。只保留必要的简短纠正事实、决定来源和验证入口；仍有效的验收来源、未完成义务及真实必要证据不能借清理删除。普通进度和个案不自动升级为通用规则，输入变更使报告不再适用也不等于报告曾经造假。清理前核对精确对象、引用依赖及替代内容，并遵守当前操作授权；缺少可核实事实时不能自行认定材料错误。

## 已确认的规则覆盖原则

- 按任务类型、计划范围及实际变更等可识别触发条件，路由到必要规则的具体小节，形成最低清单；命中多个范围时合并去重，不全文加载文档树，也不把整类规范无差别加入每个任务。
- Agent 补充业务语义、跨边界影响及必要场景，不把自动清单当作全部适用规则。领域归属、授权语义及场景充分性仍须有证据的评审。
- 对已登记且可判定的触发项核对规则及验证覆盖，实际范围变化后重新核对。无法识别范围、缺失必要路由或覆盖时明确缺口，不能以空清单或旧清单报告通过；不允许自行删减有效规则或缩小必需门禁。
- 适用规则关联到实际检查、场景或语义评审证据。清单存在、引用正确或声明已阅读都不证明实现遵循规范；自动检查与人工判断的边界继续遵守[有效门禁要求](../standards/testing-and-verification.md#门禁与失败反例)。

## 内容分工与更新责任

以下要求落实已确认的[文档形成原则](../product/rebuild.md#文档形成原则)，不增加新的产品能力或并行规则正文。

| 内容 | 维护与使用要求 |
|---|---|
| 产品定义及统一规范 | 保存有效目标、边界、统一方法及约束；普通任务引用既定规则，不把每次进度或个案经验追加为通用规则。确需变更时说明理由、影响和验证，并取得适用决定 |
| 现行设计、公开合同及使用说明 | 与受支持版本和实际实现保持一致；任务完成后仍可作为必要输入，不能随任务归档而隐藏。被替代材料保留来源及替代关系，不作为另一份现行定义 |
| 活动任务及待处理事项 | 说明当前目标、范围、下一步、待决定问题和证据入口，不复制规范全文或持续累积已完成过程 |
| 归档任务及历史证据 | 保留可追溯的输入、决定、结果、验收来源及必要整改过程；按相关任务、目标或决定查询，不用于自行恢复已被替代的规则 |

功能变化同步更新受影响的设计、合同、使用说明、索引和任务事实；“统一规范尽量稳定”不等于这些内容永远不更新。未受影响的材料不为形式完整而重写；没有实际问题的经验不自动升级为新增约束。维护责任引用[任务责任](task-execution.md#责任与人工决定)，规则变更与普通事实更新分别处理；问题整改、提交及验收收尾分别引用[整改复验](task-execution.md#评审发现与整改复验)、[候选提交](task-execution.md#候选提交与验收准备)及[验收收尾](task-execution.md#验收记录与交付收尾)。

## 归档操作与验证

验收粒度引用[交付单元验收原则](task-execution.md#已确认的交付单元验收原则)，唯一状态来源及收尾引用[验收记录原则](task-execution.md#已确认的验收记录原则)和[收尾流程](task-execution.md#验收记录与交付收尾)；本文不单独定义任务状态或验收门禁。

1. 核对任务的真实验收来源及对应输入，不能仅凭测试通过、CI 成功或 Agent 自述标为已验收。
2. 核对受影响的现行设计、合同与说明仍有有效入口；未解决问题和待处理事项明确归属及入口，不随归档隐藏或被当作已经完成。
3. 根据任务的唯一状态来源调整活动与归档入口，保留记录及证据引用；索引反映事实，不独立产生验收状态。记录无需因归档必然搬迁或复制。
4. 验证从活动入口可找到当前工作，从归档入口可定位已验收任务及必要证据。缺失或冲突先整改，再按相应流程复验；不通过删除记录消除问题。

| 情形 | 检查或评审要求 |
|---|---|
| 已验收任务完成入口调整 | 不再作为正在推进的任务返回，仍可按归档引用找到对应记录、验收与必要整改证据；记录保持原路径是合法情形 |
| 未验收任务被错误归档，或入口与唯一状态来源冲突 | 状态及索引核对必须识别，不把归档操作当作验收或放行依据 |
| 任务归档后证据失联、来源缺失或引用指向错误版本 | 对应引用及字段检查须识别；输入与验收来源是否真实仍需证据核对 |
| 任务完成但有效设计或未解决问题被隐藏 | 核对当前输入和问题归属，保持必要入口；不能用“归档成功”掩盖仍需处理的事项 |
| 历史查询或恢复任务 | 只加载有关记录并核对适用版本；被替代规则、旧执行结果或针对旧输入的验收不能证明当前输入通过，仍有效规则继续引用 |

可判定的引用、入口与状态匹配由校验器及隔离正反例验证；材料是否仍有效、证据是否充分和问题是否真的解决，需要相应事实及语义评审。具体识别与记录方式见机制设计，实际结果见任务证据；机制不生成批准或真实 CI 结果。

## 渐进式加载与覆盖核对

路由只登记触发条件、唯一正文的小节引用及对应检查或评审责任，不复制规则内容、阈值或任务状态，避免形成另一套规则正文。

1. 从[当前任务记录](task-execution.md#当前任务的必要信息)定位有效目标、范围、输入及必要前置决定；引用现行设计，不先加载归档过程或全部规范。中断后按[恢复核对](task-execution.md#中断恢复与事实核对)调查真实前沿。
2. 依据计划范围取得最低规则清单及命中理由，读取所指小节；Agent 补充需求语义和跨边界影响。当前任务没有源码变更时按实际设计、文档或其他任务范围处理，不伪造代码触发项。
3. 将适用规则关联到所需自动检查、真实场景或语义评审；可以复用有效验证，不为每条规则机械新增测试类。记录必要信息使用[任务流程](task-execution.md#当前任务的必要信息)，实际证据遵守[执行边界](../standards/testing-and-verification.md#执行与证据边界)。
4. 用实际变更重新核对范围与清单，不能仅凭任务标签或先前声明缩小检查对象。新增职责、合同、依赖或运行影响时补充适用规则；无法识别或缺失映射先查明并补齐，不因尚未匹配而默认排除。
5. 交付前执行完整适用门禁并核对覆盖证据。规则已关联但检查未执行、必需环境缺失或结果失败，不能记为通过；范围或输入变化后，旧结果不自动证明新输入符合要求。

不适用判断依据真实范围及规则条件，并可由评审核对；不是 Agent 删除路由结果的自由裁量。若路由有误，修正登记并复验；若有效规则错误或确需例外，按既有[规则整改与变更原则](../standards/system-design.md#运行约束与设计审阅)处理。合法轻量任务不应被强制加载无关规则，修正路由也不能用于绕过真实约束。

## 任务上下文与增长控制

遵守[生命周期原则](#已确认的文档生命周期原则)，控制默认加载范围而非承诺文档总数永不增长：

1. 开始或恢复时读取产品目的、当前前沿和任务摘要，由[上下文命令](../design/control-plane-mechanism.md#公开命令与记录字段)先取得最低目录，再按当前步骤逐节加载正文。同一正文重叠范围只返回一次，保留引用、命中理由及验证责任；未加载小节显式列出，不因部分读取缩小验证范围，不自动附加历史执行过程或归档全文。
2. 当前任务只保存目标、有效设计引用、实际范围、前沿、未解决事项及证据入口。完成事实留在证据，恢复不从全部历史重推规则；历史确实影响当前决定时精确补充相关小节，不复制全文。
3. 统一规范保存长期边界，现行设计及合同保存当前实现约定，任务保存过程与证据。普通需求不能把个案实现和每次进度追加到统一规范；被替代内容退出默认有效入口，仍可按来源追溯。
4. 范围扩大或出现新职责、依赖、接口、数据及运行影响后重新生成最低清单；不得为缩短上下文删除适用规则。阅读包与固定输入关联，旧摘要不是新实现遵规证明。
5. 交付评审同时核对两类漂移：代码是否遵守命中规则及设计合同，受影响文档是否与实际实现一致；目录和链接通过不代表内容准确。有效规则变更需对应决定，不能由普通任务降低门禁来自我放行。

不增加统一字数、文档数量或任意 token 硬上限。若一次任务命中过多小节，先核对真实范围、过宽路由、重复正文及任务切片；必要规则确实多时按工作阶段加载并保留总覆盖，不截断规则或要求每次全文读取。每次规范或入口维护核对唯一正文、必要索引、活动／归档分工及无关历史泄漏；结构检查和代表性使用路径共同验证，不能声称脚本已测量 Agent 的主观注意力。

## 规则覆盖验证

具体规则标识、路由结构、执行入口及记录格式见[机制设计](../design/control-plane-mechanism.md#最低清单与实际变更)。第五层用合法正例及隔离反例证明对应机制有效，不凭配置存在或清单非空认定通过；未支持对象仍须明确保留缺口。

| 情形 | 检查或评审要求 |
|---|---|
| 任务命中一个或多个已登记范围 | 返回相应小节和命中理由，合并重复引用，不误要求全部规范；合法不适用范围不应被强加 |
| 已登记触发项漏列规则、路由缺失或实际范围无法识别 | 对应覆盖检查须识别缺口，不能得到空清单通过或依赖 Agent 自述完成 |
| 正文、小节或验证映射无效 | 对应引用和映射检查须失败，不能用另一份复制正文或不存在的检查补足字段 |
| 实际变更扩大而仍沿用旧范围及清单 | 范围核对须识别新增触发和缺失覆盖，不能只校验先前声明的任务类型 |
| 有清单但必需验证未执行、环境缺失或失败 | 交付检查保留真实结果并阻止通过；旧证据、跳过结果或仅填写检查名称不能补足 |
| 自动清单齐全但语义遗漏 | 用需求、源码及场景证据评审并补充；不能宣称脚本已经判断全部业务归属、权限或场景完整性 |

可判定的触发、引用、映射及执行覆盖由校验器验证；适用性、语义补充和证据充分性由相应评审判断。路由和覆盖配置有明确维护来源，随受影响规则或支持范围更新并复验；普通任务使用已有有效基线，不自行发明另一套路由。当前实现及反例的证明范围见任务证据，不能把局部结构检查代替完整工程检查或整套验收。
