# 技术与构建规范

适用于平台、模板和生成的业务服务。当前确切版本与构建结构见[工程与构建](../architecture/02-工程与构建.md)。

## 技术栈

### B-01 统一使用 Java、Spring Boot、Maven

**规则**：平台与模板统一使用 Java、Spring Boot 4.0、Spring Cloud 2025.1、Spring Cloud Alibaba 2025.1 配套线（2026-10-12 决定）；MyBatis-Plus、Sa-Token 使用对应的 Boot 4 适配。其他语言或框架不在首版承诺内。采用这些框架不改变领域层的技术隔离（见[系统设计 S-02](02-系统设计.md#s-02-领域层不依赖框架)），也不意味着采用 Spring 或 Alibaba 的全部组件。

**检查**：评审；引入新框架或中间件需要人工决定。

## 版本

### B-02 只用稳定且有维护的版本

**规则**：选用有明确维护和安全更新来源的稳定版本，JDK 优先 LTS。不使用预览语言特性、快照、候选版本。版本号只在 POM（集中在 `platform/pom.xml` 和 `domain-forge-bom`）中维护，文档不复制版本号（[工程与构建](../architecture/02-工程与构建.md#技术基线)的版本表除外）。

**检查**：评审；Dependabot 每周提示可升级的版本。

### B-03 升级要说明影响并重新验证

**规则**：升级版本时写清：理由、兼容影响、迁移和回退前提，并重新验证受影响的能力。发现某个基线不再有维护或安全更新时，提出升级，不继续把它当作受支持组合。

**检查**：评审；CI 完整执行 `mvn verify`。

## 依赖管理

### B-04 版本只有一个管理来源

**规则**：依赖与插件版本由 `platform/pom.xml` 的 `dependencyManagement`／`pluginManagement`（含导入的 Boot、Cloud、Alibaba BOM）统一管理；子模块不写版本，除非 BOM 未管理该依赖。交付使用的依赖和插件不使用版本范围、`LATEST`、`RELEASE` 或 `SNAPSHOT`。

**检查**：评审。

### B-05 直接使用的依赖必须显式声明

**规则**：代码（含测试）直接用到的类所在的库，必须在本模块 POM 中显式声明，不依赖碰巧存在的传递依赖。声明了但没用到的依赖不阻断（Starter、运行时依赖属于这种情况）。

**正例**：cache 模块的字节码直接引用了 Netty 的 `ByteBuf`（通过 Redisson 编解码 API），因此显式声明 `io.netty:netty-buffer`。

**检查**：自动（`dependency:analyze-only`，有"使用但未声明"的依赖时构建失败）。

### B-06 新增、排除、覆盖依赖要说明理由

**规则**：新增库、排除传递依赖或覆盖上游管理的版本时，在 PR 中写清用途、作用范围和冲突处理依据，并验证受影响场景。不能为了消除警告而随意扩大依赖或覆盖版本。引入新的基础依赖需要人工决定。

**检查**：评审。

### B-07 构建配置不含凭据

**规则**：POM、Wrapper 配置、CI 文件中不出现凭据。私有仓库访问通过 Maven `settings.xml` 或 CI 密钥注入；日志和制品不暴露密钥。

**检查**：评审。

### B-08 用 Wrapper 构建，不跳过检查

**规则**：统一通过 `platform/mvnw` 构建，Wrapper 固定 Maven 版本并校验分发摘要。交付前必须完整执行 `mvn verify`；跳过测试或检查的结果不能当作通过。唯一允许的本地省略是没有 Docker 时跳过集成测试（`-DskipITs -Ddocker.skip=true`），这部分由 CI 补足。

**检查**：CI 执行完整 `mvn verify`。

## 依赖漏洞

### B-09 漏洞告警只提示，不阻断

**规则**：依赖漏洞由 Dependabot 提示，不阻断功能构建；构建成功也不代表没有风险。告警由研发者结合实际用途处理：需要升级时验证兼容性；暂不处理的，在[路线图](../product/02-路线图.md#已知风险)的已知风险中记录。不自建漏洞库、评分或抑制审计系统。

**检查**：评审 Dependabot PR；已知风险定期复查。

## 源码复用

### B-10 业务服务在本仓库内以源码复用平台

**规则**：业务服务由模板生成到 `platform/services/<name>`，继承内部 parent，通过 `domain-forge-bom` 管理组件版本，只使用组件的公开 API（2026-10-23 决定）。不要求预先发布组件到私有仓库，不例行验证独立仓库消费。每个可运行制品写清坐标、版本、运行前提和所需配置；业务配置与密钥不打进制品；同一正式版本不能对应不同内容。

**检查**：在干净的源码目录完成构建、启动和接入，不依赖开发机上的隐含文件或未声明的本地安装。
