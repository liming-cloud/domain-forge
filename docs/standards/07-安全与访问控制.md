# 安全与访问控制规范

适用于平台与业务服务的认证、授权、凭据和审计。IAM 的模型与会话设计见[身份权限设计](../architecture/04-身份权限.md)；授权在用例边界执行的通用要求见[系统设计 S-04](02-系统设计.md#s-04-授权在后端用例边界执行)。

## 技术基线

| 项 | 决定 |
|---|---|
| 登录、会话、权限校验 | Sa-Token 原生机制，会话存于 Redis；不做 OAuth 中心或跨项目账号 |
| 访问策略声明 | Sa-Token 原生类／方法注解（2026-10-13 决定） |
| 令牌传递 | 只从 `Authorization: Bearer <token>` 读取（2026-10-12 决定） |
| 密码哈希 | Argon2id（2026-10-13 决定） |
| 关键管理操作的审计 | 与业务同库同事务，审计失败则业务回滚（2026-10-22 决定） |

## 访问策略

### A-01 每个业务接口都有明确策略，未声明即拒绝

**规则**：每个业务 HTTP 入口（包括返回文件或流的接口）声明有效访问策略：允许匿名、仅需登录，或具体权限（`@SaIgnore`、`@SaCheckLogin`、`@SaCheckPermission` 等原生注解，可写在类或方法上）。没有声明的入口默认拒绝访问。同一权限不在注解和集中配置里重复维护。

**正例**：

```java
@SaCheckPermission("iam:account:read")
@GetMapping("/accounts")
ApiResponse<AccountPage> list(...) { ... }
```

**反例**：只注册了 Sa-Token 拦截器，没有声明的接口对已登录用户放行。

**检查**：自动（access-control 组件在启动时登记全部入口的策略，请求时对未声明的入口拒绝）；测试覆盖匿名、未登录、无权限三种请求。

### A-02 "仅需登录"不等于有权限

**规则**：登录身份不代表拥有所有操作或数据的权限。仅需登录的接口仍要执行业务权限、资源归属和数据范围校验。身份必须来自可信会话，不接受客户端提交的身份或权限字段。网关校验、入口策略和应用用例各自承担自己的责任；通过网关不代表后端放行。

**检查**：评审；测试覆盖范围外资源。

### A-03 依赖故障时拒绝，不降级放行

**规则**：身份或权限依赖不可用、策略无法解析时，返回 503 或拒绝，不能降级为匿名、普通无权限后被 OR 分支放行，也不能跨请求缓存"允许"结果。

**检查**：测试注入依赖故障。

### A-04 令牌只从 Authorization 头读取

**规则**：受保护请求只从 `Authorization: Bearer <token>` 取令牌；关闭从请求参数、请求体、Cookie 读取，缺少有效头时不回退其他渠道。复用 Sa-Token 的读取与前缀配置，不自造令牌协议。

**检查**：测试覆盖正确头、缺失或错误头，以及只通过参数／Cookie 提供令牌时被拒绝。

## 生效与会话

### A-05 禁用、撤权、缩小范围后立即对新请求生效

**规则**：账号禁用、权限撤销、数据范围缩小报告成功后，新发起的授权校验必须使用新状态，覆盖所有实例和调用路径；不能等缓存或令牌过期。已经完成授权的在途请求不强制中断。如果还有实例或路径能凭旧状态通过，就不能报告成功；未完成或结果未知要如实返回。

**检查**：测试用变更前登录的身份，在变更后从另一实例发起请求并验证被拒绝。

### A-06 改密后全部旧会话失效

**规则**：密码修改报告成功后，该账号全部旧会话（包括执行修改的会话）在新请求中都被拒绝；旧密码不能用于新登录，新密码可以登录；其他账号不受影响。密码保存和会话失效都满足后才能报告成功。

**检查**：测试覆盖多实例下的旧会话、旧密码、新密码和其他账号。

## 凭据

### A-07 密码用 Argon2id 保存

**规则**：使用成熟实现的 Argon2id 和自描述保存格式，每次生成独立随机盐，用实现自带的安全比较。不保存明文，不用可逆加密或快速哈希代替。工作参数在目标资源上按实际登录负载校准。明确输入长度与编码，不静默截断或规范化密码。

**检查**：测试覆盖正确、错误和边界长度输入；评审参数与负载证据。

### A-08 凭据不进入日志、响应和审计

**规则**：明文密码、令牌、密码摘要不出现在日志、错误响应、审计记录、异常消息或报告中。登录失败对外使用统一提示，不暴露"账号不存在""已禁用""密码错误"的区别。外部凭据通过环境或秘密注入，不提供通用初始密码。生产环境使用 TLS 传输（在 Nginx 等入口终止）。

**检查**：评审；测试断言失败响应不区分原因。

## 登录防护

### A-09 默认提供登录失败防护

**规则**：账号密码登录的默认接入路径自带失败尝试限制和恢复，业务项目不需要自己组装。写清限制对象、阈值、限制后的行为、恢复条件和依赖故障时的表现；跨实例运行时，不能通过切换实例绕过限制。通用限流的测试不能代替登录路径的验证。当前默认值见[身份权限设计](../architecture/04-身份权限.md#默认登录防护及审计)。

**检查**：测试覆盖正常登录、超限、限制后恢复、依赖故障和跨实例。

## 审计

### A-10 关键管理操作与审计同事务

**规则**：关键安全管理变更（授权、撤权、禁用、邀请等）与必要的审计记录在同一数据库事务中保存，审计写入失败则业务回滚。提交结果未知时不报告成功或回滚，由客户端读取业务事实核对，不自动重试。不建设通用回执、人工补录或提交后恢复机制。

**检查**：测试注入审计写入失败，验证业务未落库。

### A-11 审计记录的内容

**规则**：记录可信操作者、对象、动作、时间、实际结果和必要的脱敏摘要；不保存密码、令牌、密码摘要或完整请求。审计数据有读取权限控制和保留期。普通日志、指标的故障按[故障与可观测性](09-故障与可观测性.md)处理，不与审计混用。

**检查**：评审。

## 框架接入

### A-12 优先复用框架原生能力

**规则**：Sa-Token 已有的令牌签发、读取、过期、退出、权限／角色接口和 AND／OR 匹配都直接使用；IAM 负责账号、邀请、组织和授权规则，通过 `StpInterface` 提供权限与角色。不重写原生匹配逻辑。额外的安全机制（如 SQL 会话许可）必须写清它保证什么、代价和对应的失败场景。领域层不依赖会话或 Redis API。

**检查**：评审；接入或升级时用真实 Redis 和真实账号数据验证登录、会话读取、退出、授权成功与拒绝、依赖故障。

### A-13 公共安全处理先于应用兜底

**规则**：401、403、组件的 503 与 IAM 的业务冲突、429 由各自所有者处理；公共安全异常处理器的优先级明确高于应用的兜底处理器。异常和诊断信息不携带原始令牌。

**检查**：测试覆盖各类失败的实际响应。

### A-14 服务间调用的身份

**规则**：服务之间的调用按 Sa-Token 官方用法携带 Same-Token 证明来自系统内，被调方以 `SaServletFilter` 校验，不自造凭据或签名。在用户请求内发起的调用同时转发该用户的 `Authorization`，被调方以同一用户身份认证授权，调用方不代替被调方判定权限。没有用户上下文的调用只能访问被调方 `/internal/**` 下以 `@SaIgnore` 声明的服务专用接口；这类接口不信任调用方提交的账号或权限字段。两者都由跨服务调用组件处理，服务不手写这些请求头。设计见[跨服务调用](../architecture/07-跨服务调用.md)。

**检查**：自动（access-control 对所有请求校验 Same-Token，部署环境不能关闭）；测试覆盖直连被拒、用户令牌传递、服务专用接口无会话可调用。
