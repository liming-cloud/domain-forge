# 配置与运行规范

适用于平台组件、模板和业务服务的配置、启动与运行状态。产品范围见[产品定义](../product/01-产品定义.md#运行配置与-nacos)，故障与观测见[故障与可观测性](09-故障与可观测性.md)。

## 默认约定

### O-01 约定优于配置，只配置必要输入和差异

**规则**：组件提供默认装配和合理默认值，业务服务只为必要输入（连接地址、凭据、资源位置）和实际差异提供配置，不需要重复填写内部装配细节。只暴露有真实需要的配置项，不照搬底层 SDK 的全部参数。默认值只在组件的实现或配置文件中维护一处。

**正例**：服务只配置 Redis 地址与密码，连接池、超时、线程数使用 cache 组件的默认值。

**检查**：评审；接入测试只提供必要输入即可工作。

### O-02 配置文件与优先级

**规则**：

- 应用配置使用 `application.yml`；工具自带的 properties（如 Maven Wrapper）不改。
- 组件默认值放在组件内的 YAML（如 `META-INF/domain-forge/cache-defaults.yml`），以最低优先级加载；服务的 YAML、profile、环境变量、启动参数都可以覆盖。
- 每类配置只有一个归属：cache 组件维护 Redis 地址、凭据和连接池，access-control 只维护 Sa-Token 会话策略。

**检查**：测试验证覆盖生效、其他默认值保留。

### O-03 Spring 装配方式

**规则**：使用构造器注入和原生自动配置。显式 `@Configuration` 只用于必要的资源、框架扩展和安全装配，不为每个用例写 `@Bean`。自有的成组参数用类型明确的 `@ConfigurationProperties` 并加校验。密钥不设演示默认值。装配条件、用户覆盖、多实现选择必须有确定结果，不依赖偶然的加载顺序。

**检查**：评审；装配测试验证覆盖与冲突。

### O-04 配置错误不能静默切换

**规则**：明确选择的实现缺少必要配置时按失败处理，不能悄悄换成另一个实现或改变数据位置。

**反例**：选择了 S3 文件存储但缺少桶配置，就自动改回本地存储。

**检查**：测试覆盖配置缺失。

## 启动与运行状态

### O-05 启动时发现配置问题

**规则**：已启用能力的必需配置缺失或非法，在启动阶段明确报错，不等到首次调用才发现。能力合同明确允许时，应用可以启动并只提供不受影响的功能，此时该能力保持不可用，调用它的请求按失败合同拒绝，不返回演示结果或假成功。未启用的可选能力不要求配置。局部启动不能绕过身份授权、数据库迁移等前提。

**检查**：测试覆盖缺少必要配置、非法配置的启动结果。

### O-06 健康状态反映真实可用性

**规则**：区分"未启用""已启用且可用""已启用但不可用"。存活（liveness）表示进程可以继续运行；就绪（readiness）包含真实依赖检查（如数据库），依赖断开时返回不可用。不能因为进程存在就报告全部就绪，也不能因一个可选能力出错就判整个进程失效。健康端点不显示连接串、凭据或堆栈。

**正例**：模板服务的 `/actuator/health/readiness` 包含数据库检查，断库返回 503；`liveness` 保持 UP。

**检查**：测试验证依赖断开与恢复时的健康状态。

### O-07 管理端点不公开

**规则**：管理端口独立并只绑定回环地址或内网；只开放实际需要的端点（默认 `health`、`metrics`），健康详情默认不显示。生产部署不能把管理端口暴露到公网。

**检查**：评审部署配置。

## 部署与传输

### O-08 TLS 在入口终止，后端独立鉴权

**规则**：后端服务默认使用 HTTP；TLS、证书和 HTTPS 重定向由 Nginx 等部署基础设施负责，并通过部署覆盖文件开关。即使在内网，后端仍独立执行认证和授权。生产环境只公开入口端口，后端和依赖服务不暴露公网端口。

**检查**：评审 Compose 配置；部署验证中检查实际暴露的端口，并以覆盖文件 `compose.https.yml` 验证 HTTPS、跳转与证书重载（见[部署参考](../../deploy/README.md#https)）。

## Nacos

### O-09 Nacos 发布内容是权威

**规则**：由 Nacos 管理的配置以其发布内容为准；内容的正确性是发布方的责任（2026-10-06 决定）。不自建内容审核、拒收或停用机制。默认值只用于没有被明确覆盖的项，不用本地值纠正 Nacos 的发布值。

运行中发布的值无法应用（类型错误、越出取值范围）时，该组配置不生效，应用继续使用当前生效值，并记录错误日志与指标；发布方修正后的下一次发布正常生效（2026-10-27 修订）。启动时同样的情况按 O-05 启动失败，不以本地默认值启动。凭据与密钥不放入 Nacos。

**检查**：评审。

### O-10 收到通知不等于已生效

**规则**：写清哪些配置项支持动态更新；其余项需要重启。验证动态更新时观察应用的实际行为，收到通知、发布成功或回调执行都不能当作已生效的证据。测试覆盖正常读取、支持项的动态生效、连接中断、应用更新失败和恢复。配置中心与服务发现分别定义和验证。

**检查**：接入 Nacos 配置中心时按此补充测试；设计与动态项清单见[配置中心](../architecture/05-配置中心.md)。
