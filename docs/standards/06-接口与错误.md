# 接口与错误规范

适用于业务 HTTP 接口。合同的通用要求（结果、失败、重试、兼容）见[系统设计 S-14](02-系统设计.md#s-14-合同写清结果失败重试和兼容)；平台实现与接入方式见 [Web 组件](../architecture/03-Web组件.md)。

## 状态与外壳

### H-01 业务拒绝返回 200，技术失败用对应状态

**规则**：

| 情形 | HTTP 状态 |
|---|---|
| 成功、查询完成（包括没有匹配数据） | 200 |
| 已受理、尚未完成 | 202 |
| 应用处理后明确拒绝的业务命令 | 200，响应体给出稳定的业务错误代码 |
| 请求格式或参数错误 | 400 |
| 未认证、无权限 | 401、403 |
| 依赖不可用 | 503 |
| 未知错误 | 500 |

这不是"所有异常都返回 200"：协议错误、认证与权限失败、服务故障必须使用对应状态，不能改写成业务拒绝。消费方不能只凭 200 判断业务成功。

**理由**：业务拒绝是正常的合同结果（例如"邀请已过期"），和系统故障分开处理和统计。

**检查**：Web 组件的合同测试；评审核对新接口的分类。

### H-02 普通 JSON 响应只有 code、message、data

**规则**：普通业务 JSON 响应恰好包含三个字段（2026-10-12 决定）：

- `code`：稳定的字符串代码，程序据此判断结果。`SUCCESS` 表示成功，`ACCEPTED` 表示已受理、不保证完成，其他为业务拒绝或失败代码。
- `message`：面向用户的说明，程序不根据它判断结果。
- `data`：业务数据；没有数据时显式输出 `null`。

不增加 `success` 布尔值、时间戳或其他全局字段。二进制下载、流式响应和 Actuator 端点不包装。分页结构、业务代码在各自的接口合同中定义。

**正例**：

```json
{"code": "INVITATION_EXPIRED", "message": "邀请已过期", "data": null}
```

**检查**：自动（`ApiResponse` 构造时拒绝空代码和空说明，业务拒绝不能占用平台保留代码）；Web 组件的合同测试。

### H-03 外壳只出现在入口层

**规则**：`ApiResponse` 由 `interfaces` 层的 Controller 构造。领域模型、应用用例和非 HTTP 的平台能力不返回 HTTP 结果对象；不为此引入统一父类或继承体系。

**检查**：自动（领域层不能依赖 `shared` 中的传输类型）；评审。

### H-04 按实际语义分类失败

**规则**：失败分类依据实际语义，不依据异常名称、捕获位置推测。业务异常通过 `BusinessRejectionMapping` 按确切类型映射；未映射的异常一律按未知故障处理。对外只返回调用方需要的信息，不泄露内部实现、堆栈或敏感数据。

**检查**：评审；接口测试覆盖每类失败。

## 接口合同

### H-05 代码是接口合同的唯一来源

**规则**：先写清场景、行为和验收，再用 Controller、请求与响应类型及描述注解定义接口，由 springdoc 生成 OpenAPI。不再手工维护另一份 OpenAPI，也不手改生成物。类型表达不了的业务拒绝代码、权限要求在描述注解中补充。

**检查**：评审；接口变化在 PR 中说明对调用方的影响。

### H-06 接口变化要考虑兼容

**规则**：修改字段、类型、错误代码或权限要求时，在 PR 中写清对已有调用方的影响；不兼容的变化需要人工决定，必要时提供新版本路径。不通过修改测试预期来掩盖不兼容。

**检查**：评审。

## 消费与观测

### H-07 调用方同时处理 HTTP 状态和业务代码

**规则**：客户端同时检查 HTTP 状态和响应中的 `code`。无法解析的响应不能当作空数据或成功；超时、没有收到有效响应时，不能断言远端操作没有发生。是否可以重试由接口合同决定，不对所有失败统一重试。

**检查**：评审；调用方的适配测试覆盖业务拒绝、技术失败和超时。

### H-08 观测区分业务拒绝和故障

**规则**：指标和日志区分请求处理、业务完成、业务拒绝和服务故障。业务拒绝不自动等于故障，也不能被计为成功；只统计 HTTP 2xx 的数字不能当作业务成功率。

**检查**：评审。

### H-09 服务间调用经跨服务调用组件

**规则**：服务之间的同步调用使用 OpenFeign 并依赖 `domain-forge-service-call`：超时、不重试、身份与请求标识传递、失败分类由组件统一提供，服务不另配重试或手写身份请求头。调用方用 `ServiceCalls.data` 读取外壳，把 `ServiceCallException` 的分类翻译为自己的结果：401、403 保持语义，`REJECTED` 按对方代码处理，`UNAVAILABLE` 与 `UNKNOWN` 不能当作空结果或成功，写入的 `UNKNOWN` 按结果未知处理。设计见[跨服务调用](../architecture/07-跨服务调用.md)。

**检查**：自动（组件装配）；调用方的适配测试覆盖成功、401、403、不可用与超时。
