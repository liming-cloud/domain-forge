# 安全与访问控制规范

规范来源与固定输入见[第三层确认记录](../../REBUILD.md#第三层确认记录)；实际实现、验证及未完成项见[当前任务](../tasks/control-plane-verification.md#唯一任务记录)。

## 适用范围与阅读入口

适用于平台及受统一规范约束的消费项目。按任务触发读取：

- 新增或修改业务 HTTP 接口、访问策略及匿名例外：[已确认的业务接口访问策略](#已确认的业务接口访问策略)。
- 接入或升级身份与会话框架：[已确认的身份与会话基线](#已确认的身份与会话基线)、[已确认的-http-凭证传递](#已确认的-http-凭证传递)、[框架接入与验证](#框架接入与验证)。
- 设计策略声明或统一执行：[访问策略与执行细化](#访问策略与执行细化)。
- 实现覆盖门禁、评审授权或验收访问场景：[覆盖检查与验证](#覆盖检查与验证)。
- 修改账号禁用、撤权或数据范围缩小的处理，评审缓存及会话失效：[已确认的账号与权限变更生效原则](#已确认的账号与权限变更生效原则)。
- 新增或修改密码保存、校验或变更，评审凭证传输及旧会话处理：[密码与凭证保护](#密码与凭证保护)、[已确认的密码变更与会话原则](#已确认的密码变更与会话原则)。
- 接入或调整登录失败防护、处理限制及恢复：[已确认的默认登录失败防护原则](#已确认的默认登录失败防护原则)、[登录失败防护验证](#登录失败防护验证)。
- 新增或修改关键安全管理写入及其审计，处理审计失败或补录：[已确认的安全管理审计失败原则](#已确认的安全管理审计失败原则)、[审计内容与失败验证](#审计内容与失败验证)。

业务 HTTP 接口不因返回文件、流或其他非 JSON 内容而排除访问控制责任。框架运维端点按相应运行安全合同明确，不能默认视为匿名入口。消息、任务及内部调用的身份、操作权限、资源权限和数据范围责任继续遵守[职责与依赖](system-design.md#职责与依赖)，本规范不将 HTTP 声明方式强套于其他调用协议。

## 已确认的业务接口访问策略

- 业务 HTTP 入口明确其有效访问策略：允许匿名、仅需登录或具体授权策略。没有策略声明时默认拒绝访问，覆盖门禁不得通过，不能默认为已登录用户放行。
- 声明可由统一配置或其他明确声明承载，不强制每个方法手写检查，也不以类上或方法上是否存在某个框架注解作为唯一判断方式。
- 默认采用 Sa-Token 原生类／方法注解承载匿名、登录及操作权限声明，由统一接入执行未声明默认拒绝；不能只注册原生注解拦截器就认定已具备默认拒绝。类级、继承及组合声明按实际框架解析验证，同一权限不在注解与集中配置重复维护。其他声明方式须有明确合同与相同验证，不自动视为已支持；确认来源见[默认声明决定](../tasks/control-plane-verification.md#原生注解默认决定)。
- 仅需登录的策略不能用于逃避实际业务权限、资源权限及数据范围合同。登录身份不等于获得所有业务操作或数据访问权限。
- 策略覆盖检查负责发现可判定的遗漏；声明齐全不证明策略正确，实际授权与数据范围仍需真实场景和语义评审。
- 身份与存储遵守[会话基线](#已确认的身份与会话基线)，账号变更遵守[生效原则](#已确认的账号与权限变更生效原则)；策略声明齐全不代表实际访问控制已验证。

资料依据：[OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)区分认证与授权，建议默认拒绝并在每次请求验证相应权限，也允许采用统一执行机制。本项目据本轮人工选择确定上述覆盖要求，不将资料建议视为框架默认行为或已经实现的安全保证。

## 已确认的身份与会话基线

- 首版项目内登录、会话和权限校验复用 Sa-Token 的相应机制，以 Redis 保存相应会话状态；不扩展为 OAuth 中心或跨项目统一账号产品。
- 框架不代替完整的[身份权限交付](../../README.md#身份权限交付形态)。项目须接入实际账号校验及权限、角色数据，不以演示权限集合作为业务实现。
- 会话存储不代替业务数据持久化。项目身份与状态隔离遵守[产品责任边界](../../README.md#已确认的产品边界)，不因采用同一框架或共享物理 Redis 而合并项目身份；物理部署方式仍待设计。
- 确切版本及依赖组合、凭证传递、会话生命周期和故障恢复在能力设计中确定；账号变更执行[生效原则](#已确认的账号与权限变更生效原则)，默认拒绝与策略覆盖须实际接入并验证。

资料依据：2026-10-05 经 Exa 读取的 Sa-Token 官方 `v1.45.0` [Redis 集成文档](https://raw.githubusercontent.com/dromara/Sa-Token/v1.45.0/sa-token-doc/up/integ-redis.md)说明会话存储接入，[权限认证文档](https://raw.githubusercontent.com/dromara/Sa-Token/v1.45.0/sa-token-doc/use/jur-auth.md)要求项目提供实际权限与角色集合。该 tag 仅固定资料输入，不是项目选定版本；资料说明不证明组合兼容、权限变更生效或真实运行通过。

## 已确认的 HTTP 凭证传递

- 首版受保护 HTTP 请求只从 `Authorization: Bearer <token>` 取得登录令牌，关闭请求参数／请求体及 Cookie 取令牌，不在缺少有效 Header 时回退其他渠道。
- 复用 Sa-Token 的令牌读取及前缀配置，不自行解析或设计新令牌协议。本项不将令牌改为 JWT，不改变 Redis 会话、项目隔离或访问策略责任。
- 调用方显式携带令牌；默认接入不依赖浏览器自动携带登录 Cookie。登录响应中的令牌交付、客户端保存及生命周期按后续能力合同明确，不因确定请求 Header 就宣称端到端接入已完成。
- 验证正确 Header 的正常访问、缺少／错误 Header 的拒绝，以及仅提供参数／请求体／Cookie 时不得取得登录身份。仍遵守[凭证保护](#密码与凭证保护)与对应 HTTP 失败语义。

确认来源见[任务决定](../tasks/control-plane-verification.md#http-凭证传递决定)。本项只固定首版 HTTP 消费合同，不新增 OAuth、跨项目账号或其他登录方式。

## 已确认的账号与权限变更生效原则

- 账号禁用、权限撤销及数据范围缩小被报告成功完成后，新开始的后端授权校验必须依据新状态，并覆盖实际适用的实例及调用路径。例如撤权完成后，该用户新发起的对应操作必须被拒绝；不能继续使用旧授权直到缓存过期、令牌过期或重新登录。
- 不要求主动通知客户端，也不强行中断已经完成授权的在途操作。重新发起或重试时仍须参与适用的当前授权校验；本项不规定普通展示资料的缓存刷新时点。
- 后续设计明确何时可以报告变更成功，以及未完成、失败或结果未知时的表达和恢复，遵守[合同与失败语义](system-design.md#合同与失败语义)。如果其他适用实例或路径仍可凭旧状态授权，单独完成数据库更新或发出通知不能作为生效成功依据。
- 本项不预定权限缓存、失效通知、版本比较或会话撤销算法，不宣称多状态更新具备分布式原子性。依赖故障或无法取得有效授权依据时，继续遵守[访问策略与执行细化](#访问策略与执行细化)，不能静默放行。

## 已确认的密码变更与会话原则

- 密码变更报告成功完成后，该账号的全部既有登录会话不能再通过新开始的身份校验，后续受保护请求须使用重新登录取得的有效会话；覆盖实际适用实例和调用路径。更改本人密码时，也包括执行更改的原会话，不保留至自然退出或过期。
- 新的账号密码登录只接受新密码，旧密码不能用于新登录。不影响其他账号或其他项目的会话，不要求主动通知客户端，也不强行取消已完成授权的在途操作；重新发起或重试仍须按当前有效状态校验。
- 密码保存与会话处理均满足合同后才能报告变更成功。其他适用路径仍可用旧会话通过校验时，单独保存新密码不代表全部完成；未完成、失败或结果未知的表达及恢复遵守[合同与失败语义](system-design.md#合同与失败语义)。
- 本项只明确首版项目内账号密码登录的行为，不新增找回密码、短信、邮箱、注册或其他登录功能，也不选定自助修改与管理员重置接口、会话并发策略、生命周期参数或撤销算法；不宣称密码与会话更新具备跨存储原子性。

## 已确认的默认登录失败防护原则

- 首版账号密码登录的默认接入路径提供基础失败尝试限制与恢复行为，消费项目不必从零组装。平台承担默认策略、正常用户影响及误用风险的设计、实现和验证；不能仅提供通用限流接口或依赖坐标便宣称登录已受防护。
- 提供必要的公开策略调整方式，遵守[约定优于配置](configuration-and-runtime.md#已确认的配置与启动原则)。说明默认策略及其适用前提、调整责任和覆盖方式，不要求消费项目填写内部装配细节，也不承诺对任意攻击或任意业务提供完整保护。
- 按实际支持范围验证正常登录、约定的过量失败尝试、限制后恢复及必要故障；适用跨实例运行时，不能靠切换实例绕过同一限制合同。通用限流测试不能代替登录路径的实际接入证据。
- 本项不选择阈值、计数维度、锁定、延迟或存储算法，不推定永久锁号，不新增图形验证码、MFA、找回密码或风控中心。策略调整及恢复不绕过正常身份与授权条件，具体行为和失败表达留待能力合同明确。

资料背景：[OWASP 认证指南的登录尝试限制](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#login-throttling)说明防猜测与可用性取舍，相关正文已于 2026-10-06 经 Exa 读取；本项目的默认接入责任来自以上人工选择，资料不替项目选定算法，也不证明框架默认具有该能力。

## 已确认的安全管理审计失败原则

- 账号状态、角色授权及权限变更等关键安全管理写入，不因单独的审计保存失败阻断正常变更完成；业务结果与审计结果分别判断，允许出现已变更但审计暂时或永久不完整的结果。
- 正常的身份校验、授权、业务规则、[账号与权限变更生效条件](#已确认的账号与权限变更生效原则)及[密码变更与会话条件](#已确认的密码变更与会话原则)继续有效。不能把这些条件失败、部分完成或结果未知归类为审计问题后报告变更成功，也不能将已生效的变更描述为未发生。
- 审计保存失败必须明确报告和告警，按约定重试或人工补录，不得静默丢弃、伪造已保存记录或宣称一定能够完整补回。补录保留可核对的事实及其来源，缺失信息明确标记，不能臆造原始操作详情。
- 此项不省略正常审计功能，不把审计故障时的可用性选择推广为日常不记录。可靠保存指可恢复、可核对的信息已保存，按实际存储合同判断；不能仅因调用了记录接口就认定已保存，也不能把观测端暂未展示当作原始审计必然丢失。
- 本项仅覆盖上述关键安全管理写入的审计保存失败，不同时决定普通日志、指标及链路故障如何影响业务，也不选定审计存储、事务、重试或补录实现。
- 平台提供必要审计及故障对接能力；告警环境的提供与管理仍遵守[应用侧可观测能力](../../README.md#应用侧可观测能力)的责任边界，不新增独立审计中心或默认告警产品。

## 审计内容与失败验证

依据具体安全管理合同确定记录范围及必要信息，使记录能核对可信操作者、发生时间、操作对象、动作、实际结果和必要的变更摘要。操作者来自可信身份，不取客户端自报身份作为证据；不为字段齐全而复制凭证、完整会话或无关敏感数据。具体字段、保存与访问控制、保留期限以及补录入口在后续能力设计中明确，不机械记录所有方法调用。

失败报告与变更结果保持一致，明确故障如何被发现、如何对接项目告警，以及重试或人工补录的前提和限制。不能让失败日志依赖同一条已失效的审计写入链路而完全不可观察；具体可用机制按真实接入设计验证，不因此预定第二套持久存储或恢复框架。审计故障隔离不要求主动通知业务客户端，结果表达仍遵守实际 HTTP 与业务合同。

| 场景 | 必须保留的验证与反例 |
|---|---|
| 正常安全管理变更 | 核对实际变更、生效结果与可读取的必要审计信息；只调用记录方法或完全不保存记录不能作为通过 |
| 单独的审计保存失败 | 用实际变更和故障场景证明变更按合同完成、审计缺失可识别并按约定告警；因审计失败错误撤销已完成结果、静默丢弃或伪称审计已保存须识别 |
| 授权或变更生效失败 | 必须按相应失败合同处理；借审计容错绕过权限校验或报告尚未生效的变更成功必须失败 |
| 重试或人工补录 | 核对可用事实、来源及缺失信息，验证实际支持的补录结果；伪造原始内容、混淆操作结果或承诺无法证明的完整恢复须识别 |

可判定的结果、记录与故障路径使用相应自动场景验证；记录范围是否充分、敏感内容是否合适及补录事实是否可信，须有源码与场景证据的语义评审。验证遵守[真实证据要求](testing-and-verification.md#环境与真实证据)，必需环境缺失保留未验证。

## 密码与凭证保护

默认算法为 Argon2id，确认来源见[任务决定](../tasks/control-plane-verification.md#密码算法决定)。官方资料中的工作参数及附加认证功能不自动视为项目选择。

- 密码使用成熟实现提供的专用慢密码哈希及每次生成时的独立随机盐保存和校验；不能保存明文、采用可逆加密代替密码哈希，或仅使用快速通用哈希。使用所选实现的安全比较方法，不自行编写密码算法或靠隐藏算法名称获得安全性。
- Argon2id 使用成熟实现的自描述保存格式，保留算法及参数识别能力；实际工作参数、支持范围与保存格式在能力基线中固定，并在目标资源上校准实际登录负载。不能把资料示例值或框架默认值当作已验证组合，也不因此预建多算法兼容框架。
- 明确输入长度及编码支持，不静默截断或改变密码来迁就实现。生产登录及后续认证路径采用 TLS 或其他适当的受保护传输；具体终止位置、可信边界与必要链路在部署设计中说明并验证，不因选择 Sa-Token 与 Redis 就认定传输已安全。
- 明文密码、令牌及密码摘要不进入普通日志、错误响应、审计或公开报告；外部必要凭证按[默认约定与必要输入](configuration-and-runtime.md#默认约定与必要输入)处理，不引入通用初始密码。登录结果及诊断信息的必要性、账号信息泄露和误用风险须结合实际合同评审，不能将详细诊断直接公开。

验证实际保存与校验，覆盖正确、错误及支持边界输入；隔离验证所选哈希实现对相同输入生成独立随机盐，不因此要求业务允许重复设置相同密码。核对敏感输出和实际部署传输；明文或不合规哈希、静默截断及泄露必须由相应检查或有证据的评审识别，不在报告中展示实际密码或摘要。参数的安全性与资源成本需要技术核查及真实负载证据，不能只证明哈希函数可调用。具体密码强度、接口及恢复流程仍待适用决定与能力设计；登录失败防护的默认责任见[已确认原则](#已确认的默认登录失败防护原则)，本节不选择其策略参数或新增产品功能。

资料依据：[OWASP 密码保存指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)说明专用密码哈希、随机盐及工作参数校准，2026-10-13 经 Exa 复核；[OWASP 认证指南](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)说明安全比较、输入保护与受保护传输。算法采用以上人工决定；资料不替项目选择参数，也不是实现通过证据。

## 登录失败防护验证

能力合同明确限制对象、允许尝试及限制后行为、恢复条件、必要策略调整和依赖故障表达。依据实际支持的调用及部署范围设计场景，不在本规范提前规定固定次数、等待时间或全局账号锁定；故障与恢复不能将尚未执行防护描述为已受保护，也不放宽正常身份与授权条件。

| 场景 | 必须保留的验证与反例 |
|---|---|
| 默认接入与正常登录 | 只提供必要输入即可启用默认防护，合法登录按合同工作；未接入防护或一律拒绝登录均不能作为通过 |
| 过量失败尝试 | 真实登录路径执行声明的尝试限制；仅配置通用限流、只检查回调被调用或切换实例即可绕过同一限制须识别 |
| 限制后恢复及策略调整 | 核对恢复条件与实际结果、合法调整的范围及正常用户影响；错误永久锁定、恢复时放宽密码校验或影响其他项目须识别 |
| 必要依赖故障 | 验证实际支持的失败表达及恢复，不将错误计数或未知状态当作防护成功；具体合同需评审安全与可用性影响 |

可判定结果使用自动场景及隔离反例验证；防护强度、合法用户影响和被恶意触发限制的风险需要有场景依据的评审。实际依赖遵守[真实证据要求](testing-and-verification.md#环境与真实证据)，必需环境缺失保留未验证。

## 框架接入与验证

- 依照[版本与兼容](technology-and-build.md#版本与兼容)固定实际框架、适配模块、客户端及 Redis 服务端组合，声明连接与配置前提；适用依赖同时遵守[依赖漏洞门禁](technology-and-build.md#已确认的依赖漏洞门禁原则)。不能以配置文件存在或纯内存运行作为 Redis 接入证据。
- 接入位置遵守[职责与依赖](system-design.md#职责与依赖)，不因采用鉴权框架让领域模型依赖会话或 Redis API，也不为每个框架方法机械创建转接接口。有效访问策略须参与实际执行，框架选型不替代覆盖检查。
- 用实际账号与权限数据及真实 Redis 验证登录、会话读取、登出、授权成功与拒绝、项目隔离及必要依赖故障；账号与权限变更按[生效原则](#已确认的账号与权限变更生效原则)复验，密码保存与变更按[凭证保护](#密码与凭证保护)及[会话原则](#已确认的密码变更与会话原则)复验。权限集合或连接的测试替身只能作为隔离测试证据，不能替代真实接入；必需环境缺失保留未验证。
- 默认登录接入须执行[登录失败防护验证](#登录失败防护验证)，不以会话可读写或通用限流已测试代替登录防护证据。

## 访问策略与执行细化

| 策略类别 | 必须说明与验证的内容 |
|---|---|
| 允许匿名 | 实际公开范围及理由；匿名声明不扩大业务资源范围，也不豁免合同中的其他校验 |
| 仅需登录 | 可信身份取得与登录校验；不以客户端提交的身份或权限字段代替可信判断 |
| 具体授权策略 | 实际需要的操作权限、资源关系及数据范围，声明与执行位置及必要拒绝场景 |

统一配置、类型级或入口级声明须能解析出每个实际业务 HTTP 入口的有效策略；继承、组合及冲突处理在所选机制中明确。不要求把相同策略重复写到每个方法，但也不能用未定义的约定、空声明或宽泛匿名配置隐藏遗漏。

策略声明与实际执行核对一致，防止仅在描述中写了权限、运行请求却未参与检查。身份与授权依赖不可用或策略无法解析时，不默默降级为允许访问；相应故障按[HTTP 结果原则](api-and-errors.md#已确认的-http-失败状态原则)表达，具体状态映射仍待设计。

网关校验、入口策略与应用用例分别承担已确认的责任。不能把通过网关、成功登录或具有操作权限等同于自动满足业务资源和数据范围条件；具体执行位置引用同一业务合同，不复制互相漂移的权限规则，也不为所有内部方法机械增加检查。

## 覆盖检查与验证

覆盖检查以实际注册的业务 HTTP 入口及有效声明为依据，明确请求方法、路径和适用条件的识别方式。检查声明、继承与配置解析结果，不仅搜索某个注解名称；入口清单与[生成接口合同](api-and-errors.md#已确认的接口合同来源)核对，不能以文档漏掉接口来缩小安全检查范围。

| 情形 | 必须保留的验证与反例 |
|---|---|
| 入口没有有效策略 | 实际请求默认拒绝，覆盖检查失败；仅凭调用者已登录就放行的情况必须识别 |
| 允许匿名的合法入口 | 明确策略后匿名场景按合同工作；不能用全局拒绝所有请求制造看似安全的通过结果 |
| 仅需登录的合法入口 | 区分有效身份与无有效身份，真实验证成功及拒绝，不以客户端自报身份放行 |
| 具体授权及数据范围 | 验证实际允许、缺少权限、范围外资源与必要依赖故障，不只验证已登录管理员的成功路径 |
| 账号与权限变更生效 | 使用变更前已登录的身份，真实验证禁用、撤权和范围缩小后的新授权校验，覆盖实际适用实例及路径；报告变更完成后仍依据旧状态放行必须失败 |
| 密码变更与会话处理 | 变更前建立有效会话，验证成功变更后全部旧会话被拒绝、新密码可重新登录、旧密码不能新登录，且其他账号与项目不受影响；覆盖实际适用实例和路径，仍放行旧会话或借审计容错报告未完成变更成功必须失败 |
| 变更未完成或依赖故障 | 验证失败与恢复合同；尚未满足生效条件却报告成功，或无法取得有效授权依据时放行必须识别，不能把这类结果当作正常撤权已完成 |
| 统一配置或类型级声明 | 合法继承或配置可形成有效策略；遗漏、冲突或空声明不能被当作覆盖完整 |
| 声明存在但未执行 | 直接调用实际业务 HTTP 入口时仍参与约定检查；只检查注解存在或只测网关不能作为完整证据 |
| 扫描遗漏或检查未运行 | 排除适用入口、扫描不到目标或跳过必需检查必须失败，不能作为完整覆盖通过 |

校验器使用有效正例及隔离反例证明可判定约束。策略语义、资源归属和数据范围准确性须有源码与场景证据的语义评审，分工遵守[任务责任](../workflow/task-execution.md#责任与人工决定)；不能声称脚本可以判断全部授权语义。实际身份与业务依赖按所选方案验证，测试替身不能冒充真实接入证据；必需环境缺失保留未验证。第五层建立机制，访问控制在后续设计研发阶段实现。
