## 2. 数据权限夹具与结果

仅为技术验证建立受保护资源夹具，字段已登记为 ownerUserId 与 departmentId；不把该夹具部署为业务系统。

部门为 root 下的 A、B，A 下有 A1。主体 alice 属于 A。夹具记录：

| 记录 | ownerUserId | departmentId |
|---|---|---|
| x1 | alice | A |
| x2 | bob | A |
| x3 | bob | A1 |
| x4 | carol | B |
| x5 | alice | B |
| x6 | bob | null |

null 是已登记字段的空值，不是缺少映射。夹具允许该值，仅用于检验谓词；实际业务是否允许空部门由其模型决定。当前操作 p 为 `fixture:record:read`，q 为另一个操作；这些权限点只存在于测试夹具。

| ID | 授权 / 操作 | 预期结果 | 未来验证层 | 追溯 |
|---|---|---|---|---|
| D01 | p + ALL | x1–x6；不自动获得 q | 领域判定 + SQL | C08、I02 |
| D02 | p + DEPARTMENT | x1、x2 | 领域判定 + SQL | C08 |
| D03 | p + DEPARTMENT_TREE | x1、x2、x3 | 领域判定 + SQL | C08 |
| D04 | p + SELF | x1、x5；不能错误按部门代替本人 | 领域判定 + SQL | C08 |
| D05 | p + CUSTOM(B)；以及 CUSTOM(A) | 前者 x4、x5；后者 x1、x2，不隐式包含 A1 | 领域判定 + SQL | I02；候选组织语义 |
| D06 | 角色1授予 p/DEPARTMENT，角色2授予 p/SELF | x1、x2、x5，去重；部门与本人是 OR | 领域判定 + SQL | C09 |
| D07 | 角色1授予 p/DEPARTMENT，角色2只授予 q/ALL；再撤去角色1 | 先只有 x1、x2；撤去后 p 为 403 | 领域判定 + API | C09，防无关 ALL 扩权 |
| D08 | 角色禁用、范围缺失、CUSTOM 空集合、未知模式 | 无操作权限 403；合法空范围结果为空；损坏策略拒绝并报内部错误，不变成 ALL | 领域判定 + 故障注入 | I02、失败语义 |
| D09 | 列表带客户端 departmentId=B；分页、排序、计数 | 只可缩小服务端范围；items 与 total 使用同一权限谓词 | 真实 MySQL | I02、API06 |
| D10 | 用范围外 ID 请求详情/更新/删除；同样请求不存在 ID | 均返回相同 404，无数据修改，不泄漏是否存在 | API + MySQL | I07 |
| D11 | 有限范围写入：旧记录不在范围；或旧记录在范围但目标部门在范围外；或创建到范围外 | 三者均拒绝；不能借移动归属/插入绕过；批量不支持则明确拒绝 | 应用 + MySQL | I07、ADR-0006 |
| D12 | 授权后、写入前资源归属或 version 改变 | 条件写入不命中或冲突，不能按旧查询结果直接覆盖 | 并发集成 | I07 |
| D13 | 缺身份/范围/映射；未登记 Mapper 触达受保护表；线程复用或异步上下文丢失 | 拒绝且不执行原始 SQL；不继承前一用户权限 | 安全组件 + SQL | I03、ADR-0006 |
| D14 | 有界 JOIN/别名/分页计数；不支持的子查询/UNION/原生批量语句 | 支持清单有相同范围语义；清单外拒绝或使用经评审显式查询 | 真实 MySQL | ADR-0006、T-V05 |
| D15 | 认证系统查询白名单；从公开端点传 bypass 参数 | 合法系统查询有固定用例和审计依据；外部参数不能进入白名单路径 | 架构 + 安全集成 | I03、ADR-0006 |

测试另需在 IAM 用户资源上验证 SELF 映射为目标 userId，不沿用夹具的 owner 字段；数据范围执行器只能使用已登记映射。

## 4. 依赖故障、复用及治理

| ID | 场景 / 输入 | 预期结果 | 未来验证层 | 追溯 |
|---|---|---|---|---|
| F01 | Redis、IAM 或 IAM 数据库不可用 | 受保护访问 503，不使用过期授权结果 | 故障注入 | ADR-0004 |
| F02 | 禁用/凭据变更 DB 提交成功，Redis 清理失败；以及单会话退出失败 | 前者仍靠权威状态/版本拒绝旧会话；后者不虚假报告退出成功 | 故障注入 | I06 |
| F03 | Nacos 失连、配置缺失、服务发现无可用目标 | 启动或请求按确定错误停止；不旁路到不可信地址 | 集成 | T-V02、T-V06 |
| F04 | 异常、审计、HTTP 客户端日志包含敏感输入 | 无密码/Token/完整授权体；保留必要 traceId 与错误分类 | 日志检查 | 安全模型、架构 |
| R01 | 干净环境从模板引用已发布库/服务 | 不依赖平台源码或本机已安装 SNAPSHOT | 独立消费集成 | U01、T-V08 |
| R02 | 更新兼容 BOM/服务版本，或执行不兼容迁移 | 兼容更新通过；破坏性更新有说明与显式迁移，不能覆盖业务代码 | 升级验收 | U03、ADR-0002 |
| R03 | 模板结构更新后已有项目未同步 | 通过差异说明独立迁移，不伪装为依赖自动升级 | 发布文档审查 | U03 |
| G01 | PR 缺设计引用/测试证据，或引入未确认授权语义 | 退回补充，AI 不自行通过人工门禁 | 人工 + CI 设计 | C13、C16 |
| G02 | 同账号创建 PR、私有套餐不支持预期保护 | 明确记录实际流程限制，不要求自审批或宣称强隔离 | GitHub 设置核查 | C13 |
| G03 | 仅设计文档完成，尚无人工设计基线与研发启动指令 | 不进入工程初始化和编码 | 阶段审查 | C15、C16 |

## 5. 执行与结果记录要求

未来每条证据应包含：用例 ID、固定代码/设计版本、环境与依赖版本、实际输入、实际结果、时间、执行者、日志/报告位置和失败说明。不能用“启动成功”替代权限反例，也不能用 mock 数据库证明真实 SQL 过滤。

新增缺陷先把反例加入对应矩阵，再实现最小复现。文档阶段只维护语义；没有应用实现时不创建镜像实现的单元测试或占位测试。
