## 2. 三轮评审

| 轮次 | 输入 | 需要确认的结果 | 当前状态 |
|---|---|---|---|
| R1 方向 | 项目定位、架构职责、ADR-0001/0002 | 首批范围、服务边界、复用职责与交付方式 | 草案已提供；方向问题已提交，未收到明确接受 |
| R2 核心设计 | 领域模型、API、ADR-0003–0006、技术矩阵和反例 | 领域规则、信任与一致性边界、契约、关键选型 | 草案已提供；依赖 R1，未评审 |
| R3 研发准备 | 路线、验证矩阵、AI 流程及 R2 闭合结果 | 首批任务可执行、事实验证有计划、边界清晰 | 草案已提供；依赖 R2，未评审 |

人工接受必须指向明确文档/ADR、版本或摘要、接受范围和对话/PR 证据。可以逐项接受，不把“继续整理文档”解释为所有候选通过。

## 3. 待决问题

| ID | 轮次 / 优先级 | 具体决策 | 推荐方案与主要代价 | 影响 | 状态 |
|---|---|---|---|---|---|
| Q01 | R1 / 高 | 是否统一 IAM，并独立部署 Gateway | 统一 IAM；减少跨服务一致性，承担授权集中依赖 | ADR-0001、模型/API 服务归属 | 待用户回答 |
| Q02 | R1 / 高 | 平台源码与消费模板如何交付 | 平台源码仓库 + 轻量模板仓库；需维护版本清单及跨仓库消费 | ADR-0002、发布与新项目体验 | 待用户回答 |
| Q03 | R2 / 高 | 服务内 DDD 采用包隔离还是多 Maven 模块 | 包隔离 + 架构测试；编译期硬隔离较弱 | ADR-0003、构建/测试组织 | 待评审 |
| Q04 | R2 / 高 | IAM 政策包：在线授权/在途边界、会话期限、超管跨域边界及组织生命周期 | 采用模型草案；运行依赖与延迟较高，CUSTOM 仅含选定部门，超管不自动拥有业务权限 | ADR-0004、I01–I08、S01–S06；各子项需明确接受，不以部分接受覆盖整包 | 待评审 |
| Q05 | R2 / 高 | 数据权限支持边界与接入责任 | 显式映射、受支持 SQL 清单、条件写入、失败拒绝 | ADR-0006、D01–D15 | 待评审 |
| Q06 | R2 / 高 | API 行为、初始凭据交付及版本策略 | 采用草案；初始凭据推荐由超管通过受控渠道一次性交付，禁止默认密码与 GET 回显 | API01–API12；需逐组冻结字段与异常约束 | 待评审 |
| Q07 | R2 / 高 | Java/构建/Web/缓存接入与组件粒度 | Java 21/Maven/MVC，最小能力组件；Java 25 是可选替代 | ADR-0005、技术验证范围 | 待评审 |
| Q08 | R3 / 高 | 首批研发基线、切片顺序与 GitHub/制品前置 | 先兼容验证，再纵向切片；远程名称/套餐/权限需核实 | [研发路线](../roadmap.md)、启动授权 | 待评审 |

没有回复的选项仍是推荐草案；不能因工具预选或经过一段时间而标记接受。事实类未知由后续只读检查或已授权验证处理，不要求用户代查技术资料。
