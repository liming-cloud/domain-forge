# 需求基线与状态

版本：设计草案 v0.1。日期：2026-09-19。来源：本任务会话中的用户选择与已授权设计计划。

## 状态语义

| 状态 | 含义 | 更新条件 |
|---|---|---|
| 已确认需求 | 用户明确选择的目标或约束 | 用户明确修改并记录影响 |
| 待讨论设计 | AI 给出的完整候选，供人工评审 | 用户对具体方案明确接受、修订或否决 |
| 已确认设计 | 人工接受的 ADR 或契约基线 | 记录确认对象、版本/摘要、日期与来源 |
| 待实测 | 文档支持不足以证明运行行为 | 研发获准后执行对应验证，保存证据 |
| 已验证 | 有限定范围的实际验证证据 | 明确环境、版本、方法、结果和适用范围 |

“文档已编写”“自动检查通过”“用户同意开展设计”都不等于“人工接受设计”或“授权编码”。当前没有已确认设计，也没有运行时已验证结论。当前评审状态只在[评审记录](08-review-register.md)维护。

## 已确认需求

| ID | 约束 |
|---|---|
| C01 | 建设长期可复用的 DDD 后端脚手架，技术栈随迭代扩展 |
| C02 | 直接采用微服务架构；首批聚焦技术基础和权限体系，不加入示例业务系统 |
| C03 | 优先最新稳定 Spring Boot / Spring Cloud；先验证与 Nacos 的组合，冲突时人工决定调整，不静默降级 |
| C04 | 使用 Nacos 注册中心和配置中心 |
| C05 | 使用 Sa-Token 实现权限认证集成 |
| C06 | 单租户，覆盖用户、角色、部门、菜单、按钮和数据权限 |
| C07 | 每个用户属于一个部门，可绑定多个角色；部门为树形结构 |
| C08 | 数据范围包含全部、本部门、部门及下级、本人、自定义部门 |
| C09 | 仅合并授予当前操作的角色范围，多角色取并集；无操作权限则拒绝，缺失范围不等于全部 |
| C10 | 超级管理员管理角色赋权、用户角色绑定、部门结构和菜单权限配置；首版不做受限委派授权 |
| C11 | 首版交付后端 API 与接口文档，不交付管理前端 |
| C12 | 使用项目模板加可升级组件复用 |
| C13 | GitHub 私有仓库管理；AI 使用本人账号提交 PR，人工评审并手动合并 |
| C14 | MySQL、MyBatis-Plus、缓存为首批候选能力；ES、S3、Kafka 分阶段补齐 |
| C15 | 当前只交付设计和规划；代码、工程初始化、部署、发布、编码型验证置于设计评审之后 |
| C16 | 采用方向、核心设计、研发准备三轮人工评审；确认设计基线且明确启动后才能研发 |

## 候选而非已确认的内容

Java 版本、构建工具、具体服务拆分、Maven 模块粒度、starter 划分、鉴权调用链、缓存策略、仓库拆分和制品分发方式均需论证。旧计划中的具体建议不自动生效。推荐方案及备选集中在 [ADR](../adr/README.md)。

## 设计证据边界

- 已完成的外部工作为只读官方资料核验；证据与核实日期集中在[兼容矩阵](04-technology-compatibility.md)。
- 类图、时序图、API 示例和测试表均为设计，不是程序运行结果。
- 版本组合最终要在未来技术验证切片中确认。生产规模、可用性/SLO 和部署平台未给定，本阶段不虚构性能承诺。
- 文档产出完成后，仍需用户按三轮评审确认；待讨论项不因等待时间或后续任务开始而自动通过。
