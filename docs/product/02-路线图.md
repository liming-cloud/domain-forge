# 路线图

完整首版承诺见[产品定义](01-产品定义.md)。本页只维护：首版先交付哪些（MVP）、现在做到哪、接下来做什么。

## 首版 MVP 范围

2026-10-23 确认：先让"一个业务服务从模板生成、接入 IAM 权限、整套部署跑起来"形成闭环，其余能力后置。

| 纳入 MVP | 内容 |
|---|---|
| IAM 完整后端 | 初始化管理员、邀请注册、登录及失败防护、退出、改密；账号、角色、组织/部门、成员、操作权限、菜单按钮、数据范围；必要审计。不含管理前端 |
| 业务服务模板 | 在本仓库内生成服务，继承内部 parent，自动执行架构规则；含命令、查询、IAM 接入的示例用例 |
| 基础组件 | web-support（统一响应与错误）、persistence（单库、迁移、本地事务）、cache（缓存、分布式锁、Lua）、access-control（登录态与权限校验） |
| 部署参考 | Docker Compose：IAM、PostgreSQL、Redis、Nacos、Nginx；备份恢复、升级回退的操作说明与验证 |

| 后置到 MVP 之后 | 说明 |
|---|---|
| 多数据源、通用限流、通用幂等 | IAM 登录防护先用自身实现 |
| 文件存储（本地 + S3）、消息与 Outbox、定时任务、短信与验证码 | 首版承诺不变，按真实用例逐项交付 |
| Nacos 配置中心动态配置、API 网关、链路追踪 | MVP 只用 Nacos 服务发现 |
| 性能基线 | 先在 MVP 闭环上确定负载与门槛，再压测 |

## 当前状态

| 能力 | 状态 |
|---|---|
| web-support | 已实现 |
| persistence | 已实现（单库、Flyway、本地事务） |
| cache | 已实现：缓存区域（L2＋可选 L1、回源合并与上限、空值短期缓存、事务后失效）、分布式锁、Lua 脚本 |
| access-control | 已实现（Sa-Token 原生会话与权限） |
| IAM | 完整后端：初始化、邀请注册、登录防护、改密、退出；组织、成员、角色授予、数据范围、权限目录、菜单；系统管理员保全与审计 |
| 业务服务模板 | 生成到 `platform/services/<name>` 并加入聚合；含 IAM 接入（Feign＋数据范围），可选便笺示例覆盖命令、纯查询与编排查询；同时生成部署覆盖文件（专用数据库账号与 schema）与入口路由；CI 在干净副本中生成并验证，`scripts/verify_closure.sh` 验证生成服务与真实 IAM 一起部署后的授权、范围、撤权、数据库隔离与备份恢复闭环 |
| 部署 | Compose 单机基线：IAM、PostgreSQL、Redis、Nacos（服务注册与发现，开启鉴权）、Nginx 唯一入口；PostgreSQL 在线备份与恢复（Redis 会话清空、Nacos 账号按环境文件重建）；升级脚本（先备份）与应用回退、数据回退的条件；`scripts/verify_deploy.sh` 在 CI 中验证首次部署、重启、删卷后恢复、升级、应用回退、迁移失败与数据回退，见[部署参考](../../deploy/README.md)。HTTPS 覆盖文件未交付 |
| 质量门禁 | `mvn verify` 统一执行架构规则、格式、Checkstyle、依赖声明、单元与集成测试 |

## 已知风险

- 依赖漏洞：Tomcat 11.0.24 有 11 项告警未处置，生产可利用性未评估。Dependabot 会持续提示。
- 会话安全：原生会话迟到写入由 SQL 许可兜底（许可缺失或凭据版本不符即拒绝）。许可提交失败、改密／禁用与登录竞争由 `IdentityPersistenceIT` 在真实 PostgreSQL／Redis 上验证。
- 数据库基线：P2 重写了 IAM 的 `V1__iam.sql`（主键改为 bigint、删除回执与补录表），P2 之前创建的本地库需重建。

P1 之前的逐层确认记录、验收依据和控制面实现保存在 git tag `governance-v1-archive`。
