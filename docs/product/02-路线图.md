# 路线图

完整首版承诺见[产品定义](01-产品定义.md)。本页只维护：首版先交付哪些（MVP）、现在做到哪、接下来做什么。

## 首版 MVP 范围

2026-10-23 确认：先让"一个业务服务从模板生成、接入 IAM 权限、整套部署跑起来"形成闭环，其余能力后置。

| 纳入 MVP | 内容 |
|---|---|
| IAM 完整后端 | 初始化管理员、邀请注册、登录及失败防护、退出、改密；账号、角色、组织/部门、成员、操作权限、菜单按钮、数据范围；必要审计。不含管理前端 |
| 业务服务模板 | 在本仓库内生成服务，继承内部 parent，自动执行架构规则；含命令、查询、IAM 接入的示例用例 |
| 基础组件 | web-support（统一响应与错误）、persistence（单库、迁移、本地事务）、cache（缓存、分布式锁、Lua）、access-control（登录态与权限校验） |
| 部署参考 | Docker Compose：IAM、PostgreSQL、Redis、Nacos、Nginx；备份恢复、升级回退的操作说明与验证 |

| 后置到 MVP 之后 | 说明 |
|---|---|
| 多数据源、通用限流、通用幂等 | IAM 登录防护先用自身实现 |
| 文件存储（本地 + S3）、消息与 Outbox、定时任务、短信与验证码 | 首版承诺不变，按真实用例逐项交付 |
| Nacos 配置中心动态配置、API 网关、链路追踪 | MVP 只用 Nacos 服务发现 |
| 性能基线 | 先在 MVP 闭环上确定负载与门槛，再压测 |

## P6 实施计划

2026-10-27 确认的选型与顺序。每项一个 PR，交付标准同前：真实依赖上的场景验证进入 CI，接口、配置与设计变化同步文档。顺序依据：网关的路由与限流需要动态配置，跨服务调用要沿用网关定下的身份传递合同，消息消费方又会用到跨服务调用。

| 项 | 内容 | 已定 | 待设计时明确 | 验收 |
|---|---|---|---|---|
| P6-1 账号并发 | 账号修改（登录登记许可、改密、启停、角色、成员）去掉行锁，统一用 `version` 条件更新（CAS），版本不符返回 409 | 采用 CAS；"至少一名系统管理员"等跨行规则仍由管理守卫与组织／菜单／目录协调锁保证（单行 CAS 防不住写偏斜），不改用 Redis 锁 | 无 | 真实 PostgreSQL 并发：同账号并发修改仅一个成功；登录与改密／禁用竞争后旧凭据不能使用；最后一名系统管理员仍受保护 |
| P6-2 Nacos 配置中心 | 平台组件接入 Nacos 配置；部署参考初始化配置与访问账号。设计见[配置中心](../architecture/05-配置中心.md) | 凭据与密钥只来自环境变量，不进 Nacos；Nacos 发布内容是权威（[O-09](../standards/08-配置与运行.md#o-09-nacos-发布内容是权威)） | 已确定（2026-10-27）：首批动态项为 IAM 登录防护阈值与日志级别；启动时不可达则启动失败；无法应用的发布值保持当前值并告警；仓库种子仅在 dataId 不存在时发布；服务账号配置只读 | 启动读取、变更后应用侧真实生效（不以收到通知为准）、运行中连接中断、应用执行更新失败 |
| P6-3 API 网关 | 新服务 gateway：Nginx（边缘）→ 网关 → 各服务；路由经 Nacos `lb://`。设计与实现见[API 网关](../architecture/06-API网关.md) | Spring Cloud Gateway（WebFlux）＋ `sa-token-reactor-spring-boot4-starter` 登录校验；Redis 令牌桶限流；请求标识贯穿日志；后端仍各自授权 | 已确定（2026-10-27）：原样转发令牌，不签发内部凭据；Same-Token＋网络隔离防直连；路由集中在网关的 Nacos 配置，模板追加种子；Nginx 只做边缘，删除按服务的路由文件 | 正常转发、未登录拒绝、限流 429、请求标识关联、下游故障 503；后端直连被拒 |
| P6-4 跨服务调用 | 组件封装 OpenFeign：统一超时、默认不重试、错误翻译、用户身份与服务身份传递；模板示例增加一个服务调用另一服务；IAM 接入改用该组件 | Feign 为主；Dubbo 不进入本轮，出现真实高频内部调用时再作为可选组件评估 | 已确定（2026-10-28）：用户令牌自动转发给所有调用；Same-Token 按 Sa-Token 官方用法作为服务身份；无用户上下文的调用只能访问 `/internal/**` 上 `@SaIgnore` 声明的服务专用接口；规范条目见 [A-14](../standards/07-安全与访问控制.md#a-14-服务间调用的身份)、[H-09](../standards/06-接口与错误.md#h-09-服务间调用经跨服务调用组件)。设计与实现见[跨服务调用](../architecture/07-跨服务调用.md) | 两个生成服务之间的真实调用：成功、401／403 语义保持、超时与下游不可用、身份传递 |
| P6-5 消息与 Outbox | 部署参考加入 RocketMQ 5；组件提供同事务 Outbox、中继发送、消费者去重；模板示例发布并消费一个集成事件 | RocketMQ 5；可靠发送用同事务 Outbox＋中继，不依赖中间件的事务消息 | 已确定（2026-10-28）：官方 gRPC 客户端 5.2.2；轮询＋事务提交后唤醒、`SKIP LOCKED` 抢占、指数退避不丢弃；至少一次＋消费去重；顺序由业务按事件选择（普通主题或带顺序键的 FIFO 主题）；有限重试后进死信并告警，不提供重放工具；消息存储不进备份。设计与实现见[消息与 Outbox](../architecture/08-消息与Outbox.md) | 业务数据提交后、消息发出前中断应用，恢复后消息继续发送；重复投递时消费结果不重复 |
| HTTPS 覆盖文件 | Nginx 证书挂载、HTTP 跳转 | 放在 P6 最后 | 已确定（2026-10-28）：证书由运维提供（任何 CA），平台提供检查后平滑重载的脚本；只接受 TLS 1.2+；HSTS 可选、默认关闭。用法见[部署参考](../../deploy/README.md#https) | 真实证书下的 HTTPS 与跳转 |

链路追踪、通用限流与幂等组件、定时任务、文件存储、短信与验证码仍按真实用例逐项交付，不在 P6 预建。

## 已知风险

- 消息鉴权：RocketMQ 未开启鉴权，只在内部网络可达，网段内的容器可以发布或消费任意主题；是否开启 ACL 需要人工决定。
- 定时任务服务端：PowerJob 官方镜像的运行时为 Java 8（1.8.0_292），控制台账号体系与 IAM 分离；控制台只在主机回环地址经覆盖文件发布。
- 依赖漏洞：Tomcat 11.0.24 有 11 项告警未处置，生产可利用性未评估。Dependabot 会持续提示。
- 会话安全：原生会话迟到写入由 SQL 许可兜底（许可缺失或凭据版本不符即拒绝）。许可提交失败、改密／禁用与登录竞争由 `IdentityPersistenceIT` 在真实 PostgreSQL／Redis 上验证。
- 数据库基线：P2 重写了 IAM 的 `V1__iam.sql`（主键改为 bigint、删除回执与补录表），P2 之前创建的本地库需重建。

P1 之前的逐层确认记录、验收依据和控制面实现保存在 git tag `governance-v1-archive`。
