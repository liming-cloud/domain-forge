# 源码质量规范

适用于平台、模板和业务服务的 Java 源码。职责划分见[系统设计](02-系统设计.md)，自动检查的配置见[工程与构建](../reference/工程与构建.md#质量门禁)。

## 职责位置

### C-01 按真实职责放代码，不建空目录

**规则**：业务服务按五个职责包组织（见 [S-01](02-系统设计.md#s-01-五个职责各管各的事)），每个职责内按真实业务适度分组。没有对应职责就不创建源码或目录：不要求空领域层、成对的接口与实现、只转发的层。通用技术组件（如 web-support、cache）按自身职责组织，不套用业务分层。

**反例**：为"目录齐全"创建只有一个空接口的 `domain/service`；每个类单独一个子包。

**检查**：自动[职责归属]；评审：是否过度拆分。

## 格式

### C-03 统一代码格式

**规则**：Java 生产和测试源码的格式以 Spotless 的输出为准（Eclipse 格式化器，配置为 `domain-forge-build-rules/src/main/resources/format/eclipse-formatter.xml`，2026-11-04 决定，见 [#88](https://github.com/liming-cloud/domain-forge/issues/88)）：

| 项 | 约定 |
|---|---|
| 缩进／续行 | 4 空格／8 空格；不用 Tab |
| 行宽 | 120；`package`、`import` 行除外 |
| 导入 | 分组为“其他包 / `javax`、`java` / 静态导入”，组间空一行；不留未使用的导入 |
| 其他 | UTF-8、LF、文件末尾换行、行尾无空白 |

整理格式执行 `spotless:apply`，结果是确定的，可以对整个模块或仓库执行，不会产生无关改动。使用 IntelliJ 时安装 Adapter for Eclipse Code Formatter 插件并加载上述配置，或在提交前执行 `spotless:apply`；IntelliJ 自带的 Reformat Code 与 Spotless 的换行位置不完全一致，不能代替。模板生成的服务由生成器在生成后自动整理。会改变行为的重构不能混在格式化提交里。Markdown 不按行宽折行。

**检查**：自动[spotless:check]：verify 阶段逐字比对格式化器的输出；自动[Checkstyle format.xml]：格式化器保证不了的行宽与多余导入。

## 表达与状态

### C-04 命名表达业务含义

**规则**：类型、方法、字段按所属上下文的业务语言命名，缩写和常量要有可理解的依据。不靠统一后缀、类型数量或模式名称表达职责。

**检查**：评审。

### C-05 保护领域状态

**规则**：领域对象的状态只能通过表达业务行为的方法改变，核对构造、属性写入、集合返回和重建等所有入口。不用通用 setter、可变引用或生成方法绕过规则。实体不使用 Lombok `@Data`；生成的 `equals`、访问器、`toString` 要逐项符合身份、状态保护和不泄露秘密的要求。对象分离见 [S-13](02-系统设计.md#s-13-领域持久化接口和事件对象各司其职)。

**反例**：`account.getRoleIds().add(SYSTEM_ADMIN_ID)` 绕过授权规则直接修改返回的集合。

**检查**：评审；测试：覆盖非法状态转换。

### C-06 合理使用 Java 25 特性

**规则**：

| 特性 | 用法 |
|---|---|
| record | 透明数据载体；可变成员要防御性复制，不能假定深不可变 |
| `Optional` | 主要用于返回值缺失，不用于参数，不代替校验或故障结果 |
| switch 模式匹配、sealed | 用于简化真实的类型分支 |
| Stream | 用于清楚的转换；复杂副作用、事务、错误处理用普通控制流 |
| 未命名变量与模式 `_` | 用于确实不用的 catch 参数、lambda 参数、循环变量和记录模式分量；用到的值要起名 |
| 灵活构造器体 | 在 `this(...)`、`super(...)` 之前校验或换算参数，代替为此而写的静态辅助方法 |
| Stream Gatherers | 只在标准收集器写不清的有状态转换（滑动窗口、按条件截断）中使用 |
| 模块导入 `import module`、Markdown 文档注释 `///`、精简源文件 | 不用：导入逐个写明；类型说明写成 `/** */`（[C-09](#c-09-每个生产类型都有中文说明) 的检查只识别它） |
| 预览特性 | 不用：构建不开 `--enable-preview` |

**检查**：评审。

### C-07 时间、金额、资源、异常

**规则**：

- 时间来源通过注入或最小接口取得；区分墙上时间、经过时长、数据库权威时间，不混用时区。
- 金额和比例使用明确单位、舍入规则和 `BigDecimal`（或带单位的整数），不用浮点。
- 资源由创建方关闭，优先 try-with-resources。
- 异常保留原因；捕获 `InterruptedException` 时恢复中断标志或继续传播，不吞掉取消。

**检查**：评审。

### C-08 并发要有协议

**规则**：无状态 Spring 单例不保存请求状态。共享可变状态要写明并发协议：`volatile` 只保证可见性，不保证复合操作原子；进程内锁不能作为跨实例保证。线程池、队列、连接、重试都必须有界。

**检查**：评审；测试：有并发约束的代码要有并发测试。

## 注释

### C-09 每个生产类型都有中文说明

**规则**：生产代码中的每个命名类型（类、接口、枚举、record、注解、嵌套与局部命名类型），不论可见性，都有自己的简体中文 Javadoc。首句说明这个类型承担什么职责；有使用前提、数据含义、生命周期、线程安全等容易误用的约束时补充说明。Javadoc 放在所有注解之前。

**正例**：

```java
/** 装配当前模块的关系持久化组件。 */
@Configuration
class PersistenceConfiguration {}
```

**反例**：

```java
@Configuration
/** 装配当前模块的关系持久化组件。 */   // 位置错误：在注解之后
class PersistenceConfiguration {}
```

**检查**：自动[Checkstyle MissingJavadocType]、自动[Checkstyle InvalidJavadocPosition]、自动[Checkstyle SummaryJavadoc]；评审：说明是否准确。

### C-10 合同方法和关键行为要有说明

**规则**：以下方法要有中文 Javadoc：公开合同（用例、出口接口、组件 API）的方法与构造器；包含业务规则、副作用、失败处理或其他容易误用语义的内部方法，即使是 private。说明完成什么操作，以及调用方需要知道的参数含义、结果与空值、副作用、失败行为，适用时再说明权限、事务、并发、资源责任。没有额外语义的简单访问器和纯委托可以省略。

**反例**：名为 `getPermissions()` 的方法实际做了权限过滤却没有说明；用 `@Override` 默认继承说明，但实现新增了校验。

**检查**：评审：自动检查只覆盖类型说明。

### C-11 匿名类和 lambda

**规则**：简单的局部回调可以用匿名类或 lambda，不要求单独的类型说明；有独立职责时提取为命名类型并按 C-09 说明。不能把独立职责藏进匿名体来规避说明和检查。

**检查**：评审：匿名体和 lambda 同样计入复杂度、依赖和行为检查。

### C-12 测试用清晰的名称代替冗余注释

**规则**：测试不强制 Javadoc，用清晰的测试名和必要说明表达条件与预期。复杂夹具、时间与并发控制、故障注入、特殊断言依据要说明。测试改变时同步更新说明。生产用途的代码放到测试目录也仍按生产规则处理。

**检查**：评审；自动[Checkstyle InvalidJavadocPosition]：测试中如果写了 Javadoc，位置同样受检查。

## 耦合

### C-16 跨模块只用弱耦合

**规则**：用 Connascence（共生性）作为评审耦合的共同词汇：它从强度、局部性、程度三个维度衡量耦合，强耦合只能出现在局部（同一个类或方法内）。跨模块、跨组件只允许名字、类型这类弱耦合，不用异常类型、魔法字符串或布尔参数约定语义（[ADR-0005](../decisions/0005-共生性作为耦合评审词汇.md)）。

**反例**：调用方按异常类名或消息文本判断业务结果；用 `process(order, true, "FAST")` 中的布尔值和字符串约定行为。

**检查**：评审。

## 复杂度

### C-13 方法复杂度上限

**规则**：生产和测试代码的每个方法、构造器、初始化块：圈复杂度不超过 10，可执行语句不超过 30。lambda 的分支计入所在方法。超限时消除混杂的职责和重复分支，提取的方法要有真实职责；不为凑数字制造只转发的方法，也不把逻辑挪到检查不到的地方。确需例外的处理见 [W-11](../workflow/01-开发流程.md#w-11-发现问题时修正对象不放宽检查)。

**正例**：`RedisLoginProtection.reserve` 超限后，把事务内锁定与代际核对提取为 `policyAllows(generation)`，行为不变。

**检查**：自动[Checkstyle CyclomaticComplexity]、自动[Checkstyle ExecutableStatementCount]。

## 生成代码

### C-15 生成代码的豁免

**规则**：只有外部工具重复生成、不手工维护的输出，才能在人工批准后豁免注释、格式或复杂度检查，豁免不包括编译、架构、安全和行为验证。登记生成器版本、输入、输出范围和豁免的规则；输出必须能从输入重新生成。AI 生成后由项目维护的代码不属于生成代码；只加 `@Generated` 或放进生成目录不能获得豁免。

**检查**：评审：目前没有生成代码。
